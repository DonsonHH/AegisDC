## 1 规则到底控制什么

每名空闲巡检员先固定一个例行头`head`，再考虑自己负责的未结事件。候选要通过专业资格／归属、预约冲突、1800秒任务边界和返回巡回重访检查；非头访问还要有剩余额外访问预算。被冻结的设置为FIFO事件次序、事件TTL 120秒、全队额外事件派单预算12次。该预算按非头派单扣除，不是给每个事件12次，也不是允许规则自己增加人员。[risk_response.py](../../src/patrol_rsi/risk_response.py) L57–64、L107–130、L172–178；[冻结配置](../../configs/response-defer-study.json) `execution`。

**先固定事件，再用规则决定响应还是暂缓：**

1. 先过滤不合法或预算不允许的候选。
2. 在合法事件中按`(visible_s, -当前public_risk, task编号)`取最小值：可见时间更早优先，同龄时当前公开风险较高优先，再按任务编号打破平局。
3. 取合法例行头。只有固定事件与例行头都合法且任务不同，才计算下述线性分数。
4. 分数非负执行这个固定FIFO事件；分数为负直接执行这个例行头。负分不导致空等，也不会换成另一个较新的事件。
5. 若没有事件，则执行合法例行头；若只有事件合法，则执行事件；若事件正好就是例行头，直接执行该任务；两者均无合法动作才无动作。规则不控制这些单边或相同任务状态。

来源：[risk_response.py](../../src/patrol_rsi/risk_response.py) L116–169；[response_rule.py](../../src/patrol_rsi/response_rule.py) L55–83。不能把这里画成“对所有候选打分后选最高分”：本规则只改变已经确定的两个动作之间的门控。

**暂缓之后仍保留事件。** 完成例行头才推进巡回游标；访问非头事件不推进这个游标。任何完成于事件可见之后的该任务测量，都可以把待处理事件标为`measured`，测量正常也会关闭事件。TTL过期时才移出待处理表；已过期响应的后续完成另标`measured_late`。因此“事件已处理”“测量异常”“评价器确认一个异常段”是三件事。[risk_response.py](../../src/patrol_rsi/risk_response.py) L14–43、L179–195；[inspection_metrics.py](../../src/patrol_rsi/inspection_metrics.py) L54–79。

## 2 四个输入、分数方向和归一化

记当前原始公开风险为`R`，当前时刻为`t`，事件首次可见时刻为`t_visible`；`F_event/F_head`为各自证书上的候选完成时刻，`S_event/S_head`为各自返回证书的最小预计重访余量。定义：

|输入|实际计算|契约范围|容易混淆之处|
|---|---|---|---|
|`r = risk`|`R / 4`|0至1|当前公开风险，不是初始风险，也不是已标定故障概率|
|`a = age`|`(t - t_visible) / 120`|0至1|事件已可见多久；不是距离上次专业测量多久|
|`d = extra_time`|`(F_event - F_head) / 300`|-6至6|两个当前候选完成时刻的差；不是额外走了多少米，也不是完整未来调度的总时间差|
|`q = slack_difference`|`(S_event - S_head) / 600`|-1至1|两条返回证书的最小重访余量之差；不是异常还会持续多久|

`score = bias + w_r*r + w_a*a + w_d*d + w_q*q`。

`score >= 0`响应事件，`score < 0`执行例行头。零偏置、零权重给出0分，故在二选一状态响应事件，复现FIFO门控方向。偏置限制[-2,2]，四个权重各限制[-4,4]；接口检查有限数值与范围，不对越界特征静默截断，不使用sigmoid，也不把分数解释为概率。[response_rule.py](../../src/patrol_rsi/response_rule.py) L7–52、L70–80。

公开风险由名义温度、上次接触温度／流量、公开IT供需等构成并封顶4；热专业风险含`max(预测温度-65,0)/20 + 0.25*供需缺口`。这给出了公开信号的来源，不能据此把0.01解释为“1%故障概率”。返回余量则来自整个受保护后备巡回的期限检查。[active_inspection.py](../../src/patrol_rsi/active_inspection.py) L93–116；[coverage_plan.py](../../src/patrol_rsi/coverage_plan.py) L32–73。

## 4 为什么低至28、最高也只有60：已能直接观察到什么

### 4.1 最低28有完整的实现解释

S0-risk的分数恰好为`R - 1`。其实际保存的全部229个二选一状态中，`R`范围是0至0.7604212881，全部得负分，全部执行例行头；12个过程合计额外事件访问0。再将这些S0-risk记录与对应历史Tour逐项比较，12个过程的`process_sha256`、完整`action_log`、测量的`(time_s, agent, task, alarm)`投影都一致。因此，在这批过程里，它确实退化为Tour，确认量同为28，不只是两个总数偶然相同。来源：[S0-risk原轨迹](../../runs/response-defer-search-20261102/)、[历史Tour原轨迹](../../runs/event-validation-amended-20261102/)；[诊断数据](../source-data/report-rule-diagnosis.json) `s0_risk_matches_existing_tour`。

阈值降至0.75的S1-risk只作出4次二选一响应，确认30段；降至0.1的S2-risk作出44次响应，确认47段。这里能说“这些阈值排除了大量低幅公开信号下的事件插入”，不能据此断言所有低幅信号均真实、或更低阈值必然更好。[同上诊断数据](../source-data/report-rule-diagnosis.json) `unique_rules`；[结果CSV](../../evidence/response-defer/results.csv)。

### 4.2 最高60中的15秒规则：一次首次分歧和一段丢失

取**同一p00-coupled过程、同一agent 0、同一260秒决策**，比较FIFO与S1-age。两份记录的过程SHA均为`b261bdf3514a99289a4664c7724234845b585e02bf7c888f439c06fefd63bb3b`；260秒以前全部动作行相同，260秒候选及其证书逐项相同。此刻例行头是4，FIFO事件是6，两者都合法且预计280秒完成；事件6首次可见255秒，年龄5秒。

`score = -0.125 + 5/120 = -0.0833333333 < 0`。

### 4.4 解释边界

**已观察事实：** 规则确实改变动作；S2-risk_time在11个过程改变完整动作日志，其他8种规则在12个过程改变。9种规则全部安全违规零，全部未满足正净增条件。减少几次移动或增加完成次数，没有挽回协议优先要求的确认损失。所有实际二选一状态中，事件证书的最小余量都比例行头更低；因此这些规则中正的余量差权重实际形成一个负项。余量保持合法与能否确认短异常，是不同问题。[诊断数据](../source-data/report-rule-diagnosis.json) `unique_rules`；[源码返回检查](../../src/patrol_rsi/coverage_plan.py) L32–73。

**可检验解释：** 风险阈值可能过度筛掉低幅但有用的早期提示；正的年龄项会把年轻事件当成“尚不响应”的理由；当前四个线性输入没有直接表达“先做例行头会把此事件的下一次完成推迟多少”。p00支持这些设计与错窗同时出现，p08则说明推进例行头也可能增加别处确认。还不能把所有12段丢失都归因于同一个机制，也不能写“规则导致反复折返跑”或“模型发现迟发规律”：这里没有逐段归因的全量证据，也根本没有研究模型提案。
