# 基线保留适配器与复现

本轮执行基准是规划提交`dd6803e1`，研究基准`db2f9c7c`。执行核SHA为`9dcb188b157816fb4efed7fde77367f7adbd760a7c09558a80da8ed9752fe6cc`。原物理、观测、冻结估计、重排执行、任务账本、安全核和评价器保持原文件；protocol.json列出其SHA。本轮只有原六开发条件，未使用43000/43001逐行确认数据，没有新确认和训练。

## 适配器

`src/patrol_rsi/baseline_correction.py`固定非负成本、正公开风险改善依据和Tour默认语义。`correction_execution.py`复用原`ReorderTask`与步进，只替换选择函数；`correction_selection.py`使用预定Pareto规则区分探索父版本与正式采用。

rho为原有已知风险分项按direct/model/power/cross来源非负重加权、按公开来源年龄选择flat或linear300，最后截到4。缺失分项为null/unknown，不赋予正常含义；模型有有效输出时可作为model来源，不要求先有专业阳性确认。分项时间使用真实贡献来源时刻；组合跨支路项用最旧最大项贡献时刻，明确记录并列贡献者。风险是代理，非校准概率。

对全部所属任务的首次后续完成F计算：G_plus为风险加权提前，G_minus为风险加权延后，均以期限归一化再取任务均值。A=G_plus−G_minus−λ_move×max(Δ段及恢复连接移动秒/300,0)−λ_due×max(Δ平均平方期限压力,0)。原序A=0；只有G_plus−G_minus>1e-9且A>margin+1e-9才改序，取最大A，平分按原序/任务ID。成本系数非负由契约保证；这不保证真实任务收益。

H：四来源权重均1、flat、移动0.05、期限0.2、margin0。S1只把cross改0.5，S2把其保留父式的移动惩罚改0.2。Q使用同一完整参数对象；权重{0,0.5,1,2}，非全零，两个惩罚{0,0.05,0.2,1}，margin{0,0.001,0.01}。拒绝额外字段、负惩罚、NaN、未知值和重复；不执行任意Python。

模型入口`parse_model_response`仅规范数字表示，包括1/1.0和-0/+0，数值不变；原始回复完整保留。重复身份忽略mechanism。不是补缺失值、改系数或从解释文字组装参数；负系数仍直接拒绝。

## 同状态干预与执行身份

T/R都在新核真实执行六条件，与封存的旧开发动作和测量回归。Tour根按(time,agent)首个存在合法非原且该人所属原公开risk>0选取；全程无正风险则取首个零风险替代。原R建议原序时只在非原池按原R选唯一最佳。先冻结根和候选，再跑A/B。

A/B从初态真实重放到根，根时只改变一人的一次承诺段，随后按各自正确remaining恢复Tour；不继续按H/R重排。前缀动作及数值状态SHA相等；快照含在途/工时/预约/全账本/观察器/估计历史/刷新/辅助证据，-inf等合法哨兵用显式类型编码保留。旧几何、权重与物理指纹单独绑定；墙钟推理计时及纯审计日志排除项在原件中明示。不是部分快照恢复。

同过程/任务/时刻噪声使用旧接口；同tick同测量核对一致，改变路线后的后续测量与估计真实重新生成。A实际逐动作/测量回归T。记录全回合漏检、删失等待、移动、服务、完成与末尾义务差异，不只看被提前目标。

`guard_baseline_correction.py`是正式阶段入口，核验当前T/R/H/S/Q收据、完整六条件、根从当前T重构及原件SHA；不更改数值执行核。派生`pair-classification.json`绑定未改A/B原件，对容差内等价分类作明确处理，不回填旧原件。入口护栏和离线提示更改单独留源包，不能声称v1已含后续护栏。

## 模型实际收到的经验

固定Qwen3-8B、CPU float32/greedy、无训练，最大输入4096、输出256token、单次240秒、全局最多4真实生成。每次生成前计数，重复/失败/超时均收费；tokenizer预检不加载8B也不生成，作业资源另列。

完整结构化源卡与匿名映射留在原件。**模型实际输入以call目录的rendered_prompt为准，start.json的prompt是结构化组织源，不表示其每个字段都原样输入。** 实际列式文本保留六条件、A/B完整回合差值、所有非零提前/延后任务的风险分项/来源/时刻、新鲜度与同pod关系。ΔF严格0的任务风险行省略但任务/shift仍列出，其G贡献对任意来源权重都为0，省略不表示正常。逐机柜贡献者清单在原件；实际提示使用同pod关联与保守组件时间，并没有向模型提供所有叶节点清单。数值5有效位展示，分支差值先用原始精度相减再格式化；选择用完整精度。

任务/人员/pod匿名化保留专业关系。图任务按专业排序，非热pod取electrical128/cooling144/control160偏移；不能误用按pod交错索引。Q1行为卡使用独立q1_命名空间，不与配对卡t/u标签混同。输入不含seed、scenario、故障时间表、隐藏异常窗口、Oracle动作或确认逐行结果。

Q1收到H与实际配对反馈后生成并六条件执行，Q2读取Q1完成收据SHA后才生成。Q2看Q1的实际动作变化/分条件结果与保留原因。两次提案不等于经验因果增益；没有无反馈消融，没有改进器自身更新，递归增量未测。

## Pareto选择

三目标分别为六条件平均漏检、有异常条件平均删失等待、平均移动，容差1e-9。探索均从H开始，子式须支配父式且未被T/R支配才换父；取舍候选留档。H即使弱于T也只是探索起点，H正收益不是调用门槛。

正式默认T；仅支配T、未被其他已评合法参照支配、完成数不低于T的H/S/Q才有采用资格。多候选按事先固定H,S1,S2,Q1,Q2顺序，不以任意小等待压成本。R只作参照，不能入选。健康干预移动减少但少做1项不能当效率提升。

经use-renly-slurm核对账号、拓扑和队列，按source/receipt-*.json验证源包后解压。新run目录建jobs。每一步等待sacct终态、日志和完成收据后再继续，一次只运行一个分配：

```bash
task_source=/share/home/renly/renly-patrol-rsi/runs/20261101-baseline-correction/code-v2
task_run=/share/home/renly/renly-patrol-rsi/runs/reproduce-baseline-correction

# 分别执行pilot、baselines、pairs、human、simple；不能并行这五个模式。
sbatch --output="$task_run/jobs/pilot-%j.out" --error="$task_run/jobs/pilot-%j.err" \
  "$task_source/cluster/baseline_correction_cpu.sbatch" "$task_source" "$task_run" pilot
# 完成后把上面的最后参数逐次换为baselines、pairs、human、simple。
```

本次数值pilot/T/R使用v1；配对/H/S使用v2，同一数值核。实际模型的源版本见model-round-N/startup.json与源码包SHA。离线提示修正不改变已跑数值核。使用相应提案源包的propose.sbatch依次运行round1生成→cpu.sbatch q1实评→round2生成→q2实评→cpu.sbatch finish。可以先加第四参数prepare作零生成分词检查，预检收据每次独立命名。

原始Qwen输出不会因重跑保证相同；完整原始输入、输出和源包已封存。本轮预算60/4/0不用于追加复现实验，新复现应独立计费。
