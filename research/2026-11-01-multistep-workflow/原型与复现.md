# 最小多步巡检原型

运行入口为 `scripts/run_multistep.py`；执行器、白名单工作流和派单安全接口分别在 `src/patrol_rsi/multistep_execution.py`、`multistep_workflow.py`、`multistep_safety.py`。旧平台文件均未改写。

```text
已有公开线索 → 选择安全专业检查 → 等待真实完成
→ 实际测量及时间写入共享状态 → 更新任务顺序或返回Tour
→ 整回合评价 → Qwen离线提出一个受限子工作流 → 同条件执行
```

在线每5秒运行受限控制逻辑；语言模型仅在回合完成后调用。固定CVAE按原30秒时钟产生估计，真实测量由原专业检查接口完成。CVAE值是估计，不是实测温度或故障概率。本轮没有训练模型，没有调用PPO排序；18名执行者保留原专业与任务所属，由共同调度器共享测量、排除冲突。

每次实际派单重新检查资格、访问、所属、预约、路径、服务、剩余额度与完整返回计划，使用已经累积顺延后的实际检查时间。未完成的额外检查会阻止另一项额外派单。K仅支持1和2；两次额度不代表现场许可。

C与D使用相同首次逻辑及同一后续排序工具。C在第一次派单时，依据已有阳性公开线索预先冻结后续偏好（阳性是假设，不是测量）；D等待真实测量，然后选择正常或阳性分支，并读取当时的公开状态。C也在第二次实际派单时重新核验安全。D−C包含遥测、状态估计及几何状态随时间更新的作用，不能单独归因于第一条专业测量。

正式运行源为不可变 `source/code-v3.tar.gz`，SHA256为 `a346cbabdf161b1cf8c2b9e62766832f47e079cf27aab7d56bbff09e79f0f7e0`。其快照清单SHA为 `32a11decd9f1a6da94ca63cbc7c6f25a3341f357ef2cce43a52f4775b3be79d0`。v1仅成本试运行；v2未部署；两者均不混入v3正式比较。

## 复现命令

在已经核验的mu01环境准备源目录；所有计算经Slurm。`SRC`指解压后的v3快照；`RUN`必须是新的独立输出目录，不能写入旧M12阶段。先复现已冻结的五组巡检结果：30个开发回合、0次语言模型调用。本轮已有结果可直接读取，不重复执行。

```bash
SRC=/share/home/renly/renly-patrol-rsi/runs/20261101-multistep/code-v3
RUN=/share/home/renly/renly-patrol-rsi/runs/REPRODUCE-multistep
mkdir -p "$RUN/jobs"
pilot=$(sbatch --parsable --time=00:05:00 --output="$RUN/jobs/pilot-%j.out" --error="$RUN/jobs/pilot-%j.err" "$SRC/cluster/multistep_cpu.sbatch" "$SRC" "$RUN" pilot)
base=$(sbatch --parsable --dependency=afterok:$pilot --time=00:10:00 --output="$RUN/jobs/base-%j.out" --error="$RUN/jobs/base-%j.err" "$SRC/cluster/multistep_cpu.sbatch" "$SRC" "$RUN" baselines)
# 使用本轮真实Qwen生成并冻结的子工作流；仅重放，不再次生成模型提案。
cp /share/home/renly/renly-patrol-rsi/runs/20261101-multistep/child-workflow.json "$RUN/child-workflow.json"
sbatch --dependency=afterok:$base --time=00:03:00 --output="$RUN/jobs/child-%j.out" --error="$RUN/jobs/child-%j.err" "$SRC/cluster/multistep_cpu.sbatch" "$SRC" "$RUN" child
```

冻结子工作流也包含于 `evidence/child-workflow.json` 和结果原件包，离开原运行目录时可从该文件复制。实际31次评价包含1条旧源成本试运行，该条不属于五组主比较。

本轮真实模型生成使用Slurm CPU：所有16张GPU被占用，未启动的GPU作业131046取消。第一次CPU作业131047采用同一Qwen3-8B、float32/greedy，第一调用原始完整封装缺字段、第二调用超时，均计费；第二CPU作业131048使用明确声明的紧凑输出，第三调用生成合法修改。模型只生成changes和mechanism，接口显式加固定协议与父版本SHA，不修复模型字段。子流程随后在v3执行器运行6回合，行为与父流程相同。

若需重新运行模型提案，保留同一4次共享调用账本，按以下已实际使用的命令执行；这是新的研究运行，模型输出不保证逐字相同。`SIDE`须包含source目录中封存的同名侧车与解析器。

```bash

# 基线已完成后，最多10分钟、8CPU。首次合法子流程即停止。
```

实际提案源与解析器已封存在source目录，并在原件包的sidecars中保留部署字节及SHA。紧凑接口不能把前两次失败变成合法调用。重做模型提案时不要先复制冻结child文件；已有该文件会阻止重复提案。

依赖现有 `python/3.11-pytorch2.6-cu124` 模块及 `runs/20261026-m1/model-env/bin/python`；固定CVAE在 `runs/20261028-m111/frozen-estimator.pt`，Qwen3-8B在 `models/Qwen3-8B-b968826d`。权重未随本次包复制，需要同一清单的文件。CPU/GPU资源须在复现前重新查询。作业离线运行，不调用云API。

程序在实际开始前预留预算，失败也计入60次环境/4次模型上限；精确快照匹配的完成回合才可复用。合成测试不会生成真实物理过程，正式每回合执行独立资格、路线、测量、返回计划和整段评分核对。所有结论限于六个开发条件。
