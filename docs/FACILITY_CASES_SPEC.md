# 三设施案例包交付要求

基点：`c85ef5363a9cdc57a3ad889133c23f3621106c13`。用户要求分别整理Frontier、El Capitan和郑州曙光8000的设施拓扑、状态方程、参数表，区分真实资料与假设、明确缺值，并多配架构图帮助阅读；智能体和RSI暂不推进。

1. 三案例独立登记来源、节点、关系和参数，不把综合模板当真实现场。El Capitan地点为LLNL；郑州核心节点与曙光8000作为同一工程。
2. 每个事实或参数有来源、章节/页/段落、年代、单位及使用边界；区分公开站点陈述、设计资料、发表模型、厂家能力和本研究假设。冲突口径并列，缺值保留null并说明影响和所需资料。
3. 每站至少两幅原创可编辑SVG架构图，另配共同的状态耦合与证据边界图，总计至少8幅。图内有方向、介质/关系语义和证据图例；图与表引用同一台账，排热关系、供电关系、控制/观测关系分别说明。通行图无现场资料时明确缺失。
4. 提出各站对应的集中参数状态/代数方程，列出状态、代数量、输入、观测、参数、初始条件与适用条件。覆盖电—水—热—IT/控制耦合；郑州相变模型显式保留质量、内能、相平衡/潜热和冷凝闭合。方程归为研究提议，不能冒充官方或已标定数字孪生。
5. 明确不能闭合的状态方程及最小校准资料。区分电功率/热容量、峰值/连续负载、表压/压差、流量/存水量、设计冗余/可用率。站点UPS、电池及发电机的有无与保护范围按证据处理。

7. 核验引用来源的实际读取边界及关键PDF图页；检查台账/图/CSV一致、离线资源、链接、公式及浏览器渲染。复核应覆盖来源与方法，不以文件存在或测试绿灯代替科学核验。
8. 保留会前证据和现有风险原型，不跑新训练、RSI、注册实验或真实设备动作。完成后提交并推送现有仓库，核对远端版本与CI；校准不足仍明确标为待补数据。
