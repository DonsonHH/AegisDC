# 四轮 FIT 原生执行

实验根为已冻结的 48 行整批。每个位置先记账，再新建设施和决策工人。输入 SHA-256、公开帧、原始轨迹、独立评分、实际 CPU 和失败现场逐位置留在私服。签名回执按方案 C 验真后，才在共享父作业中调用设施。[已签查重](../fit-overlap/README.md)

| 作业 | 计划位置及预算 |
|---|---|
| 共享父基线 | 原 `V_COST` 一次跑 48 个位置，24 CPU、48 GiB、6 分钟。首个设施入口前，在本分配内检查真实角色隔离、故意拒绝的工程输入、父与零描述符公开响应逐字节相等。 |
| 首轮试点 | 一个作业，O、R 各四个提案，每个提案 48 个位置，共 384。48 CPU、96 GiB、最多 24 分钟。先封两份提案名册，再付费。 |
| 第 2–4 轮 | 六个串行依赖的臂／轮作业一次提交，各 192 个位置。整批预留至多为试点实耗乘六，并受原单臂单轮预算约束。按 48 CPU、整分钟向下取整。某项失败后留存已经提交的未执行后缀。 |

每个候选始终按完整面板计费。物理位置采用原 Python、耦合设施、原生入口和独立评分器。预算按进程树实耗和 Slurm 终态分别核对。每位置 180 CPU 秒、每臂每轮 60 CPU 秒优化控制上限。监测到硬违例、资源越界、审计缺失或不完整位置即停，无重试、替补或补抽。

在线工人、两臂提案方、评估器和只读审计器使用集群授予的不同低权限身份。每个角色只挂载声明文件，在独立挂载、进程和网络命名空间中工作。开发代码接收登记的公共视图或本臂的已付聚合反馈。OS 访问记录由受限角色之外的追踪器写入，只读审计器核对并签署；这些技术签名与 PI 的查重签名分开。首次环境检查发现 Python 启动会读取系统内存策略，而且探针脚本本身需要其公开挂载。正式程序登记这两项后再检查实际访问范围。该次检查没有设施调用。

收齐两组当轮成绩后才释放各自的签名聚合包，调用 r1 同一排行及改写规则。每份账本均用原 JSON Schema 校验。保留相同条件下改写前后的下一轮候选、后继轮实际进入付费批次的槽、胜出槽和终态父链。第四轮锁定后交审。
