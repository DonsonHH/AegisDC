# T8 阶段 0 · 合法预防窗内的等待

**本次冻结设计，等待审查。** 目标是检验利用已到达的公开证据及时处置，能否减少荷兰族的整窗服务缺额，并守住伦敦服务与两族人员实耗的界限。V\*\* 是冻结的父策略。普通改进器 O 与递归改进器 R 从同一父策略和同一提案程序起步。未来 H2 的主比较选 **R−O**，关键次要比较为 **R−V\*\***，两项均为荷兰族、单侧并作 Holm 校正。这个选择让主结论直接对应同预算普通改进之上的增量。[正式登记](registration.json)

## 开发资格怎么判

| DEV 项目 | 配对与判据 |
|---|---|
| Q1 荷兰服务 | R−父的平均服务缺额差，单侧 95% 上界严格小于 0 秒。 |
| Q2 伦敦服务 | R−父的平均服务缺额差，单侧 95% 上界至多 +5 秒。 |
| Q3 资源与合规 | 每族分别核对 R−父的平均人秒差，两项单侧 95% 上界均至多 +5 人秒。R 全部已登记位置的硬约束违例须为 0。 |

两项容许量均为开发阶段提案。按族平均折算，十二个条件合计的一分钟全缺额或一名人员工作一分钟，分别对应 +5 秒和 +5 人秒。它们以原设施的一分钟公开决策节拍为参照，现场可接受阈值未知。独立计分还需逐项保留非目标条件和退化行。只有可证明整族结果严格相同的非劣端点才可用结构性零上界；单凭样本方差为零不够。[判据、未决与失败处理](registration.json)

## 多少条件以及多少算力

历史开发板上，荷兰族父策略相对 P 的平均降幅为 825 秒，乘 0.75 得 **618.75 秒**。父策略自身平均缺额为 220 秒。若把这 618.75 秒直接当作还能从父策略追回的损失，旧板上的 R 均值将为负。功效账保留这一指定代理，同时单列与改进问题相符的较小备择。周期巡检在旧开发板的两个条件各少损失 120 秒，正向机会除以全部十二个条件得 20 秒；乘 0.75 得 **15 秒**。这是事后可见的局部机会，能否用公开信息取得、同时满足人员限制均待检验。规划只用 `41709979` 的开发材料。[原始开发对照](../../t7-incident-counterfactual/stage1/rows.md) · [完整功效网格](power.json)

## 如何识别程序改写，守住 DEV 和 H2

O 和 R 的候选策略目录、选择规则与预算一致，均可按 FIT 反馈更新自身的在任策略。R 另可在冻结语法内改写生成后续候选的提案程序。两臂每轮都保存程序原件、状态、收到的反馈、前后差异、下一轮提案和实耗。审核方固定在任策略与已见集合，比较改写前后是否真正改变下轮付费候选，并追踪到最终锁定子策略。O 的程序须逐轮字节一致。仅调参、空改写和只重排同一批候选均保留各自分类。[方法与信息白名单](design.json) · [逐轮账本格式](round-ledger.schema.json)

本次一次性生成新的公开开发根种子并固定 FIT 派生。DEV 的随机来源与取轮公式在此冻结。计分方在首次双锁回执发布后，才用预定的未来签名随机轮次派生 DEV。公开登记根种子也无法提前算出该轮输出。新面板按预登记的工作人员班次与许可窗口配对，既有物理关系不变。独立身份的核对器在每个 split 评分前一次核对完整与运行输入哈希；对 H3 只收封存索引。开发方只收整批签名放行或停止回执。真实隔离、输入零重合和接口行为均待后续核验。[种子与可信随机轮次](seed-registration.json) · [输入、旧面板与比较口径](panel-law.json) · [签名验证规范](https://docs.drand.love/docs/specification/)

H2 继续封存。Q1–Q3 全过、DEV 有真实动作与服务余量、存在可追溯的提案程序改写，而且在预定上限内两项 H2 检验的保守联合规划下界达 0.80，才可申请用户单独授权。Q4 始终只是 DEV 描述。r0 未生成 FIT/DEV 条件，未执行去重、搜索、设施或 Slurm 作业；H2 生成、读取、派生和 H3 种子原文访问均为零。静态核验用 `python -B docs/mainline/t8-rsi-wait-repair/r0/planning.py --check --checkout-bytes`。[登记及公开文件哈希](delivery.json)
