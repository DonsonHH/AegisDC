## 公共接口与关闭语义

新程序和策略分别使用可选版本 aegisdc-policy-run-program-v6 和 aegisdc-joint-problem-policy-v1。旧版本继续按原入口解释。公开构造的 ProblemSpec 给出模板／开题谓词、目标、观测／处置／复核配方、区间判据、最大次数和时钟。Candidate 由实例键、阶段、具名操作、所需许可、人员／工具、释放时刻、截止时刻和本人前驱构成。Forecast 输入是公共离散世界表、权重及响应关系。ResourcePlan 给出每条支持分支的时标、实际占用估计、逐维入场包络、位置和预留义务。PlanDecision 只发布本刻 WAIT 或一个合法请求，并留存可行集、预测量与理由。工程行号、私有工况、未来事件、下游服务账和已知标准答案只存在于外部编排或评价。策略公开读视图是分离的不可变快照。同公共历史、权限、参数表与资源时，返回相同语义决定。每种方法拥有独立设施、任务、位置及账本。

每次公共时钟先吸收合法到达的任务状态、报告和固定证据，重新验证许可、时效、资源和关闭；再处理到期义务并发行至多一项。接收 t≥arrival 且 observed≤t<expiry 的记录。承诺成功前不预支成功回执，复测始终绑定本实例实际 action_task_id／执行回执。具有本人匹配工作完成回执及当前已付报告，才可使用其中的结果。各实例 initial、action、recheck 各最多真实发行一次。共享固定测点可以在同一目标上复用，其来源和测量时刻不可变；复制不会形成第二样本。

## 一个账本如何支持多个现场实例

C 用 worker_cooling 和 tool_flow_meter，起点 loc_hx，目标 loc_lake；N 用 worker_it 和 tool_it_diagnostic，起点及目标 loc_it。资格分别为 qualified_cooling_inspection、qualified_it_inspection。初始位置来自公开可信签到，之后只能从当前已到达的可归属记录更新。按原可通行图求人员到工具再到目标的路线。每条边计旅行时间及 0.25 s 通行，同址仍有 0.25 s 入场；到站正工作 1 s，完成到回执 0.5 s。例：hx→lake 的边为 2 s，首个 C 作业完成于 3.25、回执 3.75，后续同址只占用 1.25。短窗不设外生迁移。工单状态和实物位置跨任务连续，不能每次从名义驻地出发。[原派工路线](../../../src/aegis_dc/workforce_dispatch.py) · [作业状态与回执](../../../src/aegis_dc/workforce.py)

每次发行锁定指定人员和工具至终态回执到达。成功终态只有在唯一携行、同一任务、目标和双方身份匹配时才能把公开人员／工具位置推进到目标。拒绝／中断后仅保留能够公开确认的事实；没有具名位置证据时两者记位置未知，等合法重签。已付费用和中断前实耗保留。相异专业可同时在途，但共用累计人员秒、工具秒、发行费与每刻一个发行名额。路线、资格、排班、公开通行、场地权、本人上游身份、发行及完成许可均逐项匹配。现场仍可因未预知变化而失败。

费用账沿用原生非退款入场规则。一个发行的人员和工具上界分别为 (deadline−native release)×对应数量，另加一次发行费。初检／直接行动 native release 为实例开题；复核为本人的 APPLIED 到达；问信息后同一实例的 action 仍取开题时刻。发行即记账，硬预算比较允许相等。真实人员／工具消耗按旅行、通行与有效工作另算。计划同时保留尚未发行的条件义务，分支互斥时取逐路径可行，任一支持路径超限便剔除计划。同一义务在正式发行时从预留转实账，不重复扣款。拒绝、终止或失去资格时释放未发行义务并登记未完成。不得为第二工单动用第一工单已承诺的复核。等待回执时保留真实占用和公开在途位置，不从私有路径推断下一到达。[原入场账](../../../src/aegis_dc/policy_budget.py)

## 联合选择 J 与强透明基线 B

两者使用相同的离散公共时钟、问题集、合法观测机会、执行／关闭器、共享账、世界表和预测关系。每个真实时刻先完成已承诺且可发行的本人复核，多个同时到期按最早截止、实例稳定键顺序办理。实际回执与原计划不同时，记录差异并按到时材料重排；不可能履约的分支产生未解决记录。没有新的到达或公开时钟推进不能重复发行。

1. **构造公共联合分布。** 输入为当前公共工单型、模板、设计知识、可区分的完整世界元组及有理权重，各表权重和为 1。一个元组同时给出可处置滤阻 F／正常 C0／其他水路 O、网络配置 g、可用直流上界 A、存储上限 s。按一次合法的来源组、具名任务和时钟筛选兼容元组，重新归一。相同材料不可重复相乘，陈旧／冲突／域外观察不自动补入世界。零支持时显式报告，保留本人义务，暂停依赖该假设的自选动作。已有履约义务的准入仍按真实公开记录判定。
2. **枚举有限计划。** 根为所有已开实例共同的状态。菜单包括全窗暂缓 W、至多两个不同实例行动的全部有序排列，以及至多一个待办付费初检加各可观察结果后的上述行动列表。允许一个独立行动发生在初检前或等待此次结果期间；后者必须对所有尚不可区分的后续结果同样可行。前缀、支路及排程逐一生成，行动总数每支 ≤2，已在途项目与本人复检计入费用。允许单一初检后暂缓。收到合法结果前，除共同承诺的独立前缀和强制复检外等候，不把未来分支预发。每个根只提交当前第一项，按该次承诺保留预留和数据依赖。其后仅使用实际已发布的记录。
3. **计算分支的最早合法时表。** 逐公共刻按上述优先次序，依次应用位置、发行数、资格、有效窗、到达、占用与累计上界。在排程中，对有机会 APPLIED 的每项行动须容纳其本人复查和固定采样的时间窗口。到某一 t≤H，预计已付报告尚有效，局部与服务两组各有相隔至少 1 s 的当前、合法到达样本。此条件只检查取得证据的时间机会，不预设测值正常。缺一当期不能承诺该完整计划。初检异常或拒绝的公共分支保留 W；对于有强制复核的分支保留并尝试本人的可行义务。给定私有失败不当作事前可知，实际被拒或超时不补抽。
4. **计算一个共同后果。** 书面工程预测窗为 [8,12) s，H=12。各元组在此窗中 C0 允许计算；F 在本实例成功清滤完成+2 s 前锁停计算，之后允许；O 始终受限。窗前预测允许计算。该分段关系仅是检验联合评分与排序的手算模型，原生评价须采用实际热库存／保护轨迹。一项成功网络行动在真实计划完成时把该元组的 g 置 1。每段按计算许可、配置、总负载和 A 分摊：允许时计算请求 2,000,000 W，禁用时为 0，网络与存储分别请求 100,000×min(1,g)、100,000×min(1,s) W。比例 r=min(1,A/总请求)，总请求为零取 r=1；各有效容量为 min(该配置,实际分配/额定)，禁用计算为 0。积一次 1−min(1,三项有效容量) 得该元组预测缺额。不同问题实例指向同一物理目标时，冗余处置只写同一变量，各实例付费与证书仍独立。
5. **排序。** 对每个可行计划在各权重表求期望，比较向量（共同缺额、实耗人员秒、工具秒、发行费、最迟本人报告到达）。时间与资源按支持分支的实际计划计算，最后一项取全部支持分支中最迟值，W 无报告取本刻。多份合法权重表时从最差到最好排序各表向量，再字典序最小化。最后由 W 优先、稳定物理模板／实例原始来源／动作／分支内容签名定序。数组顺序和工程行号不能破同分。真缺测或冲突未消解时，任何要求该材料的行动保持阻断。对查后拒绝、无结论等只有公开故障路径的分支，使用其取消与留账规则；不添加任意发生率到预测。每项存已选与最佳未选向量、按分支的入场界、下一次到时决定和差异原因。
6. **透明基线 B。** 先联合枚举同菜单下全部无新初检的直接完整计划，包括两项联合处置和暂缓。若在每一权重表均比 W 严格降低共同缺额，取步骤 5 中最优的该类计划。若无此计划，才考虑能在合法结果间区分“可行后续处置／暂缓”或不同后续处置的初检，且至少一个结果分支可在剩余费用内改善共同缺额。候选按实际检查人员秒、工具秒、费用、报告到达、稳定键排序。获得合法结果后从同一全局直接菜单决定，允许转办另一个问题。其余暂缓。J 与 B 默认均可直接行动；某见证明示必须有本人当前阳性报告作为写许可时，两方一同受限。

## 实施边界、独立验收与下一关

复用原生水力／热量库存、电力、共同服务、本地保护、具名检查／动作的授权执行、派工路径和全窗服务账。最小新增面包括网络现场同刻只读字段包与固定 e 通道、两种模板和实例级阶段身份、公开位置承接／分支费用预留、有限联合枚举与透明基线、两种关闭状态及外部审计导出。H10 历史评分入口继续要求终点为 10。新的独立工程核对器从冻结输入读取 H=12 或 3,600，逐段核对连续覆盖 [0,H]，分别加总原生余额与独立分段率。隔离在 opt-in 版本，新增编排只把请求提交给既有原生运行接口。允许有界修改的接缝是程序／派工加载器的版本分支、测点注册、检查完成发布、公开工作反馈、问题与关闭适配、独立工程输入／核对工具；可在相应模块旁新增小文件。无需改变 plant、power、原热控阈值、干预效果、旧 V6 研究比较、评分、已消费的启动控制或原工单语义。若必须改动这些科学或旧接口，停止相应见证交审。

[工程目录](engineering.json)把完整构造、每个公共前缀、允许动作、预计物理量、闭合身份、来源和人数列在一个文件中。P 是策略入口的合成公开快照，G 是类型和边界检查，S 是短窗原生实例，T 是长窗热工配对，L 是旧入口回归。脚本化直接／初检处理只服务指定工程见证。J、B 必须由真实策略循环办理。S12/S14 对 J 在首次信息到达前逐字比对去外部索引的公共视图与决定，S13/S15 对 B 同样核对；分开构造初态与账本，随机换输入数组顺序不得改变有唯一解的语义。实际分支未到达时保存未到达原因；工程负例不换题。

施工顺序为冻结展开后的完整输入、手定预期、覆盖图、来源版本、限额及部署清单 → 用旧入口验证新增版本尚无执行路径 → 实施新增边界 → 独立检查公共组件 → 短窗及旧入口 → 长窗两个步长 → 对已留存输出单独对账。独立检查器只读冻结预期和保存的原生输入／实际输出，不调用被测函数生成预期；按区间独算折算缺额、实耗、权限与每个关闭时刻。全量私有原始记录留在服务器，发布轻量对账、逐单位结果、失败和未执行后缀。每次尝试保留源码、输入、调度身份、起终状态、公开申请、工作／样本／处置身份、原生变化、逐时选择／预留和两种关闭账。不重复执行成功单位来扩充分母。[已有工程规则](../../agents/lightweight-engineering.md) · [计算与归档](../../agents/compute-storage.md)
