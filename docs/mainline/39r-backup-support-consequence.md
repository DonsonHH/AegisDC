# 39r · B1：UPS 后果契约

**决定：单列辅助连续性。** 适用于 `backup-ups-return-to-service-v1`。主服务缺额继续按原定义报告；下列量不并入主指标、不与原180次比较，也不加权合成一个分数。

| 后果量 | 记录口径 |
|---|---|
| 辅助供能中断（秒／负载） | 在同一已施加失电时刻至观察窗末，分别累加主控制器、内循环泵、取水泵实际功率为零的区间。分列有请求与无请求；无请求的零功率不能直接解释为未满足负荷。A1若要评估需求缺额，须先声明不因故障消失的负荷需求。 |
| 控制器供电窗口（秒） | 记录实际供电达到主控制器声明功率的连续区间、首次达到时刻及累计时长；切换间隙照计。到窗末仍满足则区间末端右删失；全程未达到则首次达到时间右删失。UPS 自用控制电源不计入，供电也不等同于控制功能核验。 |
| 交流恢复起点的状态 | 取失电后首次实际市电或柴油输出为正的同刻记录：冷热水、制冷剂、固体和机房温度（K）及控制模式。未见恢复时，恢复时刻与状态留空、标右删失；窗口末状态单独保留。 |

**证据边界。** 在交流供电为零、整流输入为零时，UPS 仅能供辅助负载，IT 交付在这段时间为零。交流恢复后的热态和联锁可能影响服务，不能据这个窗口断言服务缺额恒等。改变投入状态的物理对照也不等于检查有收益；A1仍须给出先验、观测和时钟依据，并与可直接授权处置等合法选项比较。

**复现口径。** V6 默认配置，观察30秒，第2秒将 `grid_capacity` 设为0，最大步长0.01秒；仅 `ups_in_service` 取1／0。第2秒和步长是本次声明的输入，原探针的完整输入未随审查保留。一次匹配对照，原件、输入锁和脚本见[单一结果](../../evidence/mainline/engineering/39r-ups-b1/result.json)。

| 实际记录 | UPS 投入 | UPS 未投入 |
|---|---:|---:|
| 服务缺额／交付服务 | 28秒／2服务单位秒 | 28秒／2服务单位秒 |
| 三个辅助负载各自零供电时长 | 各0.20秒 | 各28.00秒 |
| 主控制器足额供电 | 2.20秒起，已观测27.80秒，末端右删失 | 0秒，首次足额时刻未观测 |
| UPS 总峰值／保护输出峰值 | 41,728.57／41,628.57 W | 100／0 W |
| 30秒末点 UPS 电量 | 17,357,554.04 J | 17,997,200 J |
| 30秒末点制冷剂温度 | 298.784 K | 305.353 K |

两组窗内均无交流恢复，恢复初态为 `null`。用户临时表的两项电量分别与本次约7.40秒、7.45秒的轨迹点按 J 取整相符；原件不在，不能确认当时取样方式，本表统一使用30秒末点。

**交审停止点。** 两次设施进入、两个完成窗口，共60仿真秒；零策略、模型与注册研究调用。辅助后果已可观测，`backup-support` 仍为 `UNMODELED`，A1尚未开始。A2 [进度账](progress.json)的 `ups_a2_test_provenance` 分列冻结v1和现行v2，原生结果字节未改。
