# 39b第三片：同场电力与IT专业检查

在已运行的同一V6合成设施内，两个已到达且未确认的工单分别形成IT和电力问题。透明FIFO按声明身份依次派IT人员和电气人员，真实执行时间重叠，分别占用自己的专业工具。手持测量仍只能在实际完成后产生；后台实际容量、功率和工作状态不直接进入问题生成。

新增两个具名、定单位、定目标的私有测量通道：`network.available_capacity`对应network可用服务容量，单位1；`rectifier.input_power`对应rectifier输入功率，单位W。不能由调用者提供任意状态路径。输入、资质、工具、工作持续、报告延迟和误差声明仍沿用现有检查契约。

问题结果附公开功能图中的静态服务路径：network以f13关联critical_service；rectifier以f3→f12给出一条关联路径。该路径只说明服务关联，不表示实际容量、备用有效性或风险概率。两问题的故障概率与预期服务损失仍为null，不能重复累加同一服务的后果。

## 独立预期

IT任务0秒派出，在原位置门禁核查0.25秒后作业，1.25秒采样，1.75秒到达。电力任务0.5秒派出，1.75秒采样，2.25秒到达。两位专业人员在0.75–1.25秒同时工作，工具不同；未派工者和未到达结果不产生观测。

网络容量为原冻结工作点的1/4。该模型将网络实际执行功率按容量缩放，计算/网络/存储DC负载分别为2000000、25000、100000W；整流效率97/100，因此独立输入功率为212500000/97W。充足馈电和既有自动保护保持原样。需求3服务单位秒，交付3/4，缺额9/4；检查不改变实际设施能力。

这是工程竖切片，不是对两类故障的诊断准确率或检查收益评价。低功率可能由IT负载减少导致，两个工单与两次测量不足以识别根因。后续处置/复检、其他域、多问题资源竞争及39d时尺度仍需独立验证。
