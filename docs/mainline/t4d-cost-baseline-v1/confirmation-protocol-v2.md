# v3 设施的留出确认协议 v2

当前状态为书面冻结，等待两个由用户离线保管的种子承诺和另行执行授权。T4c 开发交付 `cef45c02` 已接受。本协议取代其[确认协议 v1](../t4c-action-cost-v3/confirmation-protocol.md)，v1 原件 SHA-256 为 `e77fb3c5d1b3dc6f2b9a1a62f331ebc02b127b37b2825d5c67cd27a10f0db3fc`。设施采用[已登记的 v3 规则](../t4c-action-cost-v3/holdout-registration.json)，主方法沿用[冻结的 V**](../t4c-action-cost-v3/v-double-star-freeze.json)。

## 检验顺序

当前确认面板目标为 144 个共同条件，六族各 24 条。每条条件的各角色具有独立设施、预算、证据与回执。每个比较量均为同条件左侧方法减右侧方法的全窗归一化服务缺额 L。先求各条件配对差，再求全板等权均值。

| 顺序 | 配对比较 | 进入正式检验的条件 |
|---|---|---|
| H1 | V** 减透明直接规则 B | 完整的确认面板、执行身份和预先承诺通过核对 |
| H2 | V** 减同一方法关闭自选初检的实际运行 V**−probe | H1 成立 |
| H3 | V** 减固定的成本感知透明规则 B_cost | H1 与 H2 均成立 |

每一步都使用双侧 95% 百分位区间，上界严格小于零才成立。上界等于或高于零时，本步未成立，后续所有比较仅作描述。必要输入、合法性、分母或计分未决时，本步不可判定，后续同样只作描述。三步共享条件索引和既定 T4c 重抽规则：在各族内按原条数有放回抽取同一条件的全部角色，合并各族，每个范围重抽 10,000 次，报告线性插值的第 2.5 与 97.5 百分位。种子取 SHA-256 对 UTF-8 文本 `AegisDC/T4c/paired/v1|` 加范围键的前 16 字节大端整数，使用 NumPy PCG64，全板范围为 `overall`。[T4c 分析程序](../t4c-action-cost-v3/analysis_v3.py)

人员秒、工具秒、费用、未交付服务量 U、六族结果、原定义的四位层、按公开维护时长 0／600／1200 秒分层，以及四个业务点的 NA／PV 关闭均作描述性报告。全知剩余损失比例为 Σ(L(V**)−L*) / Σ(L(P)−L*)；逐行 L* 须由实际合法轨迹达到独立下界。所需界未决或总分母非正时标为未定义，保留完整分母与逐行状态。

## 种子承诺与停止点

这里的保管标签 H1、H2 指两份不同的种子；表中的 H1、H2、H3 指三个依序检验的命题。本次三个命题都使用第一份种子生成的同一个配对面板。

| 保管标签 | 用途 | 用户提供的 SHA-256 |
|---|---|---|
| H1 | 本次冻结方法的留出确认 | 待提供 |
| H2 | 留给后续改进与 RSI 的独立材料 | 待提供 |

两份承诺只登记用户对各自离线保管的原始种子提供的 SHA-256，并与 v3 规则摘要 `7bae889a0302c2d420a9f0c3dfd199251f914b0dfaa2abeaed9a30f1013246f5` 绑定。旧执行方同账号承诺继续保持退役状态。后续核对分别验证用途、摘要和规则身份，保留失败记录。T4d 仅开展公开开发与参数敏感性；两份留出材料的生成、读取和运行均不在本次工作包中。
