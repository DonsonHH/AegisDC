## 授权如何消费

下次如用户明确批准，审查记录须绑定本页精确 manifest、有限验收、协议、启动与运行源码树、解释器、完整顺序、预算和唯一目录。其中还须有指向真实用户决定的引用。授权记录使用规范仓库 DonsonHH/AegisDC、分支 donson/mainline-39c-endpoints、固定路径 `docs/mainline/authorizations/v6-native-method-study-v1.json`。所需具名字段在 `grant_fields` 中；本次发布没有创建此生产记录。CLI 的 `start` 需要最终 manifest 的 SHA-256 和将来的授权提交 SHA，生产 CLI 不接受调用者自报的布尔授权、任意授权文件、替身或回调。

控制器通过固定 HTTPS API 在读取记录前后核对远端分支提交，核对返回文件的 Git 对象、manifest 与验收字节。身份不符或没有真实授权即拒绝。验收通过后，先排他创建 `mainline/.native-research-approvals/V6-native-method-study-v1` 的持久消费记录，再创建唯一研究目录 `mainline/V6-native-method-study-v1`。既有输出拒绝覆盖；重复授权、并发授权、已消费授权不能开启第二次研究。消费后中断保留原根与消费记录，研究重试额度为零。发布权限及 renly 账户是已有信任边界；本验收范围没有设立独立签名人或保管账户。

每份作业在提交前预记 120 预留 CPU 秒，得到真实作业号后才释放。worker 再查实际作业身份、资源、消费记录和前序终态，只能取得一次工作声明。在当前臂写入解释器与输入身份、调用前标记后才启动原生子进程。保存返回必须具有准确的逐文件源码表、源树、场景／派工／业务／外生事件身份、H10 与 0.01 步长，同时无外加行动命令与工作请求。读回通过后，对同一份验证过的快照调用原有保存评价器；在 H 臂核对 V/H 同输入、同语义后才可能启动 P。跨作业分别记保留额度、确认开始、原始返回、有效返回、已知内部数、未知数及后缀。未决时 `status` 只读查询原作业号，后续作业不自动启动。完整面板的最终封存另需 85 个原始返回、实际发行账、分臂分数和原生轨迹／余额哈希均完整。[串行 Slurm 路径](../../../scripts/v6_research/slurm.py)
