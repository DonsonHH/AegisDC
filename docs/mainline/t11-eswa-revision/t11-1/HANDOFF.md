# T11-1 执行交接

阶段 0 的身份回执与预先解读表已在 `c41ab910` 单独发布。归档 V_COST 共 72 次开发运行，压缩条件包内每一行按原生成器的规范 JSON 加换行还原后比对。整份压缩文件、还原的单条件文件、实际入口、原生入口、真实成绩和公共工人包分别绑定。研究策划、中心计时及独立计分使用不同入口。

## 作业约束

- 每个新角色在 72 条开发条件上独立使用 6 个串行批次，每批 12 条，以冻结的族内次序取键。不同角色的批次可同时运行。同角色的前批必须已按 Slurm 及十二项终态双重核实成功，才可向调度器提交后一批。每个已发出的提交意向及 Slurm 标识只消费一次。作业关闭 Slurm 自动 requeue。
- 首批使用原 v1.1 公式计算逐角色的下一批投影。非位置开销取完整 Slurm 分配墙时扣除所有单位实测墙时，并以进程实际记录的非位置开销为下界。任何角色超过自身作业时限或合计超过上限均停发。
- 每个真实请求在发入独立工人前记账，完整返回另记。实际申请经原生执行器重新准入，核对是否有成功后本人 R 可排的日历、必需 R/X 排序及单请求上限。合法拒绝保留真实后果。若已发生硬违规，完整 as-run 数值仍可做诊断；合规反事实仍按未知处理。
- 计时前先读已消耗开发原件的原始元数据和逐位置运行日志。原生决策时刻和位置总墙时不能换算为逐点延迟。缺少可重放帧或计时归属证据时，单列计时缺口。中心工人的公开回放从每条件冷启动开始，核对全部原提案摘要；从不调用中心设施或计分器。
- 调度记账保留分配和步骤。若 Slurm 有完整 TotalCPU，每个分配只计一次；整作业墙时另列。若平台进程 CPU 记录缺失，标明完整性和 Python 父子进程测量能覆盖的范围。
- 一次无设施资格分配只测试已经提交的公共策略和独立见证。若见证失败，保留原版本、原数据和失败明细。该分配的剩余时间允许处理可明确定位的实现／环境接入问题，新的实现身份必须先发布，独立见证字节不变。修改科学规则、扩大数量或需要额外资格作业时交 PI，不提交研究工作。

## 核验范围

云端研究运行使用已验证的原生核心、原始 Python 和冻结的公共工人依赖。桌面只编辑、SSH、传输和核对字节。私服留存每个已执行位置的原始轨迹、评分、输入／输出身份和逐点时间，返回包仅含公开面板、核对结果与摘要。H2、H3 封存材料没有进入这些路径。
