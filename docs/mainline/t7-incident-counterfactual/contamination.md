# 事故知识怎样进入了 T7

伦敦、荷兰的事故复盘先于这两个合成族和风险驱动方法 V\*\* 的设计。研究人员知道现实事故经过，也看过旧面板上各策略的表现。两族被选中、方法被固定，以及这次决定与哪种现状策略比较，都发生在这些信息公开之后。T7 将检验同一设计能否在新的种子下重现所登记的比较。[事故来源台账](../review-gated/R1/sources.md) · [接受的 T6 正文](../t6-paper-consolidation/r3/manuscript.md)

| 已知材料 | 进入设计的选择 | 解释结果时要保留的限制 |
|---|---|---|
| 伦敦事故中的维护隔离、供电判断、备用启动与储能耗尽 | 伦敦式条件指定可查的路径、控制关系、许可和恢复窗口。策略可以按公开证据请求核查或开展获准工作。 | 公布的事故经过解释构造动机。历史当班人员可见什么、何时能获准恢复供电、剩余电量可维持多久，仍缺现场记录。 |
| 荷兰事故中的供电转换、控制器离线、泵未重启与施工中的备用冷却 | 荷兰式条件包含重分组、泵和备用通路。观察、施工移交及各自的动作窗口限制可执行选择。 | 同一族也有无需处置或无法及时处置的工况。模拟中的时间和许可来自冻结生成规则。 |
| 已披露的两族 T3 条件、T4b 的臂间差与反例，以及其后开发材料 | V\*\*、P、报警响应、周期巡检和 B 沿用已设计的策略。T7 的主对照、事件端点和样本量均在这些旧结果已知后选择。 | 两族曾用来开发或解释同一研究路线。用于功效规划的旧行只计一次，不进入新面板的推断。 |

新的种子可以把具体抽取的条件留到登记之后。执行方在登记前只收到 H3 的公开摘要。相同的机制、策略代码、资料来源和发生器也会出现在新条件中，完整输入或运行所用输入仍可能重复。确认时逐项核对板内、T4b 和早期开发输入的身份，保留所有重合行及原分母。独立保管解决的是提前查看本次抽取的问题；跨站点或独立研究团队的外部复现仍需另取材料。[旧面板与输入身份](../t4b-holdout-confirmation-v2/condition-summary.json) · [本次登记](registration.json)
