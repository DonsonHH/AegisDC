# 39c-37：按实际证据到达时间报告三个独立参照

使用已同意的完整设施运行接口`simulate_scenario(...,business_program=...)`，新增私有`aegisdc-business-diagnostic-evaluation-v3`。旧v1/v2原件与含义保持；新版本沿用v2的状态事件、固定机会、确认截止与全部分母，逐事件增加`timing`声明。它只进评价器，不进公开判定、派工或关闭。

`timing`含有有限、严格递增的`sample_times_s`、固定`service_reference=WHOLE_FACILITY_UNSERVED_POSITIVE`、`intervention_deadline`及`source_note`。样本必须含事件打开时刻与运行终点，均为实际声明的决策／外生边界／端点时刻；禁止插值或补未来样本。截止声明为`DECLARED_PLANNED_DEADLINE`及有限时刻，或`UNMODELED`及null，必须保留来源。该截止是预先声明的计划参照，不是诊断确认截止，不从实际选择反算，也不宣称最优可挽救时间。

首次有效确认使用既有公开判断的**可用时刻**，不使用更早的测量观察时刻。每个参照分别报告节点、状态与`lead_s=参照时刻−首次确认可用时刻`：正值为早于该参照，负值为晚于该参照，零是同时。

- 故障参照为声明条件的首个私有故障样本。若打开时已故障，报告`PRESENT_AT_FIRST_SAMPLE`与左删失，真实开始时刻及lead保持null；不能把0当作已知故障起点。若先正常后故障，保留前一个正常样本与首个故障样本的开闭区间，并分别报告采样节点lead和连续转变lead区间；不声称连续精确起点。
- 服务参照为全设施`it_service.unserved>0`的首个声明样本，使用相同区间／删失规则。它是全场服务节点，不自动归因于当前疑点或行动。未观测到损失时报告`NOT_OBSERVED_BY_LAST_SAMPLE`和右删失，lead保持null；只有已有确认时才给“节点若在窗口后出现”的严格下界，不把它写成已观察提前量。
- 计划处置截止独立报告；即使在观察窗外，已知计划时刻仍是已知参照，与未观察的物理节点分开。无确认或未建模参照保持null并给原因。

首个新工程输入保持同一八域V6合成设施：初始网络容量1、外生1秒降至0.25；初始需求0.1，外生3秒升至1。公开工单只触发专业检查，实际1.25秒测量、1.75秒证据到达。合成发出费用预算1仅容许这次检查，不容许后续修复；不能由实际修复消除用于时序核验的服务节点。全部改动、预算和外生时刻在运行前固定，不是方法比较。

冻结手算预期：首个故障样本1秒，前一正常样本0秒，采样节点lead−0.75秒；服务在2.5秒样本仍完整、3秒样本出现缺额，采样节点lead1.25秒，连续节点lead区间(0.75,1.25]秒。计划处置截止3.5秒，lead1.75秒；确认截止仍为原2秒。本切片不证明故障前预测或预防因果收益；后者保持`NOT_IDENTIFIED_NO_PAIRED_COUNTERFACTUAL`。随后需独立资格覆盖右删失、初始故障／左删失、无确认、未知参照与输入拒绝，再进入成本和联合重放。
