# 完整设施方法总路线

**原生首片比较 → 两类风险的联合核查处置 → 方法配对与机制研究 → 普通改进 → 可辨识的 RSI → 整篇论文。** 研究对象是具有八个耦合域和物理、功能、控制／信息、空间通行四类关系的算力设施。问题来自按时到达的多源稀疏证据。人员、工具、许可和本地保护决定能够采取哪些付费行动。每一阶段保留原件、版本、失败和实际分母，并在对应研究授权处停下。Google 事故与 R0–R6 记录保留在有限验证章节。[设施定义](../adr/0003-complete-facility-mainline.md) · [主方法定义](full-facility-method-handoff.md) · [历史验证章节](review-gated/plan.md)

| 阶段 | 研究问题和交付 | 决定能推进到哪里 |
|---|---|---|
| 1　原生首片比较 | 在固定取水工单、手持测量、具名清滤和本人复检上，V 相对直接规则 D 能否改善实际服务，或在同服务下节约资源并保有关闭？另列固定核查 K、既有保护 P 和同模型 H。 | **第一阶段已完成，ec1e3747 的有限结果已由用户接受。** 一次性授权已消费，17 个条件、85 个独立臂全部封存。V–D 服务改善及同服务省资源且保有关闭的整板主张均未成立。[有限验收](v6-native-method-study-v1/acceptance-20261120.json) 全窗 L/U、实耗、首次／当前关闭及阶段逐行保留。[原生首片结果](v6-native-method-study-v1/README.md)[比较协议](v6-native-method-comparison-v1/README.md) · [最终 manifest](v6-native-research-launch-v1/research-manifest.json) |
| 2　两类风险的联合核查处置 | 优先组合取水／冷却与网络有效容量两个不同问题。它们竞争同一份人工发行和人员／工具预算，共同影响同一个 critical_service。 | 当前只授权总契约与工程计划，实施和有限资格另行一次授权。工程须证明两类问题可由各自合法证据打开、不重复归因；能在共享约束下选择次序、暂缓、行动及本实例复检。 |
| 3　方法配对与机制研究 | 对同一外生条件独立运行联合方法和强透明对照。分别固定问题生成、证据选择和行动排序，用受控比较识别各自增量。 | 保留可以区分策略及不能区分策略的公共历史。实际服务、资源和关闭分别判定。预定对照、完整分母、预算与停止条件先冻结。 |
| 4　普通改进 | 固定改进器 U，用本组已付反馈产生并锁定候选策略，再在预先分开的后续任务评价。 | 与固定父策略、无需反馈的人工规则及同预算搜索比较；记录验证、拒绝、成本及负结果。 |
| 5　可辨识的 RSI | 检验经验是否改变了提出／筛选后续策略的程序 U 本身，以及改变后的 U′ 在仍有选择的后续任务中是否带来增量。 | 固定父、固定子、固定 U 的普通改进及同预算搜索均须可复作。若同一公开前缀没有后续提案分歧，保留不可识别结论。 |
| 6　整篇论文 | 串起完整设施、证据边界与算法、方法配对结果、改进与递归增量；在有限事故章节陈述有来源的机制和未知项。 | 每项主张绑定相应设施／数据、对照、分母及证据层级。尚无独立确认或现场收益的主张保留其状态。[已接受的伦敦章节](review-gated/R6/london-pre-manuscript-v1.3/acceptance-20261119.md) |

**阶段 1 的接续资产。** 现有原生设施已经把计算、网络、存储有效容量与需求合成为同一个服务交付值；稀疏记录、到达时钟、本人回执、完整分支包络、收费、隔离运行和独立积分都可复用。后续最小接缝是增加能区分网络容量与下游瓶颈的合法观测和工单绑定，限定受权网络操作及其复核，在同一账本上比较两类问题的可行分支。联合服务缺额只积分一次，保留共享工具／人员冲突、时间顺序和信息仍不足的例子。具名操作和聚合服务测点已有源码接口，网络侧诊断资格、两类问题排序和跨实例位置复用仍需实证。[共同服务交付](../../src/aegis_dc/plant.py) · [观测目录](../../src/aegis_dc/sensor_channels.py) · [具名操作目录](../../src/aegis_dc/intervention_execution.py)
