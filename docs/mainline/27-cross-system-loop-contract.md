## 两处公开接口缺口

1. `sensor_channels.SIGNALS` 当前仅温度、控制温度、湖水质量流量和整流功率；没有可供24关闭条件使用的真实服务交付通道。拟新增一个显式白名单 `joint_service_delivered`，目标 `critical_service`、量 `service_capacity`、单位1，私有当前快照路径为 `it_service.delivered`。它表示新声明的归一化交付计数仪表，不是故障真值、保护内部状态或全场遥测。使用现有固定仪表的范围、误差、丢失、轮询、到达和有效期规则；与既有湖水流量通道在7、8秒采样。因本窗口恢复后的外生需求恰为1，交付读数1可用于本例服务恢复条件；不把它泛称为任意需求下的交付比例。新通道须有真实运行的采样／未达／失配负例。
2. `replay.run_recorded` 的闭合输入v1仅携带外生事件、工程命令和旧工作请求，不能保存及重放在线调度、实际检查、处置和核验程序。拟加新版本v2，显式携带一个实际 `dispatch_program`，并保持旧v1字节语义。带dispatch时旧显式work_requests必须为空，不能同时提供work_program／inspection／intervention侧门；工程命令权限和外生事件仍按原13区分。重新运行必须从冻结模型、外生输入和程序计算真正内生处置，不使用原私有轨迹作为输入。

重放比较保留决策、模型调用计数、工作／反馈、测量、事件、轨迹、平衡及输入。只将 `policy_computation_audit[*].elapsed_ns` 明确列为墙钟诊断，不要求逐字相等；不能整块忽略policy结果。Git提交／尝试UUID／生命周期时间按原13已声明身份字段分类，不能成为隐藏差异的通用豁免。
