# 完整算力设施的风险驱动按需核查与受约束处置

**主方法与实施承接说明 · 2026 年 11 月 20 日**

**论文主体是完整设施上的决策方法。** 本次用户澄清确定，导师提出 Google 事故，是为了给已有方法增加一个有效性验证章节。研究对象沿用 ADR-0003 接受的郑州核心节点／曙光 8000 工程参照启发的八域合成设施。它允许研究供配电、热排出、服务与专业作业在同一时钟上的相互影响。事故复盘提供机制与未知项，伦敦 PRE 已取得的结果只解释其实际比较过的处置、信息和时限。本文接替“等待导师重定方向或另选设施决策”的旧导航。[11 月 3 日研究决定](../meetings/2026-11-03-research-reset.md) · [已接受的 ADR-0003](../adr/0003-complete-facility-mainline.md) · [完整设施规格](../../.scratch/full-facility-mainline/spec.md) · [原主线快照](history/20261112-before-reset/MAINLINE.md)

论文的论证顺序是完整设施与合法信息边界、按需核查与处置算法、原设施上的配对效果、Google 事故机制验证、普通改进与递归增量。后三项都按已有或未来实际取得的证据表达，伦敦工作稿不充当整篇论文。

**推荐首片是 V6 上的取水低流量工单。** 对同一项已打开的疑问，判断现在应派冷却专业人员测流量、在已有许可下直接申请清滤，还是暂缓。处置后按本实例的实际回执、复测和服务证据核验。现有源码已分别走通过价值选择和动态工单闭环。首片要补的是二者之间带身份、时间和资源约束的连接。一个流量读数能排除部分解释，不能单独诊断滤网堵塞。选它的理由是有可复用的接口、独立手算及自动恢复反例，可以核验闭环的真伪，研究输赢尚未知。阅读时可依次看决策算法（§1）、代码与证据的对应（§2）、三类对照（§3）和首片接口及验收（§4）。本包是书面承接，首片的实现与执行额度均为零。

### 在线决策规则（拟承接的透明版本）

1. **形成问题。** 在事前声明的公共决策时点取得脱离设施对象的快照。核对目标、来源、采样／记录时刻、到达时刻、有效期、质量和可读角色。复制或同一物理来源的记录归为同一证据组，矛盾、陈旧、阈值误差带跨界与缺测分别留痕。历史上有效的观测只能按声明的时间演化模型进入认识，不能当作当前许可或当前确认。由到时的报障、维护造成的屏障变化、可信测量或带版本依据的风险复审条件开题。问题保存模板、来源实例、资产／服务、时间窗、待区分的原因和关闭条件。同源转发或重复轮询不另开题。同一工单既触发实例又参与认识更新时，只贡献一次观测因子。长期无测点本身不能确认故障。当前工单工厂仅支持声明的布尔触发及有限实例，其他触发须另行取得接口支持。[实例形成](../../src/aegis_dc/problem_tasks.py#L128) · [证据认识与相关性](18-belief-updates.md)
2. **从情景推到服务。** 给每个问题列可能诱因、屏障、容量／访问传播路径、可观察区别和行动能力。沿用 FEMA 的情景—资产—后果—能力思路。只对有共同口径的有限假设使用先验、转移和观测似然。在时点 t 只用已到的有效因子更新对应观测时段，再传播至 t。未声明相互独立的记录不能简单相乘。模型不支持、证据冲突或参数不可识别时，输出原因、条件边界或 `null`。例如低流量可能来自滤阻、泵的有效供电或阀门状态，不能把“冷却受限”的概率径直写成“滤网堵塞”的概率。[有限认识模型](../../src/aegis_dc/belief.py#L260) · [八域风险与覆盖口径](39r-coverage-criteria.md)
3. **生成可行动的选择。** 从开放实例和经声明的资质、工具、操作及复检目录生成暂缓、具名直接处置、获取一项证据后条件处置等分支。检查可以是查阅一份有效记录或派专业人员去测量，须绑定真实取得途径与费用。某些疑问只能升级给有权者并保持开放。直接处置只要求其自身的操作前置条件，法定或任务规定的前置测量不能省略。对每一个可能实施的分支检查角色、起讫许可、可通行路径、人员班次与共享工具、最迟完工／结果到达、执行及后续必需复核的承诺。硬约束逐分支查，不能靠较低的平均占用放行。门的输出是“可计划／不可行／尚未知”，不签发物理成功回执。[工作准备](../../src/aegis_dc/workforce_dispatch.py#L45) · [具名处置准备](../../src/aegis_dc/intervention_execution.py#L84)
4. **选择第一步。** 在同一外生需求、时域和其余问题共同的后续规则下比较。记 $d(s)$ 为需求，$c_i(s)$ 为各必要服务组件的有效支撑能力，声明的联合容量模型给出 $y(s)=\min(d(s),c_{计算}(s),c_{网络}(s),c_{存储}(s))$。全窗报告归一化缺额 $L=\int_{d>0}(d-y)/d\,ds$（秒）及未服务量 $U_{\rm svc}=\int(d-y)\,ds$（服务单位秒）。按联合情景的概率质量加权。一条服务同时受多个域影响时，对同一结果的重叠时间窗取并集。可用容量和真实 $y$ 的事后轨迹只供评价。预测使用声明的条件容量、保护响应与行动效果。[联合风险与窗口并集](19-risk-scenarios.md) · [有限行动树](20-action-value-contract.md)

   对证据 k，把移动、等候、实际核查和报告延迟纳入时间轴。令 $z$ 表示可收到的报告（含未知、失败、届时无报告），$u(z)$ 是在报告依法到达后仍可执行的后续动作。检查方案的预测缺额为 $\sum_z P(z\mid h_t,k)\,E[L_{\rm 全窗}\mid h_t,k,z,u(z)]$。到达前各分支执行相同的第一步，本地设施继续演化。没有报告就不能执行依赖报告的动作。与同权限下可行的最佳不查方案（直接处置或暂缓）取差。报告人员秒、工具秒、声明费用及关闭义务的差值，不换算成停机秒。不能把多个问题各自的“最优收益”相加。

   给出一个可复作的推荐选择规则。先安排已到条件且有期限的强制安全／复核义务，多个义务按最早可行截止、再按稳定身份排序。若资源冲突使义务无法全数完成，记录未满足项及最早受限原因，不能重复占用同一人或工具。在其余候选中只比较同一服务、同一窗、同一联合模型的一步行动树。对同一到时公共历史 $(h,z)$ 先固定一张各变体共用的续决策表 $u(h,z)$。首片只在合法直接处置和暂缓中比较，预留必需复核。对支持该报告的变体，均按期望缺额、人秒、工具秒、同单位发行费顺序取最小，数值并列先暂缓，再按稳定身份裁决。续动作一致才取该动作。分歧或无法赋值就按预定的暂缓／有权转交处理，保留开放义务。没有任何变体支持实到报告则登记模型冲突。把这张统一表回代各变体，得到各第一步的全窗预测，再按相同顺序比较。按评价者才知道的真实变体分别取最优续动作，所得预测缺额至多是乐观下界，不能当作同一可部署策略的价值。若声明敏感性变体在第一步上一致，发出这一步。若无共同效益口径、变体改变第一步或有必要分支的可行性未知，公开记录不可比的具体项。此时用公开声明的报告分支作判别：至少两种可能及时到达的有效报告能改变后续合法动作或排序，或其区别能解决一项已知核验义务。只在该条件和预算满足时，按最早截止、到达和稳定 ID 选择具名核查。不能读取将实际出现的报告来决定是否派工。否则暂缓并保留开放问题，有授权升级路径时登记转交。这是拟议的有界滚动规则。仓库已有的单问题比较采用缺额、人秒、动作名称裁决，并没有全场多问题联合最优性的证明。[既有裁决](../../src/aegis_dc/action_value.py#L178) · [前瞻与未知回退](../../src/aegis_dc/lookahead_policy.py#L104)

5. **真实执行并复核。** 只向执行器发送这一步的实例／任务意向，记录已发、占用或待确认。执行器在当前时钟核对实际人员、工具、逐边通行、安全与归属，允许排队、拒绝、中止或超时。只有完成了足额专业作业且届时授权仍有效，才可在具名物理接口施加一次残余效果。行动回执、人员完成回执、复检样本和服务记录各有观察、到达与失效时刻。在本实例自己的行动与复检身份、规定的状态／服务样本及跨度都满足后，才记证据验证关闭。正常读数可以否决本次处置。实例是否允许据此结题，要看本域已声明的证据规则。合法否定／受权误报审查、管理接受、升级、物理核验和仍未解决分别记账，不从“到访”“已实施”或“服务已恢复”倒推关闭。一次失败不从分母消失。[实际处置](../../src/aegis_dc/intervention_execution.py#L108) · [实例复核](../../src/aegis_dc/problem_closure.py#L95)
6. **两种反馈时钟。** 本次实际产生且已经到达的测量与回执更新该实例的认识、预算和待办，然后回到步骤 1。在一次设施运行中策略版本保持锁定。结束后评价器使用私有真值结合完整需求、实际服务、逐任务占用及删失记录给出一次对账。只有经批准交给离线学习方的开发反馈，才可在后续任务改变策略或改进器。[原生事件循环](../../src/aegis_dc/plant.py#L718) · [策略会话](../../src/aegis_dc/policy_execution.py#L11)

```text
对每个已声明的公开决策时刻 t：
    h ← 当时可见记录及本组到时回执。按来源去重，更新开放实例
    Q ← 各实例的候选解释、证据缺口、同窗服务后果和当前复核义务
    A ← 公共硬门允许的第一步及各报告分支的续动作，同时纳入暂缓
    a ← 先处理合规的到期义务，否则按步骤 4 的数值规则或显式回退选择
    保存 h 的身份、Q、A、选择和拒绝原因。每个实例阶段最多发行一次
    有意向才提交。原设施、本地保护和在途作业都推进至下一公共时点或窗末
    真实结果按授权渠道与到时条件发布，暂缓或未开题也消耗日历时间
评价端在完整窗口结束后记后果与未完成事项。在线端不读取这份记录
```

## 3　把三种增量分开检验

下述问题与对照供设计后续研究使用。本轮不冻结数值阈值、最终样本、执行预算或研究协议。令 π 是“给定公开帧和本组历史，发什么意向”的程序，U 是“给定已付开发反馈、当前 π 和剩余额度，下一项提案如何产生／筛选”的程序。两者都无权修改物理设施、许可、源记录、对照的行动机会、评价器或判胜口径。

一次普通更新按“锁定父 π 与 U → 用 U 产生有限的策略差分 → 先扣同价验证额度 → 取完整配对反馈并检查硬门 → 按预定准则采纳或保留父 π”进行。技术失败、未决与耗尽如实保留，不能用未返回的计数推算尚可重试。改进器更新则先锁定 U 的实际代码差分及其依据，在新的、尚未用于选择该差分的任务上，由父／子程序分别真正提案并付费验证。修改触发、提案差异、随后锁定的实际 π 和最终设施后果都要能对账。研究性保密与结果权限另有要求，同一账号内的分工和时间隔离只提供有限留痕。

| 待检验的问题 | 强对照、可修改对象与判据 |
|---|---|
| **整体方法的有效性。** 由实际到时证据开题，再按风险和行动价值分配专业能力，能否在同一完整设施上改善关键服务或减少必要占用，同时守住安全、授权和声明的关闭义务？ | 比较完整规则与同接口的强透明规则（当前状态满足门时直处置，不满足时依法取证／暂缓），以及固定的到时条件优先和一步观测前瞻。给选择器同一合法问题来源、候选能力、资源与本地保护。另用同一实例发生器固定后只换价值排序、或保留同一选择器只换开题规则的受控比较，分辨开题与选动作的贡献。无人工作业是背景，FIFO 和有真实周期义务时的周期规则是参照。各处理要自己获取并支付观察，不能共享别组读到的答案。 |
| **普通自改进的贡献。** 固定提案程序 U，利用付费开发反馈更新策略 π，能否在随后锁定的不同任务上优于原策略和同预算搜索？ | π 的可改项限于公开特征的使用、选哪项证据、何时直接处置或暂缓及并列顺序。U 读取本组已付开发记录，提出一个有差分的 π′，支付验证、拒绝或锁定，再换后续任务评价。保留初始 π、人工候选、固定 U0、同预算强搜索和无需反馈的固定规则。记录实际提案数、收费、缓存、失败与终局。只改变单回合后验属于在线认识更新。 |
| **改进器的递归增量。** 经验能否改变产生／筛选后续策略的程序 U 本身，并使它在之后仍有真实选择机会的任务上取得额外改善？ | 明确 U→U′ 修改的是提案算子、搜索顺序或筛选逻辑中的哪一处，保存父子程序／配置及触发的已付历史。先独立验证修改，再在相同后续公开前缀上核对提案是否真正分歧，最后比较实际锁定行为和后果。对照固定父、永久使用同一固定子、固定 U 下的普通改进和同预算强搜索。各组共享人工先验、可用的获取机会、同种计费规则和总上限，分别记录生成、验证、拒绝、计算和人员的实际支用。一次选择固定程序或调整人工规则不能登记递归收益。若声称多次递归，须有真实连续的程序版本链与跨机会对照。同轨或无可分辨的后续选择时，报告增量不可识别。 |

**怎么判。** 后续若获准，按事前定义的机制覆盖和可操作差异配对。外生需求、扰动与共同噪声机制、初态、能力目录、工时、公共时钟及预算对齐，各组独立执行。策略造成不同的后续观察与设施轨迹是应测的差异。开发、付费选择与锁定评价分开，按目标窗和单位预定主比较、否决项、严格改善与并列处理。筛选依据不能是已知赢家。全设施配对单位是事前定义的外生工况，检验改进程序的单位是验证后仍可作出后续选择的任务序列。不同处理、tick、票数和重复回执都不增加独立样本。报告每个同条件的服务缺额／未服务量、按人和按工具的实耗、费用、合法关闭以及不可检测、未处置、失败与删失。没有可靠的混合权重或总体来源时报告条件、分母与取舍。作为有限服务改善的可反驳判法，可要求在预定配对集合中相对指定强对照没有新违规、不丢规定的合法关闭、逐行归一化缺额 L 与未服务量均不增加，并至少一行有效 L 严格下降。某行实耗更高须单列服务／资源取舍。只谈资源改善时须逐项同尺度比较。普通改进与 RSI 应分别检验其增量相对各自强对照是否仍成立。没有严格服务差异即不支持该项服务主张，资料不齐则记不可判。独立保管和独立确认仍未成立。[原设施规格的评价边界](../../.scratch/full-facility-mainline/spec.md) · [伦敦归因上限的限定记录](review-gated/R6/london-pre-closure-decision/README.md)

诊断评价的单位是提前声明的物理机会，同一事件的多条工单、多个决策 tick 或不同截止窗口不应增加分母。记首次公开可辨识、实际确认、动作生效、服务恢复与证据关闭的时刻。初始已经异常时注明起点左删失，窗末尚未观测到后果或恢复时按对应终点右删失，未识别的风险概率、距离和预防量均保留缺失。没有匹配不行动／替代行动轨迹时，只能报告先后和差值范围，不能按一次正提前量记为成功预防。

| **3　一个真实选择点** | 在 `compile_problem_actions/choose_problem_action` 与 `choose_work` 的接合处，把本实例当前可发的检查、已获准的直接行动和暂缓映射给价值比较。旧前瞻要求具名固定候选和整套声明，不能只换策略名。初态对各对照保留同一直接权限。若任务本来强制先测，直接分支对所有组都记不可行。选择先测后，本实例在报告待决期间不能因 `action_condition=null` 抢发清滤。等真实有界测量、匹配完成 ACK 与到时记录，在下一公共决策点重算。误差跨界、过期或来源冲突保留未知，无正常结果可提前消费。仅返回第一个意向，已发动作不重复。在规划侧为各正支持分支的首检、行动及必需复检列出彼此不同的实例任务键。按截止减最早合法公开释放时刻的保守包络核人员／工具，加各自发行费用。某分支的最早释放无法由公开声明给出有限界时，资格未明。尚未到时的复检只能作条件预留估算，不进可发候选集。各任务在真实发行时才各扣一次。 |
| **4　原生执行与自身复核** | `prepare_work/prepare_intervention` 只作公开准入，随后由 `CrewWorkforce` 占用人员、工具、逐边检查访问，`InspectionSession` 真正完成工作才采样，`InterventionSession` 在完成时复核合成授权并只应用一次具名残余设置。该实例的 APPLIED 与相应人员 ACK 到达、资源可用后才可派自身复测。由 `assess_instance_closure` 同时查复测及规定的条件／服务样本。检查路线、直接路线与暂缓均在同一外窗内计入原保护、已发生占用和服务后果。 |
| **5　贯穿评价和保存** | 显式接通 `PolicySession` 的注册、公开历史和 `resource_ledger`、`plant` 的结果输出、`business_endpoints.validate_business_program` 的嵌套版本守卫。复合评价仍走 v5，分别绑定每一臂的实际派工身份，使用同一语义的私有事件定义和指标。同源录制／回读保留每个根选择的公共理由、真实请求、到达、拒绝、未执行后缀与终态。旧 `assess_conditions` 在选择之后记录，不能将它或评价端的实际诊断直接传给新策略。[正常入口](../../src/aegis_dc/__main__.py#L28) · [执行会话](../../src/aegis_dc/policy_execution.py) · [业务版本守卫](../../src/aegis_dc/business_endpoints.py#L57) |

### 有限工程资格的独立预期

下列是下一工作包须在看到新输出**以前**固定的见证义务。独立撰写预期，只能用已声明的物理关系、事件先后和手算，不调用待验决策器、执行器或评分器来编答案。旧见证用作回归坐标。新增连接须有一条从新工单到私有业务结果的同次运行，一组分量测试或拼接旧输出都不能替代。

| 见证 | 判别输入与事前可写下的结果 |
|---|---|
| 开题、复制与盲区 | 相同公开历史下配两种不同私有状态，使用同一事前公共决策时钟。开题前均不发行。工单依法到达才产生一个实例。同源转发只增加来源审计，不新增风险事件、任务或预算。未来流量、他组回执、私有门禁／故障标签变动不得改变当前公开帧与选择。没有固定测点时仍可从有效人工工单开题。 |
| 暂缓、先查、直处置的独立算术 | 原 20 项的 100 秒算术例中，异常先验 p、检查用 10 秒、灵敏度 4/5、特异度 9/10，修订用 20 秒，在此示例修订期间服务不可用。手算暂缓和立即修订的期望缺额为 100p 与 20 秒。“阳性修订、阴性暂缓”两类叶子给出 44p＋2(1−p) 秒。在 p＝1/4 时为 12.5，对照分别为 25、20，期望占用 15.5 人秒。p＝0 时暂缓无缺额且不占人，p＝9/10 时，阳性才修需 39.8 秒，查后两种报告都修是该点最小的查后缺额，也需 29 秒，高于立即修订的 20 秒。这些是声明分支的独立算术，仅用来核验选择逻辑。V6 的滤网故障率、清滤时长和效果律须另有依据。应再按本切片自己的公开作业树手列所有合法续分支，验证映射到的**实际实例第一步**与预期相符。比如承接 27 的同口径证据时，工单到达前假设质量 1/100、该报告在两类状态下的似然 3/4 与 3/100，贝叶斯手算到达后对应质量为 25/124。同源副本不得改变它。若映射、时间域或条件律改变，应重定预期，不得移用此数。[20 项独立叶子表](../../evidence/mainline/engineering/20-action-value/reference/independent-action-tree.json) · [27 项独立认识与时序](../../evidence/mainline/engineering/27-full-loop/reference/independent-literals-v1.json) |
| 新接缝的正例与反例 | 在共同的工单根、完整门和事先可复算的有信息测量条件下，首选实际检查。到达前同轨，只有付费完成才有读数。已声明的两种**足以改变续决策**的有效结果，到达后分别落入“有据且合规的清滤”和“无须该行动，暂缓／按证据处理”分支。再保留读数不区分两因、阈值跨界、迟到／过期或无结论的情况，不能因读过就强制清滤或关闭。另以只改变公开证据／约束的根见证合法直处置和主动暂缓。如果无法预先给出有辨别力的分支与条件后果，登记未识别，不靠挑运行赢家补齐。 |
| 人员、工具与权限 | 同一台流量仪已经占用时不能双派。有资质声明仍可能在安全侧通行检查时被阻断，已走路和等待照计，只返回允许的延迟反馈。处置授权恰在完成时到期则无成功效果，也不能发行“成功后复检”。原公开夹具的首检、行动、复检发行费各为 1，费用上限为 2。直接处置加复检可负担这两项费用，先查再处置再复检需要 3。旧前瞻只预查 inspect＋action，在这里会漏第三项。若复核是必需义务，在该费用边界不得让三段计划通过。它是按原文件手算的负例，成功的三段链另用足额的公开工程条件，且三种路线始终同账。[原夹具的策略预算](../../evidence/mainline/engineering/39c-development/slice-54/service-unqualified/frozen-call-input.json)对照各自付实际发生的费用，一项任务的重复回执不重复扣费或制造第二份测量。 |
| 成功也要等自己的复核 | 可用既有直接分支的独立时序锚点。在同一缩放配方，2 秒移动＋0.25 秒门禁＋1 秒工作得 3.25 秒才完成清滤，3.75 秒才到行动报告。复检完成 5 秒、报告 5.5 秒，只有本实例的完成 ACK 和当期规定的状态、服务样本都已到且合格，才在相应公开决定时刻验证关闭。复制、借用另一工单、残余流量未达标或只有 APPLIED 时均保持未核验。保留新的“先查再决定”同跑见证，不能把此直接分支时间复制为先查路径的时间。[事前时序约定](39c-instance-closure-contract-16.md) · [同跑锚点](../../evidence/mainline/engineering/39c-development/slice-53/README.md) |
| 因果与终态 | 用不派工／暂缓、相同外生条件和同一原生保护作参照。检查本身不得写滤阻，清滤只在授权完成后改变具名参数，不能追溯消除此前缺额。对“服务先恢复”的旧见证，4 秒首采恢复、6 秒动作完成、8.5 秒才验证关闭，三件事分别归档。容量由别的组件限制时也允许全窗服务持平。只有相同外生条件的完整配对才可评价人工增量。保留无阳性、未到场、未完成、未恢复、技术失败与预算耗尽的所有单位，不用零代替未知或删失。[27 独立时间与物理预期](../../evidence/mainline/engineering/27-full-loop/reference/independent-literals-v1.json) · [其保存记录](../../evidence/mainline/engineering/27-full-loop/capture-20261107-03/checks.json) |

### 后续实施顺序与交付界线

1. **先定契约与工程输入。** 后续明确授权首片后，锁定 v6 场景、一个动态模板及其跨目标来源绑定、有限条件律、公开时钟、权限／费用、外窗、配对条件、字面预期和实际总预算。先核 27 与 39b／39c 的接口差分，对未支持的量保留未知。有共同设施身份也不能混用不同配置和缩放时长。
2. **接通公开选择，再接原生作业。** 在公共帧核对候选确由到时线索打开，并验证三种第一步均有受控的可达见证。借用现有前瞻、预算及实例复核，保留约束先于排序。再经正常 `simulate_scenario`／CLI，由同一原生设施执行实际首检、具名处置、失败／成功后的反馈、复检与私有对账。旧输入沿原入口产生原有行为，不以历史专用路由冒充新语义。
3. **只做首片有限资格。** 后续按原计算与留痕规则在 Slurm 执行，输入、预期、源码和预算先冻结。记录每单位的选择理由、达到阶段、工时／工具、调用、断言和终态，失败原样留存。同一运行的公开过程和私有后果按身份关联。必要的受影响回归与新见证分账。若需要改变物理关系、证据权限或指标含义，停止受影响部分，带具体差异交审。
4. **工程达标后才讨论效果研究。** 完成标志是上述三种决定及到时分支、实际作业和独立端点在原完整设施上的有限证据。服务持平或没有可识别的人工预防贡献也要报告。这不会自动完成全八域的风险标定、39c、完整 R5、独立确认或 RSI。能否进入整体方法的配对研究，再到普通改进、最后到改进器增量，由对应的可辨识对照和另行授权决定。
