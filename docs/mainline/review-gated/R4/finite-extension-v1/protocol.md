## 固定分析

完整分母为35个具名槽位，每行含I/D/P。先登记运行状态、实际请求／阶段、拒绝或失败、记录身份、硬约束、恢复及完整窗口，再给出L、U和各成本分量。缺失评分为null，未恢复按[0,20)完整积分并报告删失。非合规保留原始损失和成本。已执行且三组完整合规才计算有效符号。未达指定阶段、未构造、未资格、未提交、调用未决或失败各自留行。每行保留原始结果位置和哈希。服务、人时和工具耗时分别汇报，不设置标量权重。

| 命题 | 适用行与判据 |
|---|---|
| F1 | 在全部完整合规行计算 ΔL = L_D − L_I。任一正值即否证“本清单固定 I 均无缺额优势”。有有效反例照常完成其余覆盖。全部适用义务完成且均无反例时，只能支持本清单。 |
| F2 | 仅 A01/A02 观察合法否定证据是否使 I 短路。记录FIX申请。I/D同服务时检验I两种资源实耗是否各严格较低。不同服务时报告权衡并标该成本子命题不适用。 |
| F3 | P 为既有保护背景。逐行给出 L_I − L_P 和实耗差。任一完整合规行 L_I < L_P 否证本清单的“相对P无改善”。 |
| F4 | ONLINE 且没有成功修订或其他物理干预时核对I/P服务机制。实际复核须绑定到达的执行身份和目标epoch。机制不一致记技术错误并停止后缀。 |
| F5 | 以实际提交、回执、时间和当时公共计划核对严格截断、权限、预算及窗口。有效提交必须早于故障、许可到期和窗口末。同公共历史不能引入私有信息。违反信息边界或硬技术不变量立即停止。 |

保留I/D主比较及D公共不可行的预分层。无总体抽样框，不计算总体功效、区间估计或普遍实用阈值。所有推断限于本版合成机制与固定清单。本轮只交执行前材料，研究结果计数为零。

## 一条启动路径与两个预算

选用登录节点的串行提交器调用 sbatch，每个槽位进入同一 slot.slurm，经固定 Python 执行一个条件。提交器等待该作业的实际终态、退出码及外层完成记录，三者一致才提交下一项。固定输出根采用排他创建。读取或回传失败先恢复同一作业及原有文件。未知不会释放重试预算。已确认技术错误止住后缀，合法拒绝、非合规与有效反例继续。

工程替身只读取原公开工程 X01/X08 的已固定原始返回和配置。追加的故障作用在归档、计数或进程边界，这些替身共用原公开设施输入。输入、来源哈希、独立字面预期、覆盖与停止规则见 [witnesses.json](witnesses.json)。真实设施、策略与评分调用的准备预算均为0。所选路径为同账号程序控制，最终研究需要用户针对冻结manifest的另行授权。

准备最多8个串行作业，每个1 CPU／1 GiB／120秒，累计不超过960预留CPU秒。预算包含静态编制、预期红阶段、入口替身、调度成功／故障和保存核对。修复限于已确认终态的工程错误，另开尝试、保留原失败。充分通过后结束。未来研究最多35个串行的单条件作业，每个1 CPU／1 GiB／60秒、3处理、最多60次策略调用，全包最多105处理、2100次策略调用、2100预留CPU秒。R5、RSI、荷兰及RESP不在本活动内。
