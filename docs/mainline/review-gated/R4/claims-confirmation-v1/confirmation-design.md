## 3. 非结果选择、候选域及去重

推荐一起review有限候选背景域：H20、P1、τG1、τB2、审批1、准备2、提交1、退出2、发布1、TTL12、grant到期20固定；read_work和verify_work各取{1,2}，E0取{1/2,1,3}。公共预算／窗口端点取1–20整数；预约最多一段、整数端点且长度1–3；tF/tR取0–20整数或NEVER。其余继承既有C0，仅按槽位主因素改动。这是候选域提案，**不是确认输入生成或已获资格的组合域**。

1. 用户先固定本覆盖表、候选域、核心及分析版本，指定C/V保管与核验职责。正常、不利、不可行、失败、非合规槽位同等保留，不按I/D/P赢家分配数量。
2. C在候选域内按静态配方、权限、资源和前序到达要求建立候选；不得调用模型／策略／评分器试跑筛选。无法静态确定的阶段或未资格组合列为依赖，而不是先看结果再选。
3. 配对组从共同背景构造其关联槽位。多个合法背景使用C私下生成、预先承诺的种子作确定性哈希排序，取首个满足全部非结果条件者。种子只作行政排序，不赋发生概率；本轮不生成种子或候选。
4. 完整配置规范化为带类型的canonical JSON：排序键、精确有理数、整数与布尔区分。排除condition_id、文件名、路径等索引后做SHA去重，拒绝与原19开发、既有全部披露工程及本清单其他项完全相同的输入。
5. 另记语义签名：目标R分支、主因素与基准配对、需到达阶段、相对截止顺序、预算／窗口可行区间、供给／副作用、行动相关的实际时长和资源占用机会。只变标签、无作用字段、顺序或共同单位缩放不能算新条件；无故障且UPS不放电时仅改E0也不能制造新颖性。相同主义务但确有不同机会窗口可作为新独立准备的参数实例，须说明差异，不能仅以粗类别相同就误删整个义务。
6. 内部配对的不同边界／主因素是不同义务，不因为同输出而去重；同一输入不能只换角色标签重复占多个义务。必要时按表顺序分配主义务，对冲突组重新选择排序中下一个合格共同背景，不能单独替换有利成员。
7. C保留每槽的候选序位、入选／拒绝依据、去重、资格及前置审计。若穷尽候选仍不能构造35个符合规则的槽，提交空缺与N修订建议供review，不扩大域、弱化独立性或填重复案例凑数。N35是有依据的推荐目标，不是假称已经找到35份明文。
8. 这些是“独立准备、选择不依赖结果的有限条件机制确认”，不称全新机制或现场外部验证。确定模型的结果可能从规则预判，尤其正常×隔离组合；必须记录这一可预见性，不把模型蕴含关系的复核宣传为未知科学发现。

D01及其他处理前D公共不可行者按预定公共层单列，但保留35行总分母。审批、提交、复核、恢复、非合规均为输出，不能用于筛选入组。若实际未到预定阶段，原行记“覆盖未达”，不得替换成成功例。

B族的work_mode分层属于评价端机制条件；固定v2策略并未收到该字段。全程保持该信息边界，不因确认需要解释副作用而临时把它加入策略输入。完整原始预约表同样不直接传给策略，仅使用既有公共计划投影。

## 4. 总预算、版本、停止

推荐上限35个条件作业、105处理、2100策略调用；每条件1CPU／1GiB／60秒，累计最大2100预留CPU秒。建议并发1，峰值内存请求1GiB，无GPU。60秒沿用旧确认门的操作保护预算，不是功效依据；资格准备另行授权、另账，不从确认预算拿样本调试。无自动增加预算或研究重试。

先冻结本设计与分析版本；后继资格不得修改核心1c0b0c47。新确认薄入口、清单规范化程序、环境、全部文件SHA及核心Git blob由执行前manifest固定。75981d12开发入口只允许原19哈希，不能改名／改schema绕过。任一核心／科学关系／目标权重需要改变，本次固定方法的确认回review，另立继承版本，不能静默替换。

I/D/P每条件一次、各自同冻结初态和外生计划；故障后只有原保护和已批准退出。实现／隐私／隔离／评分错误停止对应有效比较和后续作业，保留当前原件及未执行后缀。非合规退出失败保留真实后果；缺失完整评分为null。恢复未发生但轨迹完整时仍计全窗L/U。

结果始终保留35个槽位（包括未准备、未资格、不可构造、未执行和失败）；只有实际执行、完整、合规行可给有效缺额符号。没有全部适用义务就不能宣布完整命题得到支持。揭盲后修核心／条件／分析时必须保留污染和原失败，旧集不能再次称未见确认。
