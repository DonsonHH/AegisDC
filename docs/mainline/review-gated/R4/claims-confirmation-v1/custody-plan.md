# 独立保管、封存与揭盲准备方案

**PLAN_ONLY_NOT_PROVISIONED**。本轮未生成或读取确认条件、种子、nonce、密钥、明文清单或结果。以下为用户指定安排后才可执行的程序，不是权限已实现的证明。

## 1. 角色和独立性

| 角色 | 职责／可见内容 | 约束 |
|---|---|---|
| U 用户／批准人 | 批准覆盖、N35、预算、版本、人员及揭盲时点 | 接受方案不等于授权执行或全部确认完成 |
| C 独立保管人 | 按固定规则准备候选、静态校验／去重、选择承诺；持有明文输入、种子与解密钥匙 | 应为未参与本批策略调优／结果挑选的真实人员或机构流程；不能按试跑收益选样，不能以改名的开发代理充当C |
| E 受控执行者 | 获明确授权后读取锁定代码／输入，执行一次并留存完整日志 | 无权改方法、输入或清单，不提前向开发方传参数／结果／私有错误含义 |
| A 开发／分析方 | 揭盲前仅见方案、冻结源码、N／上限、公开承诺及资格状态；揭盲后执行固定分析 | 不持有可读确认明文／结果的凭据、种子或私钥，不通过管理员权限绕过隔离 |
| V 独立核验者 | 核对选样、去重、资格、访问、承诺和完整揭盲；必要时经授权看输入 | 不参与模型调优，不向A泄漏可择优的信息；发现问题先报U/C |

最低要求C≠A；资源有限时C/E可同一独立人员承担，但必须披露兼任，推荐V另有人。C可以知晓公开开发结果；独立性不是假称不可能推测结果，而是先冻结非结果规则、禁止收益筛样、真实权限分离和过程审计。更换子代理或目录本身不构成独立性。

若用户只能让开发者本人保管，或A仍持有读取全部确认内容的凭据，只能标“预注册但非独立保管”，不能满足本方案独立确认门。需用户改派安排或明确接受降级的新方案，不自动更名过关。

## 2. 推荐部署及访问矩阵

推荐独立机构研究账号／项目空间或外部保管机器，输入与结果不放在A的renly凭据可读目录。同一账号下新建文件夹、chmod、同账号子代理仍受所有者访问权控制，不能当隔离。本轮不登录设置账号、ACL、封存目录或密钥。

|---|---|---|---|---|
| 覆盖规则、核心／分析版本、N、预算 | 读 | 读 | 读 | 读 |
| 候选、最终输入、拒绝理由／去重表 | 准备期写，冻结后只读 | 只读最终包 | 授权只读 | 禁止 |

管理员必须用A实际凭据验证输入、结果、日志、父目录、共享组、备份、对象链接和调度stdout不可读；用E凭据验证只读输入及追加输出。记录访问测试预期／实际而不存密钥。核验失败即保管门未成立。本方案不假设现服务器已满足，也不授权本轮部署。

## 3. 可执行交接流程

1. **批准范围。** U指定C/E/V及存储边界，冻结覆盖、候选域、N35、分析、H20与核心1c0b0c47。确认薄入口须另获有限资格；不能改名复用仅接受19开发哈希的75981d12。C/V拿到公开开发／工程去重资料，A不拿到未来候选。
2. **先承诺、后无结果选样。** C私下生成选择种子并先留承诺，按确认设计的静态筛选和确定排序取候选；不能调用模型／策略／评分。每槽记录主义务、共同背景、序位、排除理由、去重和依赖。不可构造时回review，不试跑填空。
3. **先满足资格。** V核对拟用关系／接口支持。缺口用另立公开工程见证和预算补齐，不能把封存候选交开发方调试。不得不披露确认明文时记INPUT_EXPOSED并在未执行前回review重订，不静默换样。
4. **锁定清单。** C输出完整输入、顺序、I/D/P规则、公共／私有字段分类、槽位映射、去重审计、预算和停止规则；逐文件SHA-256。根manifest绑定协议／核心Git blob与SHA、确认入口、解释器／依赖、105处理／2100策略上限、执行目录和失败策略。输入与代码只读，输出独立追加。
5. **公开承诺而不泄漏。** 低熵条件的裸哈希不是保密措施。C私下生成256位随机nonce，以SHA-256(nonce || canonical根manifest)作根承诺，公开签名／时间记录、N、覆盖数量和资源上限；nonce、详细清单、映射留私有，揭盲后提供nonce及原字节验算。承诺只证明绑定，不证明无结果筛选，后者依赖C/V审计。本轮不生成nonce或清单。
6. **执行前review。** U/V审查完整槽位、N、总预算、去重、资格、权限、源码输入身份及无试跑证据，并另发明确执行授权。A只见是否满足门及公开承诺，不获具体向量或预期赢家。此门尚未达到。
7. **一次执行。** E按冻结顺序每条件I/D/P一次，保留逐条件启动、输入、全部调用／阶段／评分依据／原始日志、进度、失败及未执行后缀。合法拒绝／非合规／未恢复不删；实现错误停止后续，无自动加预算／重试／换样。
8. **先封结果再揭盲。** C/V确认所有作业终态，锁定全部结果／日志哈希及35行分母（含未执行），记录失败和污染；U再批准一次性揭盲。不能先报告“结果不错”后决定是否交付。
9. **完整交付。** 提供原manifest、nonce、选样审计、逐文件原件／哈希、代码环境命令预算、权限验证和全部尝试。A验算后只做固定分析，报告实际覆盖是否到达、有效性与主／背景差异。缺失或覆盖未达不能算完整确认成功。

## 4. 污染与异常

- A提前获具体向量：记INPUT_EXPOSED，不能继续称该输入未见，暂停相应准备／执行并review。公开槽位谓词不等同于已读具体封存向量或收益，但其可推导性仍披露。
- 按输出修改条件／方法／分析／阈值：记OUTCOME_CONTAMINATED；原件保留，新版本要新确认计划，不能复用旧集自称未见。
- 工具／传输失败：先核对同一作业终态，优先恢复同一原件；读不到输出不授权重跑。
- 实现修复需要改核心：固定方法确认停止并回review。工程修复与研究尝试分账，旧失败不删。
- 部分揭盲或阶段未达：保留全部槽和未执行行，报告覆盖不足；不能从备用池挑有利替代。替换必须在看输出前已有明确规则及授权，否则另审。
- 权限／密钥泄漏：停止访问并记录可见范围，由U/V决定失效范围；本轮方案不授权实际运维动作。

## 5. 用户最终决定

需用户明确C/E/V真实人员或组织账号、管理员、哪台机器／权限边界、nonce及钥匙由谁持有、谁批准揭盲；决定N35／覆盖／预算和最小资格依赖是否接受、是否另行授权准备。当前开发代理不会默认自己或同凭据代理为独立保管人。角色未指定、权限未核实、完整清单未冻结或执行未授权，确认门保持关闭。
