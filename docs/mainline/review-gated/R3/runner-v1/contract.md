# 三处理运行器：有限工程资格契约 v1

2026-11-15。用户接受f10ec626／565f3710的有限修复及I/D/P、19开发条件作为本包依据；原件保留。本文先固定新运行器、独立工程输入／预期和覆盖，再实现执行。工程资格与研究执行分账，不批量运行19开发条件或确认结果。

## 1. 处理、公共时钟与合法停止

每个工程条件仅包含一个共同的完整E14配置。私有评价端先构造I/D/P三个独立E14Run；每组初态、预算、权限、外生计划及保护相同，实例、配置字典、队列、观察、请求、回执和轨迹独立。条件ID、标签、完整配置及其他组输出不传给策略。

策略函数仅接收`(treatment, public_view_v2)`。I使用已接受的B1规则（M0等价不另设研究臂），D按同一公共许可、完整修订链和复核规则选择DIRECT，P不发人工请求。D先复用公共停止／等待／复核和已知无需处置状态；仅初次修订选择改为合法DIRECT，不作诊断性读取。缺已知权限或资源则INFEASIBLE；必要公共条件未知则INSUFFICIENT_INFORMATION。P停止人工策略后原保护继续运行。

I与D在准备提出FIX时均核对完整链的propose/read/verify权限、兼容性、预算和窗口，D另需direct许可；这不提前要求READ已经知道K或未来审批结果，也不改变设施对人工DIRECT前缀的原有阶段接口。初始I仍只按本次读取前置取得证据；能否申请修订在该阶段单独判断。

本包采用事前公开的1秒策略时钟，t0=0、H=20；允许行动的公开配方、预约、窗口端点为整秒。19开发条件的这些参数全部满足，因此本包见证不因时钟引入额外行动等待。设施内部仍用原精确有理事件规则，私有事件可处于分数秒；运行器从不把下一私有事件时刻给策略，也不以私有事件唤醒策略。分数秒公开资料到达的即时响应不在本版资格主张内。

每个公共时钟点，私有运行器先推进设施，再取得实际v2视图；只有`pre_open=true`且尚未停止才调用策略。PRE关闭／窗口末／H由运行器记录环境停止，不再调用策略作新的决定。每次最多发一个实际请求；WAIT只等待下一个固定公共时钟点。策略停止后仍推进设施至H，保留自动保护、恢复和安全退出，不产生RESP策略。

I每类POS/VOLT/CONFIG至多一次、FIX一次、VERIFY一次，总请求上限5；D至多FIX与VERIFY各一次，上限2；P上限0。公开拒绝、资料不足、不可行、已知失败或目标验证完成都终止该策略，不重试、不改选其他修订。合法停止与实现异常分开：非法请求／父身份、超次数、未知决定或输入版本错误属于工程错误，保留全部记录，不包装为正常失败。

请求由策略决定及当次公共材料构造。EVIDENCE请求引用实际到时证据ID；VERIFY父execution_id／target_config_epoch取自本组已到达成功执行回执。禁止注入预写成功动作串、私有profile、未来故障时间或另一组记录。默认策略入口严格v2，不使用legacy适配。

## 2. 私有记录、统一评分与成本

每组保存初态视图、全部策略实参／决定、请求负载／回复、停止原因与观察到的停止时刻、最终私有审计、实际阶段及调用计数。所有返回立即脱离引用。为统一评价实际工时，只给原E14私有功率分段追加`work_action/work_stage`：对应实际占用动作与阶段；不改变物理、事件、准入、公共视图或原预期。

统一评分函数与策略分离，在三个策略过程结束后调用，只消费私有评价包，不回流策略。它独立从常值分段积分L/U、负荷电量和UPS交付，核对模型汇总、能量非负、服务上下界及预算账；完整[0,H)轨迹缺失时L/U必须为null并标INCOMPLETE_TRACE，不能把部分积分当完整结果。

成本：实际人员秒／工具秒（占用分段积分，含安全退出）；按动作和阶段分解；实际开始前的资源排队时间；审批决定等待；未开工请求到公开停止的观察等待；工作流观察到的停止时刻；请求、策略调用、模型入口次数。FIX的资源排队从实际获批到开工计，审批等待另列；其他读取从提出到实际开工计。未开工的观察等待可能包含审批和发布等待，不能与审批项机械相加。上述时间分解与人员实耗也不得相加为货币。真实算法CPU代价不假定为零，独立记录计算用量，不据合成时钟声称实时性能。

已提出FIX但未形成实际审批决定时，approval_wait_seconds=null表示没有该决定事件；未开工到观察停止的等待仍完整记录。没有提出FIX时该项为0。不能凭审批计划补造决定时刻，也不把null解释为免费等待。

硬约束分别标记：完整轨迹、模型／评分一致性、能量与服务界、预算、与公开外部预约的实际占用冲突、resource_overrun、请求／次数／公共边界错误、组间隔离。退出失败导致预约超额是预期非合规分支：保留完整损失与成本，不把它标为正常成功。数据完整性、全设施电气细节不在此模型中，不能宣称已验证。

## 4. 隔离与预算

三个模型同时持有至本条件结束，独立性检查包括模型／状态／配置／权限／队列／请求／观察／回执／分段对象身份、共同输入未修改、运行任一组时其他组私有快照不变、初始公共视图相同。E13验证执行顺序不改变语义输出；E01/E03在首次位置结果到达前比较I公共历史，并比较D与P对应公共轨迹。所有条件标签仅在私有检查索引中出现。

每组最多20个策略调用时钟点、I/D/P请求上限5/2/0；完整评价窗始终H=20。工程包16个三处理条件加2个评分接口，共18单位、48个完整处理运行，固定输入前无本包模型调用。参数／科学关系／预期需实质改变时停止对应部分交审，原失败保留。

Slurm每批1CPU、1GB、5分钟，优先cu；cu满载时允许在可用4gpu分区仅申请CPU、不申请GPU，记录实际资源。独立输入编制、红／绿执行和保存结果核对分目录。模型只增加私有分段标签，因此复跑受影响E14的105／15及C4/C7的30／6原包；旧97模型未改，不重跑。工程执行不计研究样本。
