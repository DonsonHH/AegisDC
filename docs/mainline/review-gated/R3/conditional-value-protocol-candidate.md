# R3协议候选：核查与合法直接修订的条件价值

2026-11-15，**CANDIDATE_FOR_REVIEW_NOT_NUMERIC_PROTOCOL_FREEZE**。用户已接受854379d7的105主单位／15回归所支持的有限E1–E4资格，并授权C4/C7修复和有限接口验证。本文件是同轮协议候选，不授权收益实验，不恢复M0优于B1的比较。旧334e537b提案保留原文；本候选承接用户明确的研究方向调整。

## 1. 问题、处理与估计对象

研究问题：同一个伦敦式合成PRE实例，在相同外生状态、保护、权限、资源与需求下，先取得证据再决定是否修订，相对合法直接修订，在哪些预先声明条件下减少或增加服务缺额、资源占用和等待？既有保护作为背景参照。真实Google事故可避免性、年度风险、跨站普适效果均不由本候选识别。

| 处理 | 冻结时须采用的规则 | 合法终止与限制 |
|---|---|---|
| I：证据核查 | 复用本组合法到时记录；按POS→VOLT→CONFIG短路取得仍有辨别力且公开可准入的证据；R假停止，R真且完整FIX链可提出时申请同一EVIDENCE修订；成功实施后按自身VERIFY计划复核 | 资料不足、公开不可行、审批拒绝、未实施、复核失败／无结论／过晚均保留；每类初始读取一次、FIX一次、VERIFY一次，无重试。M0与B1是该同一规则的两个一致性标签，正式比较只保留一个处理 |
| D：合法直接修订 | 初态公共目录与兼容性、direct/propose权限均允许时，直接申请同一DIRECT FIX；先筛完整公开资源／窗口链；审批、准备、提交、退出和复核与I相同 | 不主动做诊断性POS/VOLT/CONFIG读取；不跳过保护／审批／VERIFY。直接权限或必要参数缺失时输出对应公开不可行／资料不足并保留背景保护。既有合法公共证据若已使目标无需修订，不得故意忽略以制造弱对照；当前运行域初始观察为空，此扩展分支尚未纳入拟执行域 |
| P：既有保护 | 无新增人工核查／修订，保留同样的本地自动控制、后备、UPS和设备保护 | 不删除故障、需求或保护，不作唯一优越性对手；记录同一完整窗口后果 |

未来在每个外生条件ω上，三组独立构造同初态实例，各自取得内生观察、审批回执及资源轨迹；不得复制另一组买到的资料，也不把I初态设为修订配置。主对比拟为`ΔL(ω)=L_D(ω)−L_I(ω)`，正值仅表示该条件下核查减少服务缺额；同时报告`ΔC=C_I−C_D`的成本向量。P用于解释背景后果，不能替代I对D的主对比。未运行、未估计任何Δ。

## 2. 共同条件与分层

同一ω的三组共享：初始源／连接／容量／配置、固定外生故障和恢复、G与保护、D(t)、t0/H、公开作业窗口、可信角色和目录、人员／工具、预算、外部预约，以及按动作语义固定的审批／观察／提交／退出计划。审批与动作的实际到时结果由各组执行过程产生；共享计划不等于强行共享实际反馈或完成时刻。

初始公共观察固定为空；允许取得的信号、版本和时标规则相同。直接修订资格按**处理前公开条件**划层：direct/propose允许、兼容性已知且目录可用为主要三处理层；缺权限／公开不可行条件另层报告，不在事后按获批或成功者筛样。若引入共同初始文档，必须先补真实运行入口及身份／冲突资格，不能直接把D静态材料当作已经实现的初态资料包。

公开可分层量：ONLINE/LOAD_ISOLATED作业方式、预算、公开窗口、预约和配方。私有但处理前固定的机制量（真实连接／配置、故障时刻、G就绪等）可作预注册机制条件描述，不能让决策者据此选择行动；这类分层不是部署时已知的选择规则。观察成功、审批结果、实际提交、是否恢复等内生结果均不得用来删除样本或定义获益人群。

## 5. 服务缺额、成本与硬约束

主指标仍为`L=∫[0,H) u(t)dt`，D=0时u=0，否则u=(D−S)/D；U=∫(D−S)另报。包含PRE准备隔离、故障、启动和恢复，不只从故障时开始计损失。三组D、H相同；不能把主动停机期间需求删掉。完整窗未恢复时，L/U仍完整计算；恢复时长右删失单独记录。轨迹本身不完整则标INCOMPLETE_TRACE，保留失败，不能填零或排除。

成本报告向量：人员实耗秒、工具实耗秒、预约预留与超额、等待秒、审批等待、动作数、复核状态，以及实际计算资源。人员／工具同用时是本单实例设定，不随意相加成货币；未知费用不填零。`ΔC`与`ΔL`并列，避免通过任意权重宣布核查有价值。若服务损失相同，成本差异作为条件结果报告；若服务与成本相反，报告权衡，不擅自生成综合分数。

硬约束：可信权限及版本、固定维护隔离／本地联锁、资源不得冲突分配、能量不透支、设备保护不绕过。安全退出失败导致的预约超额明确记为违反预约约束并保留全部损失，不能据其暂时服务更好宣布成功。只建模当前声明的供电保护与聚合服务；**没有数据完整性机制资格，不能声称数据完整性已得到验证**。

## 6. 开发、确认及停止规则

开发阶段只使用已披露材料和候选清单，先固定三处理适配规则及全部状态／成本分母。确认条件由独立准备流程在规则固定后生成／封存；确认输入清单、版本、预算、样本单位、失败与重试规则和主要统计量须先交审，再获执行授权。确认反馈不回流挑选规则、条件或最佳版本。单一机制的参数变体、密集时间步、重复重放、自检与接口回归都不是独立真实事故样本。

目前不登记确认样本量、总体置信区间、Δ_min或确认分布已冻结。确定条件网格若无抽样总体，只报告条件差异与范围，不提供伪总体显著性。实用收益阈值需结合研究目的和代价含义另行确定，不能用“严格大于0”自动替代实际意义。

停止／否定规则：私有信息进入方法，评价或外生条件被处理改写，时间／预算／能量关系不成立，确认信息泄入开发，或需要未接受动作／关系时停止对应部分并保留原件；若接口错误可在既定预期下修复，失败和修订分开记录。条件结果可以是核查有利、相同、被直接修订支配、公开不可行或效果未识别，不预设正收益，不看完结果再换主比较。
