## 执行接口与固定方式

新增标准库模块 `aegis_dc.london_pre`。`PhysicalWorld` 提供私有场景装载和机制审计；`PRESession` 提供可信上下文下的公开请求／视图、事件推进和私有材料审计；`ChallengeRun` 在同一状态实例连续推进 e0–e4、f、u、j_before、j_at，保留不可变冻结快照。公开视图不含私有状态；检查器作为评估者可以读取私有审计结果，但该审计不交给决策者。

检查器 `scripts/qualify_london_pre.py` 只执行冻结文件中的操作并比较固定字面预期／明确的同轨迹身份不变量；不导入模型内部函数、不利用实际输出补写答案。`scripts/freeze_london_pre_cases.py` 是输入展开工具：来自 v2 的字面表、记录模板和事件序列，禁止导入模型。在运行模型之前，先在 Slurm 展开并固定完整 JSON 输入／预期、来源映射及 SHA，提交冻结数据；原始展开工具及生成回执保留。

JSON 物理逻辑值使用整数0/1，事件和模式使用规格枚举；公开记录结构的实现编码在冻结 JSON 中明确。新增字段仅为原规格要求的记录、事件及审计编码，不增加物理关系、动作或条件。

- 一条执行单位是一份完整构造输入和顺序操作清单，具有唯一ID。连续生命周期在一个单位中推进，不把 I01–I05 或 I13–I17 的五个观察点冒称五次核查。配对世界各为一个单位，另有明确的跨单位公开相等要求。

- 所有计算在远端 Slurm；本机仅编辑、SSH、传输及文件完整性核对。使用既有解释器，不修改共享环境。
- 每次执行使用唯一目录，保存尝试元数据、输入／预期、逐步实际结果、异常及终态。先核实终态才决定修复或重跑；实现修复保留旧失败，新版本重跑受影响检查。完整通过后再从发布的新检出核对交付与固定源码。
