## 1. 声明用途与范围

拟资格用途：检验一个**受限合成模型**是否能区分上游有电、实际供电路径可用、控制器判断、启动请求、物理接管，以及事前核查者实际掌握的证据。它为后续伦敦式维护状态备用链核查提供实验载体，不是 Google 现场复刻。

唯一决策阶段为 PRE：维护状态下的事前核查。未来获授权的模型资格可在冻结 PRE 状态之后施加离线外生挑战，检查物理／控制机制；挑战期间不加入新调度、人工抢修或事中决策循环。这是模型检查刺激，不是扩展 RESP 方法。

不纳入本契约：荷兰、冷却、跨站迁移、事中响应策略、现场设备操作、真实 PLC 全程序、分钟级 UPS 轨迹、云服务恢复、服务损失积分、方法排名、收益验证与 RSI。旧八域模型只可作为待审实现资产，不自动继承其资格。

## 3. 最小模型与信息接口

| 层 | 输入／输出的责任 | 不变量 |
|---|---|---|
| 私有场景与设施 | 实际连通、源状态、设备就绪、控制版本、固定外生挑战、物理执行结果 | 不由策略或改进器改写；缺关键建模字段时在离线构造阶段拒绝，错误详情不进入决策材料 |
| 观察与文件发布 | 根据来源、版本、获取权限和事件顺序形成记录 | 实际状态不直接序列化给决策者；缺测、未知、已证伪和明确不可用分开 |
| PRE 决策接口 | 仅接收已到达记录、已声明静态知识、角色权限及公开资源状态；输出核查／升级请求 | 不接收事后复盘、隐藏缺陷标签、未发布配置或未来挑战时刻 |
| 公共请求检查 | 校验语法、公开角色权限、公开预算及显式前置记录 | 不以私有缺陷或隐藏成功概率提前过滤候选、排序动作或提供解释 |
| 执行与既有保护 | 按真实条件决定请求能否实际执行；保护及联锁可读取其本地真实状态 | 保持真实拒绝或失败，不为信息隔离而禁用保护；向决策者发布什么、何时发布另受观察契约约束 |
| 私有独立评价 | 对照声明的状态关系、轨迹与接口边界判定模型资格 | 可见私有真值，结果只用于离线资格审查，不作为 PRE 实时提示 |

每个公开记录必须有对象、值／状态、来源组、观察或文件版本时点、可用时点、接收角色及获取动作引用。事件排序是本模型的合成顺序，不冒充现场时间戳。

**拒绝与失败反馈也是信息渠道。** 未经资料授权不得返回“PLC 配置有缺陷”“后备不可用”等私有原因。实际保护可以拒绝操作，但可公开的结果粒度、延迟及获取代价必须事先声明；在结果尚未合法到达前，不通过异常文本、字段缺失、可选动作列表、路径名或返回时序透露真值。不得用一个读取真值的可行性检查器免费替代核查。

已批准的核查完成、观察模型产生确定结果、通道有效且记录合法到达后，接口必须按声明的发布规则正确提供该结果，不得永久返回未知。对契约声明能够观察的真实差异，合法到达后必须体现相应差异；不同组的主动核查结果不强行相同、不相互复制。未取得核查结果时，两个公开历史相同的场景必须给出同样的公开请求检查结果与可选请求范围。被拒绝、确实无结论、通道失效或记录按声明规则失效的分支仍分别保留，不要求所有核查成功或所有私有差异公开。

## 4. 独立检查清单（仅预先定义，全部未执行）

检查的具体关系表、取值域、排除条件及独立预期必须在查看待验模型输出之前固定并记录版本身份，不得根据实现输出反向选择标准答案。预期由规格表／独立推导确定，不能导入模型内部函数作为“标准答案”。可以共享输入格式，不能共享待验证的判断实现。实现者须提交模型与独立检查来源，审查者核对两者是否独立；复用同一布尔表达式的两次计算不构成独立检查。若后续需修订预期，须保留原版、结果和修改理由，返回 review，不覆盖失败。

| ID | 预先规定的条件 | 独立预期／验收依据 |
|---|---|---|
| Q01 正常供给 | 声明的普通供电路径具备源、连接和支撑条件 | 普通供给状态成立；不把无发电机启动命令单独判为故障。依据独立路径枚举表。 |
| Q02 维护隔离 | 一条路径被明确隔离，其上游仍有电 | 不能仅凭其上游电压判定这条路径可向负荷供电；其他显式路径仍逐条检查，不从一个开关打开推出全场失电。 |
| Q03 报道机制见证 | 已声明的维护隔离／感知错位组合，在冻结 PRE 后施加固定外生挑战 | 合成的电压判断关系可以保留“有源”的判断，而实际普通路径无支撑，启动请求受该关系抑制。只核对声明关系，不据此声称现场时间重放。 |
| Q04 非缺陷对照与接管配对见证 | 普通路径无法支撑；本后备路径全部声明的充分条件满足且无执行故障；再分别移除其中的必要条件 | 正例在声明的接管完成判定点必须实际接管；负例按对应机制不接管。不能只让启动请求变化而让实际接管恒为假，也不把更换控制逻辑单独视为充分条件。细则见下文。 |
| Q05 后备真实不可用 | 启动请求成立，但设备就绪或连接条件明确不满足 | 请求可以存在而实际接管不成立；不得自动修复或把请求当成功。 |
| Q06 信息不足 | 实际世界已定义，但某些关键记录未获准提供、未到达或已陈旧 | 决策视图保持未知／不可用信息状态；不借私有评价补齐。设施真值不因决策者未知而改变。 |
| Q07 相关来源 | 同一物理来源的记录被复制，或被两个控制器共同引用 | 来源组保持一致；不会自动增加独立证据数或变成独立防线。 |
| Q08 到达前不可区分与到达后正确发布 | 两个私有状态不同的世界具有相同合法公开历史；另声明能区分该差异的授权核查、确定观察和合法到达 | 到达前公开视图、静态请求检查、动作菜单及错误粒度一致；到达后须正确发布声明结果并呈现可观察差异，排除永久返回 UNKNOWN 的实现。未声明可观察的私有差异仍受保护。细则见下文。 |
| Q09 授权、成本及拒绝 | 无权限、公开资源不足或请求不合契约；另设因真实保护而失败的执行 | 公共拒绝只能依公开条件；真实保护失败不禁用。检查所有公开异常、回执和事件顺序是否泄漏私有原因；每次取得信息均登记访问／占用，不以未知代价记作免费。 |
| Q10 控制与真值隔离 | 修改、删除或换序发布材料；尝试在请求中携带私有字段 | 不直接改变物理状态、控制版本或固定挑战；越界字段拒绝。观察变化只影响可见材料，获准的实际动作才可按已声明接口改变状态。 |
| Q11 非成功闭环 | 核查无结论、申请被拒、修订未实施或复核未通过 | 保留各阶段状态，不自动转为就绪或关闭；不能只构造必定被方法“修好”的案例。 |
| Q12 复现与界外输入 | 同一冻结合成定义重放；缺字段、未知状态值或超出声明拓扑 | 定义内机制结果可复现；界外输入显式拒绝／标为不支持，不静默回退或套用旧 V6 参数。 |

**Q04 强制成功／失败配对。** 正例须显式列出启动请求及其合法接受、许可、设备就绪、连接、负荷支撑等全部声明的充分条件，并声明不存在执行故障；在所声明的接管完成判定点，物理接管必须成立，而非仅出现请求或“准备就绪”。随后针对该后备路径逐一移除已声明为必要的条件，其余条件保持固定，在合法取值域内给出相应不接管见证及独立预期。路径特定的不接管不自动推出其他路径或整个设施均无法供给。通过该检查仅证明模型具有正确的成功与失败分支，不证明核查方法或控制改进产生收益。

**Q08 强制合法发布正例。** 在核查已获授权并完成、观察模型产生确定结果、通道有效且记录已合法到达的条件下，首个处于记录声明有效范围内的适用决策视图必须正确包含结果值／状态、对象、来源组、观察／可用时点、接收角色和获取动作关联。到达前不得提前出现；到达后不得无故吞掉、错绑动作或始终退化为未知。对预先声明能观察的配对差异，两世界在合法结果到达后必须呈现观察模型规定的差异。核查被拒、无结论、通道失败和记录失效分别按其契约处理，不借正例要求泄漏其他私有真值。

Q01–Q12 是模型资格要求，不是已经写好的测试或研究样本。本轮未生成上述配对的具体输入、关系表或检查实现，也未执行任何见证。有限逻辑状态集合若主张完整覆盖，须先列清取值域和排除条件，再证明穷尽；抽查只能支持已覆盖条件。无数值模型时不虚设能量守恒或步长精度“通过”，一旦增加数值动力学就新增相应资格要求。

## 5. 通过与停止规则

未来执行资格检查前，需将每项检查细化为固定输入、独立预期、允许公开输出及覆盖矩阵，保留失败和不支持情况；本轮不生成这些可执行 fixture。

- **通过的含义**：在用户接受的合成范围内，声明的状态／控制关系、信息边界和复现契约均得到对应独立检查支持。每项 Q 检查必须有结果，未执行不得算通过；不适用项须在执行前经过范围审查，不在失败后移除。
- **直接阻止资格通过**：私有真值通过视图、动作过滤或反馈泄漏；越权改变设施／保护；不支持输入静默补值；只保留成功样例；检查答案依赖同一待验实现。
- **需要返回契约 review**：必须新增路径、物理量、现场时标、荷兰、RESP 或未声明动作才能解释结果；公开事实无法满足拟定关系；发现假设改变了所能支持的结论。保留原失败，提出版本修订，不自动扩范围。
- **未获支持的结论**：Google 真实事故可避免性、真实核查者当时的能力、准确处置余量、服务收益、风险概率、方法优于强基线、普通自改进或 RSI 增量。方法对照留给 R3/R4，递归增量留给 R5。

即使 Q01–Q12 将来全部通过，资格也仅限于本契约的定性逻辑与信息接口。进入服务收益比较前，还需另行交审并取得相应资格：建议经授权、准备和实施改变保障状态的链条，有限保障到失电与服务后果的关系，以及时间、资源、成本和独立后果评价。不能凭本组检查通过直接跨到收益比较。
