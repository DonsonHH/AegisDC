# C4／C7公开读取准入修复

2026-11-15。本轮接受854379d7声明的105主单位、15回归及其配对，执行ec133d2e；[接受记录](../e1-e4-execution/acceptance-20261115.json)是追加记录，原件不改。C7配方混用与C4日程筛选遗漏登记为已知实现缺陷；不撤销旧有限见证，也不赋予完整参数域／Q11／R2资格。

## 1. 修复规则及版本

运行实例的公开视图新增`view_schema=aegisdc-e14-public-v2`。context.acquisition_plans对READ_POS、READ_VOLT、READ_CONFIG及VERIFY_CTRL分别给出：work、exit_reserve、reserve、earliest_start、work_complete、available_at、reserved_until、admissible、reason。

普通READ使用read_work，VERIFY使用verify_work；reserve=本动作work+exit_work。计划只读当前公开时刻、可信动作权限、可用预算、公开预约、公开窗口和动作配方；不读tF/tR、私有审批／执行／观察计划、family、路径、设备真值或预期收益。既有`read_reserve`保留；另给`verify_reserve`供明确兼容和解释。

顺序为：权限不允许→ACCESS_DENIED；预算不足→BUDGET_UNAVAILABLE；按公开预约求最早资源段，找不到结束不晚于窗口末的完整预留段→NOT_STARTED_RESOURCE；否则ADMITTED。允许排到将来，不能仅因资源当前忙就判不可行。所算结束为半开预约段右端，`reserved_until <= window_end`允许；原工作完成、发布和故障截断语义保持。

这些是阶段前置已满足后的资源准入计划，不代替身份、已有pending请求、次数、父执行关联或PRE截止检查。C4只从仍有辨别力且未尝试的动作中选admissible计划；无合法补证路径时INSUFFICIENT_INFORMATION。C7在有效执行回执及安全退出之后，用VERIFY计划；无法准入时保留未核验状态。request在同一时点复用相同计算，方法不得提交自报计划覆盖可信上下文。

发布时刻另列，不能把资源段可排入窗口解释为必能赶上隐藏故障或保证获得有效观察；已采样但晚到的记录仍按已接受E1规则只留历史。本轮正向窗口见证的发布延迟不晚于退出预留，未新增“所有合法排队都保证收益”的主张。

兼容：缺view_schema的旧冻结D/G静态输入继续按legacy-static-v1解释，只保留原抽象输入的回放语义，不将它认证成真实日程适配器。真实E14Run始终输出v2；未知schema或v2缺少完整动作计划须显式拒绝，不能静默降级。原105／15输入及旧结果保持字节不变，新的复跑单独留存。
