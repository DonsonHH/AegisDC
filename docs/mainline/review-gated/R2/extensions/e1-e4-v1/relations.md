2026-11-15，**待 review，未实现／未执行**。参数单位、C0默认点及证据分类见[契约](README.md)。本文固定的是推荐的合成规格，不是现场测量；下面每项均有[预期和覆盖](expectations.md)。

## A. M0 与 B1 的精确共同部分和 D3

共同固定信息谓词为 `R=(cB=0)∧(vB=1)∧(K=LEGACY_LINE)`。只使用已合法到达、尚有效、与 q-1／ctrl-1／维护版本匹配的记录。任一有效条件为假，R为假；全部为真，R为真；其余为UNKNOWN。冲突不投票、不猜值，同源副本只作一个来源。K来自合法 READ_CONFIG，不可读评估器或旧T初态。

M0/B1共享以下完整顺序：

| 次序 | 公开条件 | 共同输出 |
|---|---|---|
| C1 | 已达故障截断／H／公开窗口结束，或FIX流程已有终态失败且本实例不重试 | STOP，保留终态／剩余义务与已发生后果；单次初始READ无结论不自动视作整个问题终态 |
| C2 | 有未结束请求、审批、作业或待发布记录 | WAIT_PENDING，不重复请求 |
| C3 | q-1 的目标复核有效通过，或R为假 | NO_ACTION_CURRENT_SCOPE；不声称其他保障或服务必定正常 |
| C4 | R为UNKNOWN | 在未尝试且仍可能改变R判断的字段中，按POS→VOLT→CONFIG选首个公开准入条件齐全且可行的读取；本次读取只需自身角色、目标、预算、资源和工作窗。已尝试无结论或明确不能读取的字段不重试，可继续其他仍有辨别力的字段；没有这样的合法补证路径时为INSUFFICIENT_INFORMATION，记录权限／预算／未知参数等原因，不推断整个修订链必定不可行 |
| C5 | R为真 | 对同一FIX_CTRL链做公开可提出性筛查；通过则PROPOSE_FIX，否则已知不满足为INFEASIBLE、未知为INSUFFICIENT_INFORMATION |
| C6 | 获批且排到资源 | 既有FIX_CTRL自动进入同一获准链，方法保持WAIT_PENDING，不另发阶段动作；实际提交仍由执行器和本地联锁决定 |
| C7 | EXECUTED_UNVERIFIED 的合法回执已到达，且安全退出已完成、公开资源释放 | 仅请求绑定该执行／版本的VERIFY_CTRL；两条件未同时满足则WAIT_PENDING。若窗口、角色或预算不允许，保留未核验状态 |

C7是链内下一步，在实施回执和退出／资源释放信息均已可用后执行，优先于重新评估旧R；C0在5收到实施回执、6退出，故5仍等待，6才可请求复核。C6的受控执行器由实际到达的内部签署授权触发，方法本身不越过C2。初始三类READ每类至多一次、申请一次、复核一次；不在记录过期后无限重读。READ的前置不要求预知R、K、未来审批或最终服务收益，否则会把合法补证路径锁死。

本包不使用未定的通用排序器：初始READ固定上述顺序，修订目录只有一个FIX_CTRL，复核也只有一个绑定父执行的VERIFY_CTRL。请求准入先查封闭字段／目标身份，再查可信权限、该阶段必要材料、次数／预算、已知配方与公开窗口；不能要求随后才能获得的值来准入当前读取。FIX申请筛查完整计划的准备—提交—退出—复核发布是否可在公开窗口内完成；审批后若实际授权到期早于计划提交点，则拒绝开工，不靠方法提前知道尚未公布的批准内容。预估只用公开资源预约和配方，不读取tF。

**唯一候选差异**：M0在C5发出命令前执行D3证书识别；B1不做D3识别，直接用C5。为保持本包最小并诚实面对证据缺口，D3仅认可信任目录中的 `PLAN_IDENTITY`，条件为：R已公开证实、C5可提出性通过、证书版本／目标／条件域有效、直接方案与B1即将选择的方案具有相同动作ID、参数、授权流程、资源配方、退出及复核规则。M0可将理由记为D3，但发出的执行请求与B1完全相同。证书不授予额外权限，不跳过审批、准备或复核。

目录证书由冻结规格审查者预先登记，不由方法生成。证明来源为共同执行计划在同一输入／外生计划上的结构恒等：各审批、失败、退出、观察分支逐项相同，故完成／占用／服务后果差值的上下界均为0。这是恒等关系，不是用私有状态计算出的服务预测。各链绝对时长来自公开配方，绝对服务缺额只知`[0,H]`，不能靠这个粗上界触发非恒等支配。

`NONE`、未知／过期／目标不符证书、仅“直接链最坏上界小于核查链最坏上界”的材料，以及任何 `NONIDENTITY_BOUNDS` 均为D3_NOT_PROVEN。风险未知时不触发D3，继续共同C4；R为假时已由C3停止。今后非恒等支配需要另行资格和版本，不在本包添加。

| 静态见证 D | 公开输入 | M0／B1固定决定 |
|---|---|---|
| D01 | R假，其他必要性无冲突 | 都NO_ACTION，D3不进入 |
| D02 | R未知，POS缺失且读取准入成立，无证书 | 都READ_POS；不能把未知私有配置当缺陷 |
| D03 | R真，链可提出，合法PLAN_IDENTITY | M0理由D3、B1理由C5；两者相同PROPOSE_FIX负载及后续流程 |
| D04 | R真、链可提出，但证书缺失／失效（分别） | M0不触发D3，回到C5；两者仍同一PROPOSE_FIX |
| D05 | R未知，提交两个最坏上界或NONIDENTITY_BOUNDS | D3_NOT_PROVEN；两者按C4读取，不据此直接修订 |
| D06 | R真，窗口仍开放但容不下完整链或预算明确不足；另列窗口已结束 | 前者都INFEASIBLE；后者按C1 STOP。证书不能覆盖权限／资源限制 |
| D07 | 必要参数未知或记录冲突且没有剩余合法补证 | 都INSUFFICIENT_INFORMATION |
| D08 | 已知提交失败／审批拒绝／复核失败 | 都保留未解决终态，不自动重试或关闭 |
| D09 | POS已尝试但无结论，VOLT=1，CONFIG尚未读且可准入 | 两者都READ_CONFIG；不得要求本次读取前先知道K，亦不无限重试POS |

因此在上述闭合输入域内，M0/B1的执行动作序列相同；D3审计理由不算收益。方法计算耗时目前未建模，不能将执行计划恒等扩写成真实CPU成本相等。当前不支持非零的M0相对B1方法增量；不改变主比较或削弱B1来制造差异。

## B. E1：顺序观察、身份与有效性

固定身份：`problem_id=q-1,target=ctrl-1,maintenance_epoch=m0`。物理B通路目标为feeder-B。只读动作枚举 READ_POS、READ_VOLT、READ_CONFIG、VERIFY_CTRL；写动作只有FIX_CTRL。旧v2的数据不自动转换成新增记录。

可信公开上下文包括角色权限、签署目录、工作窗、预算和资源预约；方法不能自报角色或余额。公开字段缺失是资料不足；无权不通过；私有状态不参与公开请求准入。离线场景定义缺关键字段则拒绝构造，不作为给方法的补证工具。

| 请求阶段 | 请求前必须知道 | 可经本次或后续阶段取得，不能预先要求 |
|---|---|---|
| 初始READ | q-1与目标、合法读取角色、动作配方／持续时间、发布延迟、当前公开资源和预算、工作窗 | 值、K、当前配置序号、观察成功与否、风险R、未来审批结果 |
| FIX_CTRL申请 | 合法申请角色、目标修订目录、兼容性、版本适用域、准备／提交／退出／复核配方与预算；EVIDENCE模式需R证据，DIRECT模式需公开direct_allowed | 审批结果、未来撤销、实际执行成败、本地写联锁、复核与服务结果 |
| 准备／提交 | 已到达受控执行器且有效的签署授权、目标和配方、实际资源分配 | 不以方法是否已收到延迟回执代替执行器授权；不能以评估器真值预知成功；本地安全条件由执行器合法检查 |
| VERIFY_CTRL | 已到达的EXECUTED_UNVERIFIED回执、execution_id和目标配置序号、读取权限及剩余资源／窗口 | 实际核验结果、功能探测是否通过；不要求先知道“已修好”才准读取 |

请求ID按本方法已提交的动作顺序单调唯一，重发同ID只返回既有状态、不新增占用；同ID不同负载拒绝。problem_id、目标、动作、请求ID为必需；VERIFY还需父execution_id与目标config_epoch。其他请求不强制已知config_epoch；角色／物理真值／故障标签不得写入负载。

读取获资源后占用工作时长，在完成时刻σ采样。初始READ分别观察B位置接点、B电压接点或当前活动控制配置的限定依赖类型及版本。DEFINITE也须所读通道有效才产生确定值；本地接点MISSING时产生NO_RESULT，不能改读评估器真值。结果在`a=σ+δ`发布，当前适用区间为`[a,σ+TTL)`。INCONCLUSIVE与CHANNEL_FAILED产生NO_RESULT/UNKNOWN，工作／发布时间和占用相同，不提前泄漏私有原因。中止另记ABORTED_READ；不得伪造确定结果。

记录的共同字段固定为：record_kind、record_id、problem_id、target、value/status、source_group、observed_at、available_at、expires_at、maintenance_epoch、receiver_role。`record_kind=ACTION_RESULT`必须关联request_id/action；config_epoch仅配置／复核记录必需，parent_execution_id仅复核记录必需，其余动作这两项为null。`record_kind=DOCUMENT_CLAIM`使用document_id与claim_field，本版claim_field仅为breaker_position，值域为0/1；request_id/action、config_epoch及parent_execution_id为null，不伪造获取请求。两类记录的对象、维护版本、来源、接收者和时标均须完整。POS/VOLT分别使用公共来源组pos-B/volt-B；CONFIG为cfg-local，VERIFY为独立probe-local；副本保留原来源、原时标和copy_of，不新增独立证据或刷新有效期。

共同初始资料可显式包含合成维护文档声明，来源组maint-doc、记录种类DOCUMENT_CLAIM；它不是无误差的本地传感器读数，也不写入设施。若与同目标／适用维护版本的有效POS记录冲突，公开认识标记CONFLICT/UNKNOWN，不按隐藏真实值或多数副本裁决。D07b仅检验这种公开认识规则，不新增获取动作或传感器噪声模型；所有初始资料及其代价归属在各组相同。

配置状态为`(family,config_epoch)`，family∈{LEGACY_LINE,REVISED_LOCAL}、初始epoch=0，实际成功提交后epoch加1；已有REVISED_LOCAL时也执行幂等同目标提交并记录新epoch，不提前泄漏“无需修改”。公开决策只按TTL及**已经公开获知的最新版本**判断材料适用性；不能因尚未公布的私有变更提前撤掉旧记录。配置采样到发布之间有新公开提交回执时，旧epoch配置记录只留历史，不用于当前决策。物理POS/VOLT绑定m0，不因控制配置epoch变化无故失效。

VERIFY以独立读取的活动版本和隔离功能探测为依据，不复制实施回执。探测只向验证通道送入固定的本地信号组合`zVA=0,zVB=1,zCA=1,zCB=0,zSA=zSB=1`，各通道quality=OK、sample_time为复核采样时刻，观察当前控制关系是否请求后备；不将测试信号送入设施闭环。PASS计划还必须满足目标epoch、实际REVISED_LOCAL及探测请求=1才发布VERIFIED_FOR_TARGET；不满足则VERIFY_FAILED。FAIL计划产生负向核验，其他模式产生INCONCLUSIVE；均保留实际配置。通过只说明目标控制条件，不证明G或服务一定可用。

方法每次只维持一个未结束请求。发布、审批回执、资源／权限变化可触发决策；私有完成但回执尚未到达时仍等待。审批决定在申请后τA形成，同一时刻签署授权进入受控执行器的可信账，执行器可据此开工；面向方法的审批回执在决定后δ才到达。提交回执也在实际提交后δ发布。两个接收者与available_at分别登记，同源授权不是两份独立证据。实际状态变化不等方法回执才发生。

公开资源预约／起止通知在其发生时可见，是单独声明的合法渠道；据此可能知道作业已开始，但方法不能读取尚未到达的审批回执、伪造授权或越过WAIT_PENDING。不能宣称所有审批相关信息在δ期间均不可观察。故障截断后即使旧记录晚到，也只存历史，不触发PRE新动作。

## C. E2：单一修订状态机与本地信号

初始控制family可为LEGACY_LINE或REVISED_LOCAL，各方法在同一比较条件中相同。FIX_CTRL只将活动family设为REVISED_LOCAL并增加config_epoch；不改源、断路器、设备就绪、容量、燃料、授权或评价器。配置写入是一次原子提交，部分写入不在本版域内；失败保留原family/epoch。

实现状态采用三个正交维度，避免将“审批拒绝”“配置未实施”和“正在安全退出”混为一个值：`phase∈{NONE,PROPOSED,APPROVED,QUEUED,PREPARING,IMPLEMENTING,EXITING,AWAITING_VERIFY,VERIFYING,TERMINAL}`；`commit_result∈{NOT_ATTEMPTED,SUCCESS,FAIL}`；`verification_result∈{NOT_REQUESTED,PENDING,PASS,FAIL,INCONCLUSIVE,ABORTED}`。审批结果另记PENDING/APPROVE/DENY/CANCELLED。下表的DENIED、NOT_IMPLEMENTED等是回执／终态原因，不覆盖EXITING阶段：未开始作业的拒绝直接TERMINAL；已经开始的未提交失败先EXITING，退出结束后TERMINAL；成功提交先EXITING再AWAITING_VERIFY，若已过故障截断则保留成功提交但以未核验TERMINAL结束。退出未完成则phase保持EXITING至H。私有故障原因与公开回执分开，公开不披露GUARD_BLOCKED等细分真值。

`commit_result`固定映射：原子提交前被拒绝、截断、撤销、过期或写联锁阻止为NOT_ATTEMPTED；实际提交尝试按已声明计划返回失败为FAIL；只有原子成功为SUCCESS。NOT_IMPLEMENTED公共回执可以涵盖前两类，不能据其反推出私有细分原因。

| 状态／转换 | 条件、事件与副作用 | 输出及失败保留 |
|---|---|---|
| NONE→PROPOSED | 公开准入通过；记录申请模式EVIDENCE或DIRECT、目标及证据／目录引用 | 仅请求，不改配置；模式在所有方法均可用，M0/B1按共同规则选EVIDENCE，直接基线可在direct_allowed时选DIRECT |
| PROPOSED→APPROVED/DENIED | τA后，公开角色／目录／有效性仍满足；按跨组共同审批计划决定 | 记录审批，不读取私有缺陷代替诊断。证据型申请以申请时有效材料快照为依据，审批时再核实已公开的版本／撤销信息；TTL自然过期不抹去已提交证明，但明确公开状态变更使审批失效 |
| APPROVED→QUEUED→PREPARING | 授权在有效期内、可预约完整资源区间，按E3分配；进入准备时实施公开目录指定的work_isolation | 等待占用计入延迟，不虚报人员已工作；尚未改变配置 |
| PREPARING→IMPLEMENTING | 准备时长结束且未被截断／撤销 | 仍不改配置；实际写入只在工作结束点 |
| IMPLEMENTING→EXECUTED_UNVERIFIED | 提交完成时严格早于tF、窗口截止、授权到期；授权未撤销；局部写联锁允许；提交计划SUCCESS | 在此时才设REVISED_LOCAL并epoch+1，生成execution_id；不能靠修改初态充当执行 |
| 任一未提交阶段→NOT_IMPLEMENTED | DENY、撤销、窗口结束、故障截断、提交计划FAIL、局部写联锁BLOCK等 | 配置不变；保留原申请／授权、已发生占用与物理影响。已开始现场工作进入SAFE_EXIT；尚未开始的队列／申请直接结束 |
| 已提交→SAFE_EXIT→AWAITING_VERIFY | 提交后仍执行τexit；释放资源，解除本动作自己的负荷隔离 | 故障或授权撤销不能追溯抹去已经完成的提交；执行安全退出不产生新的策略 |
| AWAITING_VERIFY→VERIFYING→目标核验终态 | 对绑定执行和目标epoch的VERIFY获准后按E1采样／发布 | VERIFIED_FOR_TARGET、VERIFY_FAILED或INCONCLUSIVE。故障前未能完成／到达则保持未核验；配置不会因复核失败自动回滚 |

每个实例一次申请与实施机会，无自动重试。SAFE_EXIT是固定、预先授权的动作尾段，在失败／故障／撤销后也执行。若资格场景明确声明退出路径失败，则隔离与占用保持到H，标记EXIT_INCOMPLETE；不能释放成“免费恢复”。本版没有第二套回滚／修复动作。

局部写联锁是设施维护／服务模式接点 `z_write_allow`，由共同设施的本地保护提供，不由方法设置；每次提交判定前，在当时外生／撤销事件处理之后，执行器从该接点采样当前ALLOW/BLOCK。不可用或过期按BLOCK，不调用全局评估器推断；这次局部采样先于写入，不等待随后供电控制信号的刷新。BLOCK时不尝试写入，已耗准备／工作保留，公开回复仅为NOT_IMPLEMENTED，不能提前返回私有原因。审批回执不透露该接点值。此项是明确S假设，不表示Google具备本包接口。

| quality、sample_time | 每个本地通道带OK/MISSING及采样时刻；本版正常源在事件时刻提供即时、无误差采样 | 不假装有现场误差／延迟标定；MISSING不当作健康电源 |
| G就绪、连接、转供许可及本地保护 | 固定的实际执行联锁 | 决定启动／接管实际结果，profile不能绕过 |

控制计算只能接收显式本地信号包、family和本地事件时刻，不能持有评估器、World或全局ordinary真值引用。六个供电接点值域为0/1（quality=OK），或UNKNOWN（quality=MISSING）；写联锁另用上述ALLOW/BLOCK域。未来采样时刻是非法输入，早于当前事件的样本在本版视作MISSING。信号生成层与控制层分离；正常合成条件下信号对应其本地物理量。独立接口见证须固定相同信号包、改变未被输入的私有状态，要求控制请求不变；私有容量／连通仍独立决定实际供电，不随信号伪造而修复。该见证隔离控制接口，不把人为不一致信号当作已标定现场传感器模型。

LEGACY_LINE：任一有效上游有电接点为1则不请求G；否则请求。REVISED_LOCAL：任一馈线的电压、连接、支撑三接点均有效且为1才视为该本地路径可用；没有这样的路径则请求G。两个控制器共用相同通道与逻辑，不形成独立概率防线。

G初始IDLE。首次请求时若实际许可、就绪、连接或容量支撑不成立，立即FAILED；这些本地硬条件成立则进入STARTING，在τG后的启动完成事件重新检查条件，且exec_fault=0才RUNNING，否则FAILED。FAILED不自动重试。RUNNING保持到H，若实际执行条件丧失则失去供电。控制请求与G输出分开；普通源优先供电。启动燃料／辅助能耗及控制电源细节不在本包能量边界内，假设本地控制电源持续可用，不据此声称全设施能量或冗余保证。

## D. E3：精确事件时钟、资源与截断

时刻为有理秒；状态在事件处理完成后对右侧区间生效，积分用半开区间 `[前时刻,当前时刻)`。不靠浮点epsilon决定“同刻”。资源预约也是半开区间；前项结束时可释放给同刻后项。

同一时刻的优先级固定为：

1. 先累计此前区间的能量、服务缺额、人员和工具占用；将恰在该点耗尽的UPS能量设为0（解析事件，不允许负能量）。
2. 处理全部外生故障／恢复、撤销、窗口／授权到期和PRE截断。截止与故障优先于同刻提交；这一步只发生一次。
3. 处理已安排的安全退出及G启动完成；核对真实联锁，不默认G请求成功。
4. 处理仍合法的读取、准备、提交和复核工作完成及审批决定。提交必须满足 `t<tF`（tF=NEVER则无此限制）、`t<window_end`、`t<grant_expiry`，相等即不提交。
5. 更新本地信号、固定控制和供电；然后处理设备保护／启动完成。UPS恰耗尽同时外源/G接上，若两侧供电连续则没有虚构瞬时掉电或重启。
6. 发布到期的合法观察／审批／执行回执，再统一更新失效标记；有效区间右端不含。方法只处理这一步后的公开视图。
7. 若仍在PRE且未到H，方法作一次决定，公开准入后安排作业或审批。按请求到达时刻、request_id固定先后；不借隐藏成功率排序。

零审批延迟允许同刻下一微轮处理新产生事件；每个微轮维持上述次序，不重复积分或外生事件，提交仍用相同严格截止条件。**任何在供电处理之后发生的作业启动副作用（例如步骤7开始准备并隔离L），都立即安排同刻的本地状态重算，更新信号／供电／保护，使该时刻右侧状态正确；这个重算不重复积分、外生事件或方法决定。** 因而准备1开始时即OFF，不等待另一个未来事件。初始读取／准备／提交／退出／复核时长和发布延迟均正，申请次数有界，不产生无限零时刻循环。H处先处理已经到时的状态事件并记录端点，不启动新工作；H后的事件不执行。

每个现场工作占同一名技术员和工具。排队只依据公开预约和已知配方；READ／VERIFY在开始时预留其工作时长加可能安全退出的最坏占用，正常完成可提前释放；准备—提交—退出一次预约完整资源段。若没有能在公开窗口内安排的已知区间，返回NOT_STARTED_RESOURCE，不无限排队。预算在开始时预留、按实际占用结算、释放未用额度；故障后的安全退出已在预留范围内，不能以预算耗尽为由省略。

若退出失败导致实际占用超出预留、预算或后续外部预约，保留安全占用并显式记录RESOURCE_OVERRUN／未满足预约约束；不能强制释放、截断成本或让两个工作同时占用一套资源。这是预先声明的失败分支，不是允许方法违反硬约束后仍领取收益。相关损失保留在完整分母。

故障 tF 到达后：禁止新方法决定、申请、读取或提交；未开始的任务取消。正在READ/VERIFY而尚未完成者为ABORTED_READ，不能生成确定采样；其资源经τexit后释放。已采样但尚未发布的记录可按原时刻进入历史，绝不重新触发PRE方法。

READ_ROLE撤销同样中止该角色尚未完成的读取，安全退出仍完成；已有采样是否向该接收者发布按撤销后的访问权处理，失去读取权限者不获新值，只保留撤销／中止事实。FIX_GRANT撤销按E2作用于尚未提交的链，不能取消已完成提交或其必要安全退出。二者不互相代替。

正在准备／提交但尚未成功提交者保留原配置并进入SAFE_EXIT。若 LOAD_ISOLATED 已在准备开始时隔离L，则隔离持续到安全退出结束；ONLINE没有该隔离，但同样保留实际资源占用。退出失败保持隔离／占用至H。成功提交后的撤销／故障不回滚配置，尾段退出照常完成。这里都是事前固定的安全行为，不生成故障后新策略。

## E. E4：供能、保护、服务与评价

实际普通路径可支撑的条件为：源有效、连接成立且额定容量≥P；依次选择A、B、已RUNNING且实际联锁满足的G。三个都不能支撑时才用UPS。`work_isolation_active=1` 时L不能被任何源供电，设备断电、UPS不放电；隔离解除不自动跳过启动恢复过程。

有可用外源或G时，其向L输出P，UPS不放电；否则 E>0 时UPS输出P，直至解析耗尽事件。无源且E=0时输出0。设备被供电时（含启动和D=0的保持工况）消耗P，断电时消耗0；本版不并联分摊、不充电、不回收能量。容量不足视为不能支撑，不供给部分功率。

\[
E(t)=E_0-\int_{t_0}^{t}P_{UPS}(s)\,ds\ge0,
\quad\int(P_A+P_B+P_G+P_{UPS})dt=\int P_{load}\,dt.
\]

这是L负荷侧交付和UPS储能账，不包括燃油／启动辅助／全场损耗。E/P 给出下一耗尽事件，不能靠步长跨过再剪负值；冻结输入为有理数时，可得到精确分段解析基准。

设备初始为已供电RUNNING。失电立刻OFF；电力重新可用时进入BOOTING，连续供电τB后才RUNNING，期间耗电P但服务为0。BOOTING中再次失电回OFF并清除连续启动进度；重新供电重新计τB。若τB完成与失电同刻，先处理失电，不能短暂宣称恢复。既有保护不得被方法禁用。

`S(t)=D(t)` 当且仅当设备RUNNING且有供电，否则S=0。D为各组同一外生函数，方法无写权限。定义损失率 `u(t)=0` 当D=0；D>0时 `u(t)=(D-S)/D`，不计算0/0。主指标为 `L=∫u(t)dt`（s），从t0至H完整计入PRE隔离、故障与恢复损失。总未服务量 `U=∫(D-S)dt` 另记，不同D时不混作同一单位。

恢复记录按每次OFF事件分段：首次保护停机时刻ℓ，到重新RUNNING的r，恢复时长r−ℓ。若到H仍未RUNNING，则r=null、right_censored=true、已观察下界H−ℓ；它不是恢复时长的估计值。无停机记NO_OUTAGE，不填0秒恢复来混入样本。若恰在H完成启动，可记录端点恢复但不推断窗后持续性。

**恢复时间右删失不使窗内L/U删失。** 只要 `[t0,H)` 全轨迹完整，未恢复场景的全部窗内缺额仍精确累计；不能删去、填零或只积分到断电点。若执行本身中断而没有全窗口轨迹，则L/U标INCOMPLETE_TRACE，保留失败，不冒充完整窗口结果。
