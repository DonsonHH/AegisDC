## 1. 边界与固定拓扑

合成负荷节点 L 有三条互不旁路的候选支撑路径：普通 A、普通 B、后备 G。A/B 各有上游源、连接与适用负荷支撑条件；G 单列请求、许可、接受条件、就绪、连接、支撑、执行故障和完成事件。不增设联络、备用市电或其他通路。删减后的拓扑仅用于本版关系检查，不表示真实设施只有这些路径。

本版支撑是定性布尔量，不表示瓦数、能量或实际服务。即使某路径支撑为真，也不能推出现场数据完整性、服务恢复或收益。

## 2. 私有世界取值域

所有 `0/1` 均为真正布尔状态；`UNKNOWN` 只属于公开认识，不是物理世界的第三个真值。表中“输入”是离线场景编制者的输入，不能由 PRE 方法写入。

| 字段 | 有效域 | 含义与拥有者 |
|---|---|---|
| `vA, vB` | 各 `{0,1}` | 私有上游源有电状态；本版电压通道的真实被观察值 |
| `cA, cB` | 各 `{0,1}` | 私有连接状态；0 表示该路径隔离，无其他隐含旁路 |
| `sA, sB` | 各 `{0,1}` | 私有普通路径适用负荷支撑条件；不是数值容量 |
| `profile` | `{LINE_ONLY, PATH_REF}` | 两个合成控制关系；PATH_REF 仅为资格参照，非拟研究方法 |
| `permit` | `{0,1}` | G 的实际转供许可／联锁条件；与核查者的公开资料访问权限不同 |
| `accept_enabled` | `{0,1}` | G 请求接受链条件；0 时存在请求也不接受 |
| `ready, connected, supports` | 各 `{0,1}` | G 的设备就绪、连接、适用负荷支撑条件 |
| `exec_fault` | `{0,1}` | G 的执行故障；1 阻止接管，不自动修复 |
| `completion` | `{BEFORE, AT}` | 声明的接管完成判定事件尚未到达／已到达；不是瞬时接管或现场时长 |

所有上述字段必须完整声明，缺失、`null`、非法枚举、以字符串代布尔等为离线构造错误。合法布尔组合均可用于合成关系检查，包括异常连接状态；它们不因此成为现实操作许可。派生字段不得作为独立输入覆盖，值由下表决定；不允许伪造 `ordinary=1` 而三个显式路径都不能支撑。

同一 `profile` 的两个 PLC 资格视图读取相同源及路径输入，分别给出同一 `request`；共享输入标为同一来源组。PATH_REF 在这个合成参照中获得实际路径谓词，这是**私有本地控制的显式假设**，不授予 PRE 决策者同样的信息，也不是 Google 控制程序。

## 4. PRE 公开请求域与访问代价

| 字段 | 有效域／规则 |
|---|---|
| `action` | `READ_B_POSITION` 或 `READ_B_VOLTAGE`；两者只读，不改变物理状态 |
| `role`（可信公开上下文） | `AUDITOR` 或 `GUEST`；仅 AUDITOR 获准两类读取，由独立会话上下文提供，不是请求可写字段 |
| `access_slot`（可信公开初态） | `AVAILABLE` 或 `EXHAUSTED`；由方法不可改写的资源上下文提供。单请求生命周期另记占用 `NONE → RESERVED → RELEASED`，无秒数或费用值 |
| `request_id` | 本版单请求固定为 `rq-1`，在配对世界相同；不是私有世界标签 |
| `target` | 固定 `feeder-B`，无其他资产可选 |

固定请求字段集合仅为 `action/request_id/target`，role/access_slot 是可信公开上下文，方法不能自报或改写；请求额外携带这两项同样为 INVALID_REQUEST。公开检查顺序：字段／值合法性 → 上下文角色访问权 → 上下文初始访问许可。各步只读公开请求和公开上下文，依次返回 `INVALID_REQUEST`、`ACCESS_DENIED`、`RESOURCE_UNAVAILABLE` 或 `ADMITTED`；不返回输入私有字段的内容、隐藏失败原因或建议答案。无效请求不取得观测、不占用访问许可；其拒绝仍有公开请求留痕。仅允许 e1 提交一次，重复或其他阶段提交均为公开 INVALID_REQUEST，无额外占用。

本版只描述一个请求的生命周期，不研究调度或预算优化。`RESERVED/RELEASED` 是访问占用，不是零成本或已测成本；没有授权的现实时长／费用数据，不作成本收益比较。

e0 的公开初态固定为角色、访问许可状态、`target=feeder-B`、两项允许的请求名称和当前 PRE 事件标记；观察与请求历史均空。这里公布的是请求语法集合，GUEST 也能看到同一名称集合，但请求会按公开权限被拒。不包含任何 v/c/s、G 就绪或 profile 值。ADMITTED／REJECTED 仅来自前述公开规则，配对世界采用同样的请求ID与公开元数据。

## 5. 观察域、事件顺序与发布

私有观察结果域：`mode ∈ {DEFINITE, INCONCLUSIVE, CHANNEL_FAILED}`。DEFINITE 时，READ_B_POSITION 观察实际 `cB`，READ_B_VOLTAGE 观察实际 `vB`；没有误差、随机采样或隐藏的额外观察值。此理想确定观察是假设，只支持声明可观察字段的发布资格。其他模式没有确定值，不伪装为真／假。

固定事件顺序：`e0 初始 → e1 请求检查 → e2 已准请求核查完成 → e3 统一发布事件 → e4 记录失效`。这是合成偏序的一条完整顺序，不对应现场时长。所有已准请求，无论私有观察模式，在 e2 完成并释放访问许可，直到 e3 才允许观察结果出现；未经准入的请求不进入核查流程。该固定发布顺序避免在本版用私有模式控制提前反馈时间。

| 时点／条件 | 公开请求状态 | 当前有效观察 | 其他公开信息 |
|---|---|---|---|
| e0 | 无请求 | 空 | 不给私有世界标识、控制版本或故障标签 |
| e1 已准 | PENDING | 空 | ADMITTED；访问许可已占用 |
| e2 已准且完成 | PENDING | 空 | 统一完成／释放占用标记，不含结果或私有原因 |
| e3 已准、DEFINITE | RESULT_AVAILABLE | 一条 KNOWN 记录，必须正确发布 | 不是可选输出，不能仍为空或 UNKNOWN |
| e3 已准、其他两模式 | RESULT_AVAILABLE | 一条 NO_RESULT 记录，值为 UNKNOWN | 两模式不公开其私有原因；记录元数据仍正确 |
| e4 已准 | EXPIRED | 空 | 已发布历史记录保留并标明原适用时点，不能充当当前有效观察；不要求行动者忘记已合法见过的值 |
| e1 已拒，至 e4 | REJECTED | 始终空 | 仅保留对应公开拒绝类别；无核查、无虚构结果 |

e3 的原始记录字段固定为：`record_id=obs-1`、`target=feeder-B`、`quantity`、`value`、`status`、`physical_provenance_group`、`observed_at=e2`、`available_at=e3`、`expires_at=e4`、`receiver=AUDITOR`、`request_id=rq-1`、`action`。POSITION 的 quantity/group 为 `breaker_position/g-pos-B`；VOLTAGE 为 `upstream_voltage/g-voltage-B`。KNOWN 的值为布尔 0 或 1；NO_RESULT 的值为 UNKNOWN。记录 ID、字段集合、来源组等由公开动作决定，不编码私有值或失败原因。

合法传播副本单列字段域：继承原始记录全部字段，只有 `record_id=obs-copy` 不同，另加 `copy_of=obs-1` 和 `copy_received_at∈{e3,e4}`。原件必须已经合法发布且仍存在于公开历史；其余值、状态、来源、动作关联及原始时标均须一致。e3 收到副本时，当前有效观察仍规范化为原始 obs-1 一条，历史可保留副本；e4 收到时仅加入历史，当前观察仍空。副本不刷新有效期、不产生新核查或新独立来源；重复接收相同record_id幂等。引用缺失／未发布原件、篡改字段或e3前副本为不合法材料。

发布账是受控观察模块的权威输出，方法不能直接写入。材料包 `records` 可以含原件和上述合法副本；顺序不影响规范化当前视图。私有交付完整性核对按已发布账、字段集合、身份和复制规则判为 ACCEPTED 或 INVALID_MATERIAL，不能查询隐藏缺陷来修复材料。缺少该时点应有的原件、改值、提前材料等均隔离；核对状态仅留私有审计，PRE 仍从未被篡改的权威发布账读取。该核对不是方法的免费可行性工具。coverage-v2 的材料修改只发生在审计输入副本，不删除权威账或改变正常发布义务。

只有 e3 的适用当前视图使用该记录；e0–e2 不发布记录字段、值或私有元数据。e4 及之后的公共历史可含已合法发布的原记录和按副本规则合法到达的副本；副本保留原有效期，不恢复当前有效性或新增独立来源。PRIVATE 场景审计可以区分 INCONCLUSIVE 与 CHANNEL_FAILED，PRE 公开接口不能提前或额外区分。

## 6. 配对世界、保护与排除条件

信息配对使用固定 PRE 世界：`vA=vB=cA=sA=sB=1`，LINE_ONLY，G 的 permit/accept_enabled/ready/connected/supports 全为1、exec_fault=0、completion=BEFORE。`W0:cB=0`；`W1:cB=1`；`W2` 与 W0 相同但 `ready=0`。这些名称仅供私有检查清单索引，不能出现在公开请求或输出中。

新增电压配对世界 `W3`：与 W0 **仅 vB 不同**，即 `vA=1,vB=0,cA=1,cB=0,sA=1,sB=1,profile=LINE_ONLY,permit=1,accept_enabled=1,ready=1,connected=1,supports=1,exec_fault=0,completion=BEFORE`。W0/W3 均为合法 PRE 世界，A 的普通支撑仍成立；不把 W3 的 vB=0 解释为新增事中故障场景。两世界各只提交一次相同的 `rq-1/READ_B_VOLTAGE/feeder-B`，可信上下文 AUDITOR/AVAILABLE、观察模式 DEFINITE 相同。

W0/W1 在 e0–e2 的公开历史、角色和资源相同；DEFINITE 的 READ_B_POSITION 在 e3 必须分别发布0与1。READ_B_VOLTAGE 在 e3 都为1。W0/W2 的 READ_B_POSITION 到达后仍同为0，不能附带披露未被该动作观察的设备就绪差异。

W0/W3 的电压请求必须连续遵守 e0–e4：e0–e2 公开历史与空观察相同，e3 分别完整发布真实 vB 对应的 KNOWN(1)/KNOWN(0)，e4 当前观察为空但各自已合法发布的记录保留在历史中。元数据按第5节的电压 quantity/group/action，不暴露私有世界名。不能以两个重新初始化的请求分别证明到达前与到达后；也不能用机械输入中的 vB=0 替代这一公开读取见证。既有 W0/W1 的电压读取仍保持同值，用于保护未被观察的 cB 差异。

本版 PRE 不含变更、启动或转供动作：后备机械见证是离线挑战后的私有机制检查，没有额外公开响应策略。真实许可、接受、执行故障的拒绝／失败必须保留；本版没有把这些私有原因声明为 PRE 可读通道，因此不得经菜单、请求检查、异常或目录名发布。未来若需要把实际执行失败作为 PRE 可读结果，须另行规定该动作、到达时点、粒度和占用并返回 review，不能直接暴露调试异常。

界外内容：第三条普通路径、别的资产／动作、缺字段、非法枚举、外来私有状态注入、数字时间／费用、已知未来故障标签，以及 RESP/荷兰场景。离线定义错误仅报告给私有审计；公开请求错误只能按第4节处理。支持的读请求永不改变物理字段、profile 或外生挑战。
