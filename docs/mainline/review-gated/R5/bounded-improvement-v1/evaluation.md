# 反馈、最终评估与上限

以下为协议设计值。当前交付中没有新候选分数、最终评估输入、执行 manifest 或启动授权。

## 数据何时可见

| 材料 | 选择前与选择中 | 锁定之后 |
|---|---|---|

| 四种 H 在两面板的开发反馈 | 未来若获授权，每一唯一的“描述符＋输入＋运行依赖”生成一次从空观察开始的独立完整轨迹。专用评价进程保存全表。三个选择程序仅通过各自的 query 收到已付的整列。 | 公布各逻辑组的逐轮提案、读取顺序、逻辑票、缓存来源及物理调用。拒绝与缺失留行。 |

开发查询接口只接受目录 ID，不能指定条件、分支、行的排序、终止点或想看的指标。物理层允许先按公开固定顺序生成四个完整列，再在不可改写的已见开发结果上按组回放。每次使用缓存与实际计算一样扣该组的一张票。组间不传候选排名、未来列、cache hit／耗时侧信道或另一组反馈，同组不能用缓存免票再询问。各组得到相同的外生条件、许可、观察机会和结果字段，实际观察和成本来自各自策略。缓存键包含面板、完整输入 SHA、描述符／策略源码 SHA、设施、观测、评分、H、时钟、初态和环境版本。同一算法偶然给出同一动作不构成跨描述符缓存键。

I/D/P 的 162 条既有处理记录（57 与 105 分列）是共同初始资料，先按各自原输入、核心 1c0b0c47、历史运行身份、需求及轨迹 SHA 对账。闭合／违规／成本以保存原件为依据。回执不足时先恢复原件，不插补、翻用其他臂或擅自重跑。三个 selector 每个最多获得四列新反馈，每列都要经过完整 19 和 35 两面板；开发物理矩阵只对四种 H 各算一次。三个回放的结果高度相关，不能算三次独立研究。

**污染与技术停止。** 每次查询先登记版本、顺序及费用，再放行信息，禁用任意文件读取、网络、时钟和自由文本工具作为策略／改进器输入。运行服务保留输入与输出可见人、时间、版本和实际读取账。静态可见性从一开始披露，不承诺对操作者盲。若人或选择程序提前取得新评估输出、用手算的预计赢家换样／改权重／挑版本，立即停止并记录已见范围与原件，相关结论只作探索性材料，交 review。不能换目录或换代理后重称独立验证。正常的拒绝、无改进、非合规、右删失或命题被否证仍完成预定覆盖；技术、身份、信息或评分错误停止后缀，禁止重试或挪用未花预算。

## 将来怎样构造最终面板

目标是 **21 个新的有限条件**，由九个双联和一个三联组成。每组只承担当列的主义务。起点取原开发 C01 的完整共同配置，统一改为无故障／无恢复、ONLINE、预算各 20、窗口 [0,20)、E0=3、初始观察为空，未列其他字段沿用原件。下表中 a/b/c 是评价端的配对键。它们不进入任何策略或提案程序。[原配置](../../R3/formal-protocol-v1/development-inputs.json) · [既有整秒候选域](../../R4/finite-extension-v1/selection.json)

| 组 | 行数及唯一主变化 | 执行前静态可达要求 |
|---|---:|---|
| V01 位置 | 2，cB=0/1 | 首个 POS 可合法采样、发布且在决策时有效。D 正常完整链可达。 |
| V02 电压 | 2，vB=1/0 | cB=0，POS 支持时，第二项 VOLT 的读取和有效到达均有机会。 |

| V04 无结论 | 2，READ_POS 模式 DEFINITE/INCONCLUSIVE | POS 均可到达，首次读取后的 DIRECT 完整链可行。无结论与访问被拒分开。 |
| V05 权限 | 2，仅 direct=ALLOW/DENY | 其他角色、兼容性相同，I 的合法 EVIDENCE 链可达。 |
| V06 截断 | 2，tF=T₁ / T₁+1，tR=19 | 其他因素相同，名义单读后提交 T₁ < T₁+1 < 19，读取结果早于两种截断。 |

| V08 窗口和排队 | 2，W=W₂−1 / W₂ | 同一个外部预约确实推迟首读或后续必要作业。前两项在两个窗口内都能到达；两行的完整链准入须分别为否／是。 |
| V09 物理后备 | 2，仅 ready=true/false | tF 取 I 与 D 名义正常复核到达的较晚者加 1，tR=NEVER，tF+τG < H。核验许可、配置与请求链；后果另读 G 与实际供给段。 |
| V10 作业副作用和退出 | 3，(ONLINE,SUCCESS)、(LOAD_ISOLATED,SUCCESS)、(LOAD_ISOLATED,FAIL) | 前序相同且正常可开工；a/b 只改作业方式，b/c 只改退出计划。真实到达、失败和服务后果随后照实报告。 |

计算 T₁、B₁、W₂ 时只用书面名义配方，不调用设施、策略或评分器。给定读数 k 并假设各次合法到达且支持前件，从 s=0 开始，每次取得能容纳 read_work+exit_work 的第一个公开空档，令 s 为采样时刻加发布延迟。固定修订在 s 申请，审批后寻找容纳 prep+commit_work+exit_work 的首个空档，从开工加 prep+commit_work 得名义提交 Tₖ。VERIFY 的最早开工为退出完成、执行回执到达两者中较晚者，再按 verify_work+exit_work 寻空档。记其名义结果发布时刻为 p、资源预留末为 e，则 Wₖ=max(p+1,e)，Bₖ=k×read_work+prep+commit_work+exit_work+verify_work+exit_work。先在完整窗口推导，再在每个拟定边界复核所有前序读取、有效期、余额和审批／执行条件；不能仅代入最后一个不等式。隐藏挑战时刻仅用于编制该对，在线资格始终取当时 v2 视图。

未来构造顺序固定为 V01 至 V10，组内 a、b、c。每组的自由背景仅限 read_work／verify_work 与一段可选预约；采用原 selection.json 的 4 个配方和 7 个预约，按原表的外层配方、内层预约顺序。取第一个**整组**满足表中静态前置、精确去重和语义差异的背景。每组最多 28 个背景，总计最多 280 个背景／588 个拟议槽位向量。预算与窗口必须在 1–20，T／恢复时刻在已声明域内；固定权限、有效期和撤销规则沿用原机制。全部背景尝尽仍不合格则记“模板内未构成”，不能写成全域不可能。保留原因和全部槽位，部分清单须重新交审批定，不能扩大域或补重复行。

用已接受的规范化对完整配置算 SHA，排除原 19、35、历次已披露工程与本包以后新增的资格见证，亦排除清单内重复。语义比较沿用修正过的历史撤销处理，要求有实际可达的公开行动／资料时点、准入边界、物理父条件或外生挑战差异。新前缀的名义机会单列作依据；仅标签、无作用参数、迟于所有有效动作的预约或无放电时的能量变化不得制造新颖性。保持组共同背景，任一成员冲突则拒绝整组。逐输入列出旧有限依据和新增适配资格；未承接的关系保留具体缺口，不用最终评估输入作调试。此处只定义模板和排序，没有构造 V01–V10 的完整向量或揭示其结果。[既有基准](../../R4/confirmation-entry-v1/public-dedup.json) · [静态承接修订](../../R4/finite-extension-v1/static-transfer.json)

## 判定与分母

开发期在两套已见资料上分别发布原分母、完整性、违规集合、关闭状态、L/U、人员／工具秒与其他冻结成本，按改进协议的逐行非退化规则选出一个 π*。唯一推荐值、完整前沿及每个不可比候选的具体退化行均入账。新统计不回写 19 或 35 的原始结果。

最终评估固定输出 I、D、P、人工 H1a 和 π*，无论谁有利都列出。描述符相同时使用同一回执并列明别名。逐行先判技术状态与实际阶段，再给 L/U、资源违规、人员／工具、排队、审批等待、未开工等待、停止时刻、请求／策略调用、分动作／阶段占用及恢复删失。原 I/D 参照继续给 `L_D−L_I`，P 是背景。对新策略统一给 `L_ref−L_π*` 与 `C_π*−C_ref`，ref 分别为 I、D、H1a，P 的背景差另列。主问题为 π* 相对 π0 在新增有限面板能否仍满足相同晋级关系；如果 π*=π0，明确报告没有策略更新。

固定参照掩码仍由该面板 I/D/P 决定，报告所有 21 槽。比较的两策略均完整合规且在 M 内，才给有效的数值收益符号。新增非合规、无法合法关闭本应关闭的目标、某维度退化、未达分配阶段、缺失或未执行各自列明。缺证据或覆盖未达时不宣布完整命题获得支持。服务与成本相反时报取舍，不找结果有利的子集、总体权重或阈值。技术失败中止后也输出完整分母与未知调用小计。单一合成模型中的配对结果只支持所列条件，不给总体统计功效、发生概率、实用阈值或现场收益。

## 未来预算（提案）

**一个环境回合**指在一个完整外生条件下，用一个全新单策略实例跑到 H20 并独立评分一次。预算按开始调用即占用，未返回单列未知，不能退票。相同初态也不能跨描述符共享付费观察。单回合最多 20 次策略入口调用、5 个请求。适配器最多 21 次公共读／推进（含 tick 0 与终止 tick，复用初始公共包）、5 次 request、1 次收尾推进、3 次审计，共 **30 次外层 plant 入口调用**。原设施在准入内部做的复核计入该次调用的计算实耗。构造和评分各自最多 1 次，另计。

|---|---|---:|---|
| 开发物理矩阵 | 4 种 H × (19+35)。I/D/P 的旧回执按身份共用，物理新增为 0。 | 216 / 4,320 / 6,480 | 每候选两面板分别以最多 3 个新回合一作业，4×(⌈19/3⌉+⌈35/3⌉)=76 作业 ×60 秒 |
| 最终评估 | 21 条件 × 至多 5 个不同描述符。相同版本只执行一次，报告别名。 | 105 / 2,100 / 3,150 | 每条件最多 2 作业，I/D/P 一组、H1a 与其余不同的 π* 一组，共 ≤42 作业 ×60 秒 |

科研合计上限为 321 个环境回合、321 次构造、321 次评分、6,420 次在线策略调用及 9,630 次 plant 入口。科研环境作业 118 个，上限 7,080 预留 CPU 秒。加三项零环境处理和两项资格，**全包至多 123 个作业、7,680 预留 CPU 秒**，每作业 1 CPU／1 GiB、并发 1、GPU 为 0。60 秒沿用原三处理作业的资源保护上限，每一作业最多承载三个完整回合；这是运行限额，不是策略实时性能结论。少于上限时不补跑，技术失败不重试、不把未知计数折成可用余额。

U0、强搜索与 U 程序换序回放各有 4 张新候选票，每组至多 216 个逻辑条件回合、三组至多 648 个逻辑条件回合。三组实际共用的开发矩阵最多 216 个新物理回合。一次换序双提案占 U 组两张票，元提案上限 1。H1a 属于上述四列。选择与锁定作业的 120 秒中，每个选择进程各有 30 CPU 秒，余下 30 秒用于共同校验和写账，不跨组转让。各进程实际 CPU 用量单列，超限按技术停止处理。

三个选择程序均可用确定规则实现，LLM 请求、输入 token、输出 token、外部检索和在线人工改写的上限**均为 0**。人工只保留一次共同的开跑前材料审阅及一次锁定版本的最终评估放行，逐次记录人员和实际用时。研究中途人工候选、筛选提示、补参数、改阈值或救援迭代均为 0。发生人工科学干预时保留失败、停止该版本并交审。本轮协议编制不消耗这些拟议执行配额。
