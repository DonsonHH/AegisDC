# 接口差距、实施顺序与所需见证

以下是可拆票的契约与独立预期。当前没有新增适配器、策略实现、检查器或资格运行。未来先固定纯接口输入、预期与源码身份，再执行所获授权的切片。

## 现有接口在哪里能用，哪里会拒绝

| 接缝 | 可承接的部分 | 最小新增工作 |
|---|---|---|
| `E14Run.public_view / request / advance / audit` | 原设施接受 POS、VOLT、CONFIG、FIX_CTRL、VERIFY_CTRL。DIRECT 有自己的许可，EVIDENCE 需满足既有证据规则。模型仍执行审批、写联锁、退出、复核与原有保护。[请求边界](../../../../../src/aegis_dc/london_e14.py#L481) | 直接复用固定版本。新策略始终拿到脱离引用的 v2 副本。把新目录限制在策略侧，不给它设施对象、外生配置或原始预约。 |
| `choose / make_request / fix_feasibility` | I、D、P 的决定、公开完整链判定及请求／VERIFY 父身份构造可复用。[现有实现](../../../../../src/aegis_dc/london_treatments.py#L37) | 新增封闭的 H 描述符解析与单步函数，复用原 `make_request`。DIRECT 读后申请需要单独的策略身份。前缀材料只决定是否申请，不能写成 EVIDENCE 证书。 |
| `run_condition` | 原整数时钟、推进至 H、请求及异常归档方式已有有限证据。[三处理循环](../../../../../src/aegis_dc/london_treatments.py#L104) | 现有函数强制 I/D/P 排列，内部固定调用 `choose`，限制 D 的诊断动作。原函数无策略注入参数。新增窄的一条件一策略执行适配；不改 `ARMS/CAPS`、不覆写 `choose`，不用 I 或 D 伪装 H。 |
| `score_arm(audit,run,isolation_ok,frozen_input)` | 现有评分按冻结需求而非可修改的模型汇总积分，保留能量／服务、人员／工具、各等待、硬约束与右删失。[评分](../../../../../src/aegis_dc/london_treatment_score.py#L18) | 继续由评价端调用原函数。单策略记录满足原 run 格式，arm 写真实策略身份。隔离证据来自新进程和实际绑定检查；不能将 isolation_ok 常量设为 true。 |
| 入口、保存核对与优化 | 原 `manifest_data` 固定 35 槽、原数据及许可；原报告同时要求三臂并禁止 D 诊断。已接受的 PL01–PL05 给出持久调用意图、已知／未知计数、外层错误停止的契约。[原入口](../../../../../scripts/finite_extension/common.py#L75) · [原报告检查](../../../../../scripts/run_london_public_development.py#L77) | 新 R5 用途、目录、单臂 schema 与配对器。沿用计数／留存规则；新接口要证明自己能保存失败、区分按组付费与物理执行，绝不使用已消费的 R4 授权文件。 |

**单回合隔离。** 每个物理回合使用新进程和新 E14Run，共同输入由只读权威副本深拷贝。初始配置哈希、初始私有状态的语义摘要（去除运行时对象地址）、初始公共视图、真实策略版本和回合身份分别登记。相同条件的不同策略要有相同初态、不同的预算／观察／请求／回执空间。候选只能是已审核的有限描述符解释器；禁止任意脚本／闭包、文件查询、网络或跨回合持久化。父进程核对每次实参与分离的 v2 返回、身份、初始化／结束输入哈希，收齐隔离证据才交最终评分；缺证据时记技术错误／未评分。此安排替代了原三臂同时在内存中时“比较其他两个活动对象”的证据方式，须在新边界补资格。

```text
run_one(common_bytes, frozen_descriptor, intent):
    评价端独占新的回合位置；记开始前意图、输入与策略身份
    从不可变输入构造新实例；保存初始 audit 与 t=0 的公共包
    在原公共整数时钟 0..20：
        0 复用初始公共包；之后调用 advance(该 tick)
        PRE 已关即登记 ENV_PRE_CUTOFF；不再调用策略
        validate_v2；decision = act(descriptor, detached(view))
        WAIT_PENDING 等下一 tick；合法停止则留 reason、time
        其他动作检查描述符的类型／次数／唯一性；原 make_request 生成负载
        只通过实例 request 提交；公开拒绝停止；非法请求或父身份作为技术错误
    保存停止与审计；若需则收尾推进到 H；保存最终 audit、实际阶段
    独立验实隔离；评分器只读本组档案与调用前的冻结需求
    将原始返回／异常、调用账、资源账和终态写入评价端
    开发查询仅在两面板整列完整、已付票时解锁；最终分数按冻结批次统一发布
```

## 最小资格设计（未执行）

第一工程作业用小型、预先冻结的完整 v2 字面包／假回调／假反馈账；提供与真实 schema 同形的所有必填字段。下表每族至多四次纯决策调用，总计至多 32 次，配对与账务检查不调用真实设施或评分器。没有实物真值或由待验函数生成的“标准答案”。

| 族 | 输入差别 | 预先规定的可观察结果 |
|---|---|---|
| Q1 身份、隔离 | 经新适配器送入两个带不同私有作业方式／未来截断标记的评价端替身，两者发布同一 POS 可读的空观察 v2 包。另给多余私有字段或错误版本。 | 在实际策略调用边界截取脱离引用的实参，描述符与 v2 字节分别相同，没有私有标记或设施引用。两次都应 READ_POS。越界包在调用前报技术错误，真实请求为 0。 |
| Q2 到达与到期 | POS 请求 pending；合法 POS=1 在决策 tick 刚到；同记录在 expires_at 恰等于当前时刻，history 有原发布记录，DIRECT 完整链可行 | pending 时 WAIT。到达时停止且零 FIX。到期的值不能短路；H1a 可提 DIRECT，H1k 资料不足。 |
| Q3 未知的四种处理 | 一次合法 POS 在本组已到达 NO_RESULT，pending=false，VOLT 与 DIRECT 均可行 | 按 H1a、H1k、H2a、H2k 依次应为 DIRECT、资料不足、READ_VOLT、资料不足。DIRECT 负载没有 evidence_ids。 |
| Q4 二读与同源资料 | POS=0 后 VOLT 未试、VOLT=0 合法到达、两项支持均有效、POS 在 VOLT 回来时已过期 | H2k 四个对应决定为 READ_VOLT、停止、DIRECT、资料不足。不得用过期 history 或复制件补足独立支持。 |
| Q5 完整链的公开边界 | 已完成足够前缀，分别令 direct=DENY、需要的 verify 权限为 UNKNOWN、chain_finish=window.end、以及余额=chain_reserve 且 resource_end=window.end 且 finish<end | 分别为 INFEASIBLE、资料不足、INFEASIBLE、DIRECT；最后一项保留审批／执行流程。 |
| Q6 复核与失败 | 已 FIX、等待回执；成功回执到达且 AWAITING_VERIFY；只令 VERIFY 自己的计划不可行；已到失败回执 | 等待、以真实执行 ID 和目标 epoch 申请 VERIFY、资料不足、STOP_UNRESOLVED。错误父身份不能变成成功，已提出的 FIX 不可重发。 |
| Q7 缺证与请求拒绝 | POS 不可准入；attempted 但无到达依据且已不 pending；已尝试 POS 而唯一到达记录的对象／角色错误；一次实际 READ 请求被合法拒绝 | 前三项保留资料不足（错误身份不计 settled）。最后一项按原请求回复停止，后续请求次数为 0。 |
| Q8 发起与停止边界 | 比较合法 DIRECT、历史 I 的完整证据请求、在 PRE 关闭时恰到达的资料、调用前持久化意图失败 | 两种 FIX 负载按各自模式和真实记录构造；后两种情况均不得再进入相应策略／环境回调。原始异常、未知内部计数和未启动后缀保留。 |

同一纯接口作业再做以下离线账务见证，使用**符号比较关系**作为独立预期，不产生科研输出。

- 在同一 S 中，H1a 的“未知后 DIRECT 退化”和“单读后 DIRECT 退化”均为真，H1k 与 H2a 未试且票足。U0 首选 H1k，交换优先序后首选 H2a。两票先锁定，验证双提案互有取舍时拒绝改 U。没有两种有效下一提案时保持原 U。
- 给晋级器“同服务且两资源均少、其他行无退化”和“某行省工但另一行缺额上升”两个符号夹具。前者在 M 上产生严格晋级，后者记录取舍。只在已违规行获得原始好处、在参照合规行新增违规或缺评分，分别是无有效严格收益、拒绝、技术停止。
- 相同全表用三种不同解锁序列回放，终局前沿和选定 ID 一致。重复请求相同 ID、预算不足的双提案、试读未来列／评估真值或缺失来源哈希，均记录错误并停止；不追加票。用公共替身模拟一次已返回后的归档失败，调用数为 1、后缀未启动；若仅有意图而无法证明已调用，则标未决。候选付款与真实环境执行分别记账。

第二工程作业只用旧公开 `E01-no-fault-full-chain` 的共同初态（无故障、无预约、各读取和发布均 1 秒）。最多五个新适配回合，I、D、P、H1a、H2k 各一次。先固定源码、该工程点的完整输入、以下字面预期及旧 E01 的原件哈希，再开始。I/D/P 的动作序列、时点、停止、L/U、成本和硬约束对照已接受的 E01；忽略进程 ID 等不具机制含义的差异。H1a 的设计预期为 POS@0、DIRECT 申请@2、实际提交@6、退出后 VERIFY@8、复核结果到达@10。H2k 还需 VOLT@2，DIRECT 申请@4、提交@8、VERIFY@10、发布@12。两者都必须通过实际公开状态驱动的循环、实际批准以及各自的执行身份。手算占用分别为 1+5+1 与 2+5+1 人员秒／工具秒。它们是独立工程预期，不是本轮取得的处理结果。[原 E01 配方与验收范围](../../R3/runner-v1/contract.md)

这里的资格只覆盖新适配与给定分支。已见 19／35 的旧处理不为此重跑，拟冻结 21 行不作工程试跑。预算不足、出现核心变更需求或无法保证信息隔离时，原失败和未执行后缀留存，不能挪用研究预算。
