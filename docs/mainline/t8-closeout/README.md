# T8 在 FIT 收口

## 机制未触发

两臂共支付 32 个提案槽，对应 16 个不同编辑。前三轮每臂的 12 个候选均未严格降低父策略的平均缺额，R 的改写条件连续三轮未触发。第四轮两臂都选中第 3 槽的 `ORDER_FAR=3`，随后锁定。R 因改写新增并实际付费的候选为 0 个，进入最终父链的也为 0 个。观察到的 R−O 缺额差和工时差均为 0，反映的是同一锁定策略的表现。本批没有执行改写产生不同候选之后的效果比较，也没有检验两种搜索程序的等价性。[轮账与锁定身份](numeric-sources.md#fit-mechanism)

## 已测单点编辑的服务缺额

逐行保留并列最低者，`ORDER_FAR=3` 是唯一在 48/48 行都达到最低缺额的已测编辑。在 16 个已评分单点编辑中，2 个相对共享父降低了整板缺额，均增加工时，同时改善两项的为 0 个。单点空间还有 `ALARM_NEAR=3`、`ORDER_NEAR=3` 两个非零编辑未评分。服务饱和的适用域是这批条件与已测编辑，不含未测编辑、组合编辑或其他端点。[候选分母与最优集合](numeric-sources.md#fit-menu)

## 服务收益与工时约束

相对共享父，O 和 R 各减少平均缺额 15 秒，平均多用 18.958333 人秒。Q3 的 +5 人秒容许量按族比较单侧上界。伦敦工时均差为 +1.458333 人秒，荷兰为 +36.458333 人秒。若未来每族 38 个独立块复现 FIT 两个块的均差与样本方差，荷兰工时的单侧 95% 上界为 +38.152 人秒，单此一项即使联合资格不能通过。这是条件预测，DEV 实测判定尚未取得。[父子对照](numeric-sources.md#fit-trade) · [分族门槛和情景上界](numeric-sources.md#fit-gate)

## 面板结构

伦敦和荷兰各有两个十二行块，四个登记签名互不相同。42 行的全部已测编辑在缺额上并列，其余 6 行都在荷兰。这些签名排除了面板结构同构的解释，定位到的饱和范围是这些单点编辑在服务端点上的表现。[块签名](numeric-sources.md#fit-blocks) · [逐行并列情况](numeric-sources.md#fit-ties)

## 证据边界与停点
