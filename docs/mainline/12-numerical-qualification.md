## 独立预期与数值比较的等级

隔离房间案例只通过显式系数／边界隔离热库存，保留整个设施。无电源、固体换热和冷却流量时，1 MJ/K 房间相对 293.15 K 恒定环境的 10 K 温差，以 0.1 MW/K 被动导热衰减。独立解析解为 `T(t)=293.15+10 exp(-t/10) K`，10 s 时为 296.8287944117144 K；相应边界能量为 `C(T0-T)`。它检验一阶步进误差，不能代表其他联合工况具有解析解。

原 M1 独立手算预期继续约束 AC 预算、UPS、发电机、室内作业与组合轨迹。独立读回器从保存状态重算 `J=W*s`、`kg=(kg/s)*s`、固定库存、外生需求／交付积分和归一缺额。归一服务缺额为秒，未交付服务为服务单位秒，人员为人秒，工具为工具秒；各自报告，不加总成收益分数。公共加载器另外拒绝把比热写成 J/kg、库存写成 kg/s 或功率写成 J。

其余复杂轨迹以 0.01 s 同模型细步轨迹为**数值参考**，并以 0.02 对 0.01 s 检查参考分辨率。参考不是解析真值、外部求解器或经验数据。连续热状态采用分段线性读回，积分过程中实际保持的热流采用左保持；离散模式不插值。逐事件比较有序身份和切换时刻，服务、资源时间单列，防止连续温度误差掩盖一整个采样周期的保护差异。

冻结最大步长为 1、0.5、0.25、0.125、0.0625、0.025、0.02、0.01 s。0.025 s 是捕获前提出的候选步长，先声明温度 0.05 K、压力 1000 Pa、热流 25 kW、服务／资源／切换 0.001 s 的数值误差界；0.02 对 0.01 s 的差异需小于对应界的 25%。隔离房间另有 0.005 K 解析界。阈值案例使用冻结的 306／305 K 保护与复位，不因结果改变阈值。任何未通过条件都保留为未获资格，不由绿色回归代替资格。

## 时标反例与修复

原运行器在 0.1 s PLC 时钟下，对 `0.6` 和 `.2*3` 两种仅差一个 binary64 ULP 的事件编码，分别交付 0.6 和 0.7 服务单位秒。数值表示差异被放大成一个采样周期。原 red 保留于 `evidence/mainline/engineering/12-numerical/development/red-clock-ulp.log`。

`aegisdc-binary64-time-v1` 明确规定：有限时刻相差不超过两者最大 ULP 的八倍时，在当前处理时刻视为同刻；该时刻在批处理中固定，不沿相邻事件滚动合并。PLC 采用从零锚定的 `n*period` 时钟，每个时刻只采一次；备用有界求稳和最终右值访问语义保持。原输入／事件 `time_s` 不变，`applied_at_s` 记实际处理时刻，结果 metadata 保存完整约定。3600 s 范围内的八 ULP 上界为约 3.64 ps。这是模拟时标约定，不是设备时钟分辨率，更不用于裁剪温度、质量、能量或干度。

行为测试覆盖八／九 ULP、1 μs 明确延迟、相邻 0／8／16 ULP 不滚动链、同刻同参数冲突、0.037 s 数值步下 0.1 s 长时钟，以及积水阈值同刻转向排水后按最终右值允许工作。修复只涉及时标，未改变热力学方程、守恒容差或物性适用域。

## 相变物性与表示边界

冻结 R134a 表的压力范围为 0.1–3.0 MPa，仅支持固定容积纯工质两相平衡；质量、容积、能量、两相可行性及根唯一性共同约束输入，不能只看压力。实际郑州介质身份未知。

重新读取已交付 432 个冻结输入，要求其全部接受／拒绝身份保持；五个名义纯汽输入编码后重构干度为 1.0000000000000002，仍严格拒绝。围绕这五个原输入，对容积 ±8 ULP、能量 ±1 ULP 的 255 个邻域组合保存完整浮点十六进制、实际编码干度和结果。该有限探针不能证明所有质量比例都可表示，也不能成为裁剪干度的规则。

九个固定容积热量状态继续对照冻结的直接 EOS 参考，明确为同一 HEOS/R134a 的数值一致性。固定 V6 的 V/M 还在每个冻结行按两相混合关系记录可行库存包络；这只是表行采样，非所有参数的连续可行域证明。无根、多根、单相及真实域外输入依旧失败。现场经验验证保持 pending。

正式捕获前冻结源、输入、工具和 runbook；每个输出目录唯一，失败不重写。四份 `save_run` 原文件逐字节压入分运行 ZIP，保留原 run metadata；每个成员记录 SHA、字节数及记录数，并与公共 manifest 复核。ZIP 是无损容器，不把重新编码 JSON 当原件。

开发 `capture-01` 的零流检查按原请求时刻划区，错误纳入已在数个 ULP 前恢复的右值；原 archive、失败和 trace 保留，读回器改按 `applied_at_s` 解释实际零流区间。此项是作者验证工具准备错误，不是物理缺陷修复。

开发 `capture-02` 的字面检查在 3 s 附近找到 2.999999999999993 s 的左值和精确 3 s 的右值，却取了第一个，误报发电机仍 starting。两份状态原件保留。读回器现在要求未关联事件的检查点有精确保存时刻；UPS／发电机的解析切换和耗尽检查点在 runbook 中显式关联事件身份，10 ns 窗口仅匹配该事件，并记录目标时刻、实际事件／匹配行时刻及差值。检查的是实际事件后的右极限，不声称未来状态已在目标时刻成立。窗口中若有另一个不同刻事件则判歧义；事件实际时刻误差还独立计算。此项是读回器准备纠正，不是放宽保护或库存规则。
