# 公开信息与处置价值：有限决策树

`assess_action_value(frame, belief_model, risk_catalog, value_model)`及同名模块CLI接受四份封闭JSON输入。它先调用第19项公开风险接口，从当前已到达证据重建第18项认识，再对声明的联合后果、观测和行动模型计算。没有后台实际状态、未来事件、真实资源占用或物理执行器查询。八域及原六项未识别风险随结果保留；不将未识别项赋零概率。

## 比较对象与共同条件

每个已量化问题单独比较暂缓、直接处置、检查后条件处置三种备选。它们使用相同的当前联合结果分布、共同外生需求、时域、人员/工具可用性声明和资源预算。多个问题的值不能相加为全设施增益；本接口没有并行多任务调度或全局最优策略。问题未被价值模型覆盖时，不表示其风险为零。

检查的二值报告似然以同一联合结果为条件；似然与第18项现有信息的条件独立性是明确研究假设，而非因来源ID不同自动成立。报告到达前没有条件行动。检查只改变认识，任何服务损失减少都必须通过声明行动期间/完成后的容量规律产生。行动开始之前继续使用基线容量；行动期间使用`during_capacity`，完成后使用`after_capacity`。容量和共同需求的最小值给出交付，重叠组件缺额计一次。处置没有在仿真设施中执行，也不修改风险或关闭问题。

## 时间、资源和费用

所有时间是从当前决策时刻起的秒偏移。检查按移动、等待、作业顺序占用一个指定人员及所需工具；其后报告延迟不占用人员或工具。报告到达后处置再依次移动、等待、作业，可以由同一人执行；两阶段不重叠。动作耗时与有效容量不是现场测量，而是显式研究输入。

`expected`仅累计评价时域内实际会发生的预测移动/等待/作业时间。`required_resources`记录一旦启动该分支作业便承诺的完整资源时间，即使该作业不能在评价时域内完成。所有正概率分支均须满足同一完整承诺预算和可用性窗口；不能用较小的期望成本通过硬预算。可用性窗口为显式规划假设，`null`表示未知而非可用。资格、工具与目标绑定沿用第19项当前公开选项；动态执行许可始终为false。

阶段`cost`是在阶段移动/等待/作业开始时承诺的整笔研究成本。若阶段起点在评价时域外不收费；若起点在时域内，即使作业本身尚未开始或无法完成，也记录该笔承诺成本。它不是每秒费用或维修完成费。人员/工具在完整承诺与时域内累计之间分别记账。

当检查或报告不能在时域内完成时，报告标为`unavailable_within_horizon`，没有虚构正/负结果，也没有该报告触发的行动。直接处置尚未到场则继续基线；行动已开始但尚未完成则继续行动期间容量，不提前恢复。零概率报告分支保留`ZERO_SUPPORT_REPORT`和缺失条件后验，不解释为零风险。

## 选择、模型误差与数值范围

报告分支可预先声明暂缓、处置，或在同一条件分布及预算中作一次最小服务缺额比较。后者是有限一步条件续决策，不是全局策略。最终展示服务缺额最小的已明确可规划备选；并列时依次比较人员时间与稳定名称，不混合不同量纲。检查价值显示服务缺额变化、人员时间变化和研究费用变化三个独立量；费用没有任意折算为服务秒。

第18项认识变体与检查/行动变体的笛卡尔积分别计算，输出逐假设结果和逐点范围。范围不是统计置信区间，不估计尚无数据的现场误差。参考认识冲突时数值缺失；任一敏感性认识冲突则不提供全变体包络。全部分支持续时间、完整承诺和输出积分必须有有限binary64表示；不支持的数值范围以ValueError拒绝，CLI退出2，不返回无穷或零回退。时间与容量积分用解码数值的精确Fraction；概率从公开显示值的最短十进制重新归一后运算。

第21项控制真实人员占用，第22项取得真实检查证据，第23项执行物理处置。这些行为不由本票预测自动获得。有限工程算例检验计算及边界，不证明巡检收益、现场标定或AI/RSI增量。
