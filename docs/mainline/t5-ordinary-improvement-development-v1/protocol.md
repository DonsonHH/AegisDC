# T5　普通改进的开发协议

主轨道从 B_cost 的参数向量开始，热启动从 V** 开始。两个初始向量在完整公共历史上逐帧核验，使用原生支持的 61 个 60 秒决策点、0.25 秒设施步长和 3600 秒服务窗口。每次选择一项合法工作意向或暂缓。真实作业、许可、排他恢复期、R/X 与 NA/PV 均沿用原接口。V** 与 B_cost 的正式参照使用冻结工作进程。[公开参数空间](parameter-space.json) · [固定 U](U.json)

## 参数空间和基数

八个具名任务类别各有八个独立三档参数，另有五个全局三档参数，共 69 个。直积大小为 3^69，严格大于 10^12。即使固定全部全局参数和每类中的四个参数，另外 32 个坐标的直积仍有 3^32 = 1,853,020,188,851,841 个参数向量。表中参数用于选择是否核查、选择核查对象、处理截止时间、分配可竞争写入名额、评价公开旁路损失、预防性重分组，以及根据实际读数考虑写前复核。主轨道的 69 个参数都可被固定 U 调整。三档是离散参数向量计数，同轨向量和样本上等效会保留账目。该计数不要求任一给定面板上每个向量都产生不同轨迹。

热启动仅开放预防重分组的三项全局参数，以及各类别的写前佐证、直接处置所需支持度和公共剩余时限。27 个三档参数，3^27 = 7,625,597,484,987。触发阈值与候选排序使用已到的公共观测和冻结 V** 的公开预测。从原始选择出发，热启动可提高预防重分组优先级、在已有足够的本人读数证明正常时避免有维护风险的写入，或在预期必要操作的窗口将关闭时免去同对象核查的等待。每条候选仍需经过同一合法性和资源检查。

## 面板、付费反馈和锁定

由新增 32 字节开发种子派生 FIT 与 DEV 两个独立域。沿用 v3 生成器和原 v3 行动成本。FIT 为六族各 6 条、共 36 条。DEV 为六族各 8 条、共 48 条。每族各取两个十二档块中的前 3 或 4 个槽，按块内槽位置和族顺序排列。对每个槽以 SHA-256 的域隔离子流及预声明的递增重抽编号得到候选种子。条件候选的整包身份或实际输入身份与 T4b 已发布摘要及已经入选的本期条件重合时，按同一子流的下一编号尝试。槽位置和分母固定。筛选只使用身份匹配，独立于任何服务指标。训练前核对两类摘要。结束后从保存的条件重新计算两类摘要，复核与 T4b 的交集及 FIT/DEV 交集。全程只提供公开的 T4b 条件摘要作排除索引。

所有搜索查询在进入设施前记一笔付费。每条轨道起始向量与每个候选分别购买同一批 FIT 条件。除参数、已知 U 和历史候选状态外，提案只接收该轮已购的匿名配对单元、L、人员秒、工具秒、收费、调用支付与有效评分状态。实际处置证据与原生轨迹只留在评价端。机制诊断和各 DEV 评分均在两个最终向量锁定后读取。主轨道与热启动各自更新候选，记录每轮的父策略、提案、反馈及接受规则。正式方法不回传评价端诊断。U 的元参数全部位于 U.json，后续 T6 可在同一空间和评价协议上改 U。

两条轨道各预购初始父及最多四轮、每轮三个候选。每个方向按过去付费降低 L 的平均信用、探索系数和 PCG64 提案随机源排优先级。成熟候选择最小 L，最低接受降幅 0.01 秒/条，人员、工具、费用与候选哈希依序破平。在任一调参面板不全时，保留原查询状态与最近的有效父，停止该轨后续搜索。正式分母缺项时，区间基于有效对照配对作描述，达标判定为不可判定。完整搜索最多 468 次每轨、936 次合计。抽签、回退及早停由冻结的 U 实施。

DEV 并行对照为 P、B、B_cost、V**、V**−probe、主轨锁定策略、热启动锁定策略以及同一个热启动向量关闭初检的配对臂。48 条每条八臂，共 384 次。DEV 评价用于新情景开发自检。热启动失效按 T4b 复用的三条证据判别，报告 V** 参照与热启动各自的原生残余计数、可判定分母及变动。

## 统计和算力边界

冻结的开发达标规则要求，主轨在 48 个完整配对中相对 B_cost 的双侧 95% 区间上界严格小于 0，相对 V** 的区间上界不超过 30 秒/条。均差均为候选减参照的整窗服务缺额 L。另列已付的人力、工具及收费，以及每轮入选父的 FIT 相对 B_cost 服务差。学习曲线的横轴为本轨累计已付设施调用数，初始点包含父策略的全 FIT 测量。曲线和 DEV 对照分开。重抽为族内条件配对 PCG64 重抽 10000 次，配对双方共用索引，线性百分位 2.5% 和 97.5%。指标、所有域、限额及原子选择在首个设施位置之前固定。[确认协议 v2 的统计口径](../t4d-cost-baseline-v1/confirmation-protocol-v2.md)

试点购入每族一条 FIT 条件，在两条轨道的父与第一候选上各运行一次，共 24 次。试点计入训练预算。待试点全返回后，以最慢一批完整墙时 t 按 ceil((2*(1.20*t+8)+6)/60) 定出正式批的整分钟上限。每核最多串行两个位置，记录作业分配核数、申请时限和实际 TotalCPU。用剩余全部注册位置、计划统计和已发生失败重算，超过 90 作业或 75 预留 CPU 小时就保留当时状态并停。拟定开发总分母 1320 次。全批均保留输入、身份、调用、付费、失败和结果摘要。详细原件保存在私有集群。H2 的访问、派生或设施调用为零，最终确认留待 T6 后的单独阶段。
