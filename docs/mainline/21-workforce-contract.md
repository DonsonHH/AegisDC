# Timed heterogeneous crew execution

Ticket21 extends the existing private facility `Workforce` resources and access relations through an opt-in `work_program`. Legacy `work_requests` retain their original behavior. `simulate_scenario(..., work_program=program)` and `python -m aegis_dc simulate --work-program program.json` advance the same eight-domain plant while issued tasks move, wait and work. They remain private evaluator interfaces. Nothing in a work record repairs equipment or produces an inspection measurement.

`prepare_work(frame, profile, task)` is the public preparation seam. It receives one validated current ticket15 frame and separately declared static timing assumptions. A task identifies a target, work interface, unique crew roles, a designated qualified tool carrier, a deadline and a source note. Assistants meet their own declared qualification; the carrier also meets the interface qualification and tool capability. Task-specific specialist roles are synthetic declarations, not site certification requirements. Current declared restriction records can prevent planning. Actual state, current hidden tool occupation and hidden closures are unavailable to this function. Its `execution_permission` is always false.

The evaluator-owned `CrewWorkforce.submit(frame, task)` admits a current issued intention without restarting resources. The program wrapper is a deterministic sequence of these issue events; a planner receives only its current frame, not the future program. Each submission must retain the bound nominal registry. Duplicate task IDs are rejected; a second open task for the same interface and target is not executed. This version uses stable issue-order, work-conserving admission: a waiting task does not block unrelated free resources. This queue convention is declared engineering behavior, not an optimized dispatch policy.

The executor shares physical identities, capabilities, interfaces, access graph and timing values with the declared public profile. It reserves the crew and necessary tools when all are free, routes the carrier through tool pickup points, and routes assistants independently. Work starts only after the entire crew reaches the target. Worker shifts and task deadlines must permit the full declared route, positive access checks and work duration. A queued deadline expires even when a required worker remains occupied. No worker or physical tool is assigned to two active jobs.

Routes use the declared static access graph and route qualifications. They do not query actual closures before travel. Every attempted destination transition includes an explicit positive access check, performed at the safe approach before entry. A closed destination prevents entry at check completion; the last safe location and all incurred travel, waiting and reservation time remain recorded. Existing local physical protection can abort ongoing unsafe work. Public task-local feedback becomes available only after its observation instant plus the declared communication latency. Repeated submissions provide no instantaneous physical query. Private traces, rejection details, actual resource snapshots and work records are evaluator output and must not be supplied to a dispatcher.

Person-time categories travel, wait and work are disjoint. Wait is decomposed into access-check, crew-rendezvous and idle on-shift queue wait. These three are subsets that sum to total wait, not extra occupation to add again. An already busy worker waiting for another queued job is counted only in its current activity. Physical tool reservation spans pickup/travel/check/crew wait/work; tool-work time is a reported subset. Waiting before a worker's shift is not counted as personnel occupation. The gate convention charges even an already present worker a check, so the canonical two-person case starts at61s and ends91s:60 travel,62 wait and60 work person-seconds; the two check person-seconds are contained in62.

The frozen engineering protocol executes one original60s/30s V6 case at maximum step.01, preserves its complete private trace, and checks exact independent timing literals. Development tests use explicitly scaled legal timing assumptions for shorter public-interface counterexamples. Their red/green logs preserve development defects and fixture corrections, including a filter-location/horizon error and the initially inherited tool-snapshot assumption. Author full regression is deferred to Root's reviewed integration. Research comparisons, field calibration, inspection observations and physical intervention remain later gates.
