## 原失败及修复解释

C01 请求于 4.0 秒恢复网络，原生 applied_at_s 为 3.9999999999999947。原检查器对所记录的处理坐标使用逐字面相等，首次 C01-V 因此失败。协议基线已经声明二进制时钟的重合范围为 8×max(ulp(请求),ulp(处理))；此处相差 6×ulp(4)。补充检查器精确核对请求时刻、参数名、值和顺序，要求实际处理坐标确实在原生轨迹中，并按该原有规则核对两种坐标。[原生时钟定义](../../../src/aegis_dc/time_coordinates.py)

所有原请求、原始 applied_at_s、独立答案和真实轨迹均按原值保存。5 个 C01 臂以及 C04-P 的旧坐标字面诊断在补充报告内也有记录，按原比较式仍不等。C04 的两段服务下界另用跨界段的实际时长覆盖完整 [0,4) 和 [4,10)。公开派工时钟、有效期右端、费用、主评价方向继续执行各自原规则。首次 FAILED 和汇总器的附带异常保留原身份。

## 核验强度与未执行的边界

Z1 的正差、反差及相同率历程细分经服务评价器运行；数值未决的独立见证位于符号分类器边界（余额差 0、率差 2⁻⁵²、历程不同）。本包没有用两份天然产生该组合的原生轨迹再做一次端到端演示。已有整窗连续性代码会拒绝非 H10 完整轨迹；当前保存的缺失证据是 Z4 的未返回及真实初次作业的停后缀，并无一条非空、提前结束的原生服务余额专门触发 H10 拒绝。两项边界应保留在后续使用判断中。

K 的固定 LOW 续动作只查支持与完整链可行性。在 C11 的根和本人 LOW 前缀中，实际 return 均记录 risk=2、action_value=2、forecast_branch_count=4；这些继承字段反映按变体填入的逻辑槽数，不能当成 K 实际执行了四次前瞻或作为各方法计算成本比较。267 是由直接入口及真实设施决策时钟合成的顶层计数。对原目录清单逐条复核，red、首次、定向分别有 0、114、157 个内部归档文件，全部能绑定已声明输入、返回、独立断言、工作账或原生日志角色。原清单与哈希均保留。[归档分类及证据限制](evidence-scope.json)
