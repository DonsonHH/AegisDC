# 新面板确认：执行冻结

进入依据是阶段 0 原始回执的两道门槛。新面板上的主量为 S−W 全窗平均 L；严格按冻结的六族配对、双侧 95% 百分位区间判断，上界 < 0 才成立。另列 S 对 V**、M_hot、P、周期巡检、报警的相同口径差及区间；B_cost 一并列出。每个角色列出 L−L* 和逐族分解。历史按族参照的差异单列核算，不用它更改本包。

1. 原生试点的准备步骤先读取封存的 36 个旧格键，用阶段 A 的 fit 对全板训练 S 和 W，写出整张锁表。只有 GitHub 已发布的锁表与私服字节一致，才允许生成新条件。主随机源为 SHA-256(ASCII「AegisDC/T5-v3c/new-panel/v1|」+公开锁表提交的 40 位小写 Git ID)；不同于 H2。沿用 v3a 发生器，六族各一个十二槽区块，取 0…5；规范字节派生为 SHA-256(源32字节 + ASCII 竖线 + UTF-8「family|block0」)，冲突时改取「family|slotN|retryK」，最多 128 次。拒绝整包或实际输入与先前 144/84/36/36 条、或本面板已接受输入任一相等的槽；保留拒绝账。各槽按轮次、冻结族序排列。完整清单发布后才允许首次设施调用。
2. 每条件 9 个独立原生位置，顺序名册 S、W、V_COST、M_HOT、B_COST、P、PERIODIC、ALARM、ORACLE。前 3 条另各有一个独立的所选向量复现位置，共 327。实际 S 在共同公开帧上顺次询问原 58 个策略；判断“存在非空提案”可在找到首个非空时短路。若所有策略均等待则给设施返回等待；一旦成立，独立选择进程只收到公开目录、当前及历史公开视图、公共提案的非空标志，以及旧面板已冻结的选择表。在当帧实际发出所选向量的原响应；本人在这帧也可等待。所有可选工人在首次提案前均接收相同实际前缀。选择一经做出保持不变。复现核对同一新输入的 L 及**完整签发请求对象序列**，包括时间、对象、动作和绑定身份。未触发或复现失败单列，不能据此宣布确认通过。
3. 合法全知复用冻结的独立下界和真实写入/本人复核核验。有限备用结构恒等只在既有证书前提、P/全知均无动作且原生服务曲线相等时采用独立 P 的实际见证。检查每条合法成绩未低于所证界。同面板比较保留 36 的分母；有未决的主配对或未能复现即不作主门槛通过结论。缺少认证下界则相应剩余缺额留空。没有外部保管或现场总体推断。
4. 设施试点一项 Slurm 分配（3 CPU、14 分钟）。在同一分配中等待两次公开发布回执，仅用于前置身份核对，原始等待亦计入申领。第 1 条跑 9 个角色，第 2、3 条跑 S，第 4、5、6 条依次跑 W、ORACLE、V_COST，最后跑前三条 MIRROR：共 17 个位置覆盖六族和九角色。余下 310 个位置按原清单顺序轮流分入 26 个批次，每批 3 核；各位置独立。根据试点各角色实际 CPU 和墙时，将批内任务按预计墙时从大到小分到当前最空闲的核，预计墙时增加 15%，最终批留 24 秒读回，时限向上取整到分钟。每批预留不超过预测 CPU 的两倍，执行后核查实际比；累计包括阶段 0 两项作业，不得超 40 作业或 30 CPU 小时。最后一批在其他批次终态后运行，以便同一分配读回，避免只做瞬时对账另占一作业。超限先报告，零自动重试。失败、已调用、缺分和未执行均保留。私有轨迹不出集群。
