# T5 v3c：公开帧选择整套策略

阶段 A 在任何按格成绩、向量选择或新设施调用之前冻结。阶段 0 使用 v3a 原有的 36×58 份结果，检验在首次有策略提出请求时，能否从当时的公开信息选一套完整策略。缺额 L 与认证下界 L* 均以整窗服务缺额秒计。分析对象为同一批 36 条有限开发条件。v3b 的负结果限于其固定拼法；背景的 120.37 和 226.01 秒只供核对，不作为拟合目标。

## 决策帧与门槛 0

沿用 v3b 冻结的 58 个策略、原进程、公开 IPC、v3a 原始条件和每策略自己的合法历史。帧号从 0 开始，每 60 秒一帧，共 61 帧。在同一条件中，取任一策略首次发出**非空提案**的最小时钟 t*，包括最终被设施拒绝的提案。永久没有提案则 t* 不存在，核对至 3600 秒；不伪造决策帧或排除这个条件，门槛 1 未决。

先定位 v3b 的逐策略回放记录，再从原件经原回放接口复现全部 58 项的公开提案。每个策略自身的完整回放摘要用于认证来源。比较的是原生派发时的完整公共输入（包括原静态目录及逐帧 view 的规范化 SHA-256），不是工作进程按角色再过滤后的输入，也不要求各策略的输出相同。必须从首帧到 t* **含 t*** 的 58 份输入逐帧一致，且没有更早的非空提案。只将一份代表历史的静态白名单和不晚于 t* 的公开信号投影交给特征函数；评分、实际族别、作业键、文件位置、私有附件、完整频道和后续帧均不在接口中。原始历史的审计可读已封存的后缀，仅供验证旧回放承诺。

按 v3a 原条件序比较。遇到首个不同立即停止后续条件及分析，保留原条件键、0 基帧号、时钟、各个哈希与对应角色；原件或位置不全登记为未决，失败／未执行保留在 36×58 分母。全部条件通过后，才能将格键与得分连接。

## 三个冻结特征

| 特征 | 公开字段及编码 |
|---|---|
| 设施类型 | 从静态 subjects[].key 读行动目录：C/N 为 MAIN，LC/LB/LG 为 LONDON_STYLE，NR/NP/NC 为 NETHERLANDS_STYLE。混合或未知为 OTHER。不给函数传入评价端族标签。 |
| 首个风险信号的域 | 对原始且已到达的信号，用公开 subjects[].id → key 解析 records[].subject 或 fixed[].field；service 记 SERVICE，群组／无指向记 UNSCOPED。不会从名称前缀、来源、私有故障或第一个策略的动作倒推。 |
| 首个风险信号的类别 | 已生效的原始 alarm、prior（记录中原有的 record_type）、release、status，或公开异常测点 fixed[].ok=false。一般开工授权 order、正常测点及中继副本不作为风险信号。无信号时域和类别均为 NONE。 |

只在 sampled ≤ arrived ≤ 当前时钟 < until 的帧首次接收一个信号，最早一次记忆可跨其后过期。顺序先取最早到达，再依次按固定优先级 alarm、异常测点、prior、release、status，再按公开域／类别的字典序破平。相同根或重复投影不加权。未知 prior 不发明子类。允许先有提案、后有信号，条件仍使用当时的 NONE。设施类别会与部分族别相关；可得性来自合法静态目录。线上触发由 58 个公开策略在同一实际输入帧的提案决定，不向策略提供条件编号或事后算出的 t*。选中者在同一帧的响应（可为等待）即实际响应，此后保持该策略。

## 跨半拟合与门槛 1

两半分别训练：A 的 18 条选、B 的 18 条评，精确对调后合并。每格至少 2 个选择半条件时，按该格平均 L 选 58 个中最低的完整策略；0 或 1 条均取该方向**整块选择半**的赢家。报告训练和评价出现的格的并集、支持数、选中者、回退格和实际受影响行数。并列按 Q01…Q48、B_COST、V_COST、M、M_HOT、MAIN-U-1…3、MAIN-R-1…3，使用封存浮点的精确有理数和。整板比较 W 使用同一选择半、候选集和破平。另按选择半每个评价族选同一 58 项中的整向量，评价半查分；此项是拥有族标签的参考，不能部署，对有限样本也不是数学下界。

门槛量为 36 条等权的配对差：(L_S−L*)−(L_W−L*) = L_S−L_W。两方向各占一半；报告各方向／族的剩余缺额和原始逐条件配对。不把选择半的标签或成绩作为评价行的特征。以 6 个族为层，在每层原来的 6 对交叉评价结果中有放回抽 6 对（两方向已各自锁定，不在重抽中重选）。NumPy 2.2.6，PCG64，以 ASCII「AegisDC/T5-v3c/paired/stage0/v1」的 SHA-256 大端整数为种子，10,000 次，取线性 95% 分位作单侧上界。未舍入上界严格小于零才通过。它衡量固定两半拟合在这块开发板上的条件波动。缺分、未证下界、无决策帧或任何身份核验失败均不判通过。若核算出的按族参照与用户补算值有差别，并列报告，不调平局或成员。

## 计算及停止

冻结发布后才允许第一项 Slurm 试点。试点先做零设施人工例自检，再做 v3a 原序前 12 条（覆盖六族）的真实回放，计入本次分母。以 v3b 同一回放的历史步 CPU 作初始参考；首作业 2 核、2 分钟。若完整，按其实际含步骤 TotalCPU 和墙时，为剩余 24 条及一次读回共同确定一个作业的预留：推算同等单位数的用量，至少留 15% 墙时余量；时间向上取整到整分钟。预留不超过对应推算 CPU 实耗的 2 倍；核对实际账，异常不靠增加无用运算来稀释。全包累计不超过 40 作业、108,000 预留 CPU 秒。预算无解、超限或中断先交付，不削减角色、条件或重复失败位置。使用已验证的 renly/mu01，详细原件留私服。H2 的生成、读取和派生均为零。

只有门槛 0 和 1 均通过才进入阶段 1。先对全部旧 36 条按同一规则拟合 S、W，发布冻结，再生成新的六族各六条件和双身份审计。以独立种域「AegisDC/T5-v3c/paired/stage1/v1」做六族分层、10,000 次、双侧线性 2.5%／97.5% 区间，主比较为 S−W。原生 S、W、V**、M_hot、B_cost、P、周期巡检、报警、全知均有各自原生记录；前三个预先固定的条件（按新注册顺序）另跑所选策略，要求 L 及全部签发记录严格一致。需做新面板试点预算核对；不提前生成新输入、读种子或发布新的执行许可。
