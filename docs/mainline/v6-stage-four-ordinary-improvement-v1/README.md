## 1　预测时间的三个含义

| 量 | 冻结实现与本协议选择 |
|---|---|
| 排序用的积分域 | 历史 J 在绝对时间区间 `[8,12)` 积分公开世界下的预期缺额。新增的人工选择只允许将该积分域改为 `[0,12)`。每次重选沿用同一绝对原点和 H12，含共同的已过前缀。 |
| 公开热风险的发生 | 冻结的 `signals` 同时用 `forecast_window[0]` 确定预测的计算许可。声明的热风险时点 Θ 固定为 8 秒。Θ 前计算侧在本模型中许可，Θ 起正常冷却 C0 持续许可，滤阻异常的 F 依赖恢复条件，其他冷却原因 O 继续不许可。这个简化假设只用于公开预测。 |
| 处置、恢复和得知结果 | N 的预测配置从具名 N.A 的计划生效时刻起置 1，供电和存储仍可限制服务。F 的清滤在 C.A 生效时改变预测流量，热许可须到生效后 2 秒才恢复。两者都取右侧状态。O 不能靠清滤恢复。实际处置、本人回执到达和取得有效关闭各有独立时刻。 |

对世界 w、已付公共历史 h、合法计划 a，排序损失为该域内 `∫(1−ŷ_w(s|h,a)) ds`，再按支持世界的原质量取期望。积分断点包括域两端、域内 Θ、具名有效时刻和冷却恢复时刻。先核对原有许可与完整分支资源预留，再比较缺额、计划人员占用、工具占用、费和最后回执时刻，沿用旧的平局规则与分支合成。预测对在途处置采用原计划生效假设，证据支持仍枚举一套跨历史一致的未决结果。实际派工继续等本人合法到达的报告。同一公共前缀中，未来分支不能改写过去。同一时点分组后的前缀项按原世界质量合并，任何新编辑都不能重写取样时刻来提高分数。[承诺与预留](../../../src/aegis_dc/joint_resources.py) · [证据与关闭](../../../src/aegis_dc/joint_evidence.py)

## 3　付费反馈、U0 和对照

**每个查询**是预先购买一个“开发任务 × 完整描述符”的原生 H12 位置。启动前扣一个离线查询单位，失败、同轨和拒绝照记。另记实际作业内 CPU、公开决定、现场人员秒、工具秒、费用，以及未返回与未执行位置。一个科学条件中的现场预算与离线查询账分别核算。既往披露材料对所有组等价可见，各组新反馈只来自自己结清的查询。

冻结的开发回执投影只给出同一块内的不透明配对键、描述符、支付／返回状态、合规或数值资格类别、L/U 两套账、三项实耗、逐实例首次／曾达／5／7.5／12 秒的合法关闭类型，以及预先列定的已付双方之间的资格与差值。键仅用于配对和完整性，选择器对键名和行序置换不变。物理真值、具体任务号、评价诊断标签、私有轨迹、未来块或他组回执不送入提案。只有双方查询都已付，才可返回对应比较。另存的研究审计字段与给改进器的反馈投影逐字段核对。开发中产生的新反馈不会成为未来在线策略输入。

将“候选 a 通过参照 b”定义为在该块每一行都有合规、可判配对，两套账的服务无一变差，三项实耗逐项不增，b 的每个具名关闭要求均保有，且至少一行服务严格改善。相同服务、资源节省或新获另一类型关闭单列报告。只因某个关闭总数较多，不能抵消某一实例的关闭损失。排序先在通过 J 的候选中按各行规范化服务改善之和降序，先 L 后 U。逐行用独立分段率的“参照减候选”精确差，按原比较分类持平者贡献零。其后取改善行数较多者，再按 H、O、X 的固定顺序。仅开发块用于排序，额外研究权重为零。没有任何候选通过时保留 J。

## 4　冻结前的可辨识性判断

**公共决策根确有分歧。** 在已见 EXZERO、两单同于 0.5 秒开题、4 费、60 人／工具秒的合法空采购历史上，两世界各半。原 J 的尾窗令两项直办与先查后办的预测缺额均为 0，计划工时破平，实际先发 N.I。对同一历史手算全窗公开预测，C 先办时网络在 2 秒恢复，N 先办时在 1.75 秒恢复，先核查时网络分支在 3.5 秒恢复。另一滤阻世界的相应清滤及两秒恢复均赶在 Θ 前。故这三项计划的公开预期缺额分别是 1、7/8、7/4 秒。暂缓、只办 C 或只办 N 均留下更大的公开期望缺额。H 在这个根有不同的合法首选。该算术给新接口一个独立正例。它没有提供 H 的实际全板成绩。在 COZERO 的已付空前缀，B03/B04 已分别留下实际 C 先／N 先的见证。若已到阳性初检只允许一个合法续行，排序位没有选择；预算不足、强制本人复核、零支持也可能使多个规则全程同轨。后续须按实际公共根分开报告这三种情况。[B08 事前推导](../v6-stage-three-cold-v2/protocol.md) · [原料与合法前缀](../v6-stage-three-cold-study-v2/result.json)

**离线也须有选择。** 在读 D 前各组面对相同历史和四个可付费规则。给定完全相同的一份合格付费矩阵，若 H、O 各自不能通过而 X 单独通过，U0 的一位路径会留在 J，S 可直接提案 X。若 O 通过且 H 未通过，U0 可提案 O，M 仍提案 H。如果 V 将二者均退回 J，过程分歧可观察，后续在线效果仍为同一规则。若两个描述符在所有到达的公共根都等价，按实际选择／同轨列出等价代表，保留两个登记位置。在未取得新的付费回执前，以上为条件推导。[独立选择与回退见证](qualification.md)

## 5　实际评价、失败与待决定项

E 固定 7 个角色、12 个条件。主比较为 U0 锁定策略对 J。另报其对 B、H、O、M 锁定策略、S 锁定策略的五种对照。另存 H/J、O/J、S/J、M/J、J/B 五个参照，每类 12 对，共 132 个报告位置。同一角色在多个配对中复用同一次本行回执。若多个角色锁定同一描述符，仍按原位置独立构造运行，标明别名。没有第二份独立开发历史。各类分母、同轨、触发过的合法选择和未达阶段分别报告。

每对以“参照减候选”为差。沿用原生两套 L/U、原 1e−8 单臂对账界及同曲线优先判平。核对相同公共前缀直到首次实际不同发行，物理轨迹核到首次不同实际作用的真左侧与人工写前状态，同作用全程核到 H12。另报每个工单、每一类 NA／PV 曾达、首次时刻、在参照首次时刻候选是否仍有效，以及 5、7.5、12 秒的当前类型。费用、真实人员／工具占用、入场预留与等待分别列账。类型替换、过期、未关闭和不同行上的得失分别保留。[原评价与关闭方向](../../../scripts/cold3_evaluation.py)

主张按三个层次登记。服务支配要求全部 12 对可判、无一劣且至少一行严格优。实耗按三维逐行报告。**建议的严格晋级**另须所有行三项实耗不增且保有全部参照具名关闭。等服务省资源且保有关闭另列为次要结果。研究按优、平、劣、数值未决、非合规、缺对六类保留完整分母；不合格、未决或缺对不能通过整板主张。遇硬身份／封存／额度／运行异常先停相应有依赖的活动，保留已发调用、真实成本、未知项与完整后缀，重试为零。依法暂缓、拒绝、零支持或未获关闭按实际记录，正常完成的此类轨迹仍可评价。E 返回仅归档，不能更新 U0、选择第二个锁定或调整行、权重、窗口或关闭门。

**请审查的评价选择**是是否接受上述逐行严格门，以及在无严格晋级时是否同时发布只满足“服务支配”的描述性结果。本稿建议发布两种事实并分别命名。任何允许某一行增加人员、工具、费用或损失具名关闭的实用性晋级均须事前另定允许的分量、幅度、实例类型及时点，当前没有这类容差或折算价。没有总体抽样、现场效用门槛或独立确认，结论只抵达这份有限合成任务。协议审定、输入冻结、工程资格与正式研究分别需要其相应授权。
