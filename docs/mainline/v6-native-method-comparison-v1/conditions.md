# 十七个拟议比较条件的完整规范

[conditions.json](conditions.json) 是规范数据。它列出每行的源文件、基准单位、带原值的替换、证据属性、五个处理的完整调用文档 SHA-256，以及物理场景／外生事件的共同身份。材料全部公开，属于拟议的机制比较，不构成独立确认集。

## 如何得到唯一的五份输入

1. 使用 ef9ff7e6 中的 [19 行冻结输入](../v6-intake-engineering-v1/inputs.json) 和[原生绑定补正](../v6-intake-engineering-v1/input-binding-addendum.json)。取指定 source_unit；深拷贝 common（原规范若指向 legacy 则按其原件），依次应用该单位原 edits 和补正中的 edits，每步均校验源单位的完整身份。得到原生调用文档，包含完整 V6 scenario、外生事件、duration_s、step_s、dispatch_program、business_program。表中行均来自 common 类型的源单位。配置基底是该输入内的八域、四图 V6 实例，其各参数与缩放配方都按原件取值。
2. 所有比较条件使用相同的公开设计背景。保留 0.0 秒从外部把 network_service_capacity 置为 0.5 的事件，将原本 2.0 秒的恢复事件移到 4.0 秒，恢复值仍为 1.0。原配方直接清滤的名义完成点 3.25 和首检后清滤的 5 之间已有公共刻度 4，故选择它来比较“外部瓶颈与人工工作同时存在”的机制。此选择依据是时序覆盖。外生事件内容或下一事件时刻不得喂给在线策略。C04 在同一时刻先恢复网络，再施加声明的存储容量界。其余行保持原有事件次序。
3. 依 JSON 的 row_edits 顺序替换指定叶；replace 校验原值，append 只在明确位置追加完整对象。参数数组的索引及名称双重核对。给所有处理分别复制完整文档。V/H 保留实际 v3 的 intake_value；D/K 仅把嵌套 policy 改为所列精确新 token（待实现）；P 仅把嵌套 schema 改为已有 v2、policy 改为 no_human，并移除 v2 没有的 value_model。P 使用同一公开能力、可见帧与人员工具配置；共同模型可作为公开方案材料，P 从不查询它。标签、条件号、研究路径和对手信息只进外层执行清单。
4. 为每臂按原生规则同步三份公开声明：policy_program.inspection_declaration 取本臂 inspection_program.profile，policy_program.intervention_declaration 与 closure_program.intervention_declaration 均取本臂 intervention_program。更新私有 run_binding 的 scenario、完整 dispatch_program、boundary_events、空 action_commands 的摘要，duration_s 与 maximum_step_s 以浮点数 10.0、0.01 写入。diagnostic.reference 的六个字段分别绑定实际 scenario、boundary_events、nominal_knowledge、evidence_ledger、workforce_profile、inspection_program.profile。共同配方的诊断参考描述 3.75 秒可能收到的首检报告及 4 秒截止；这项声明既不保证收到确定读数，也不保证该报告能用于处置。C08 尤须区分这两件事。各自业务程序保留原生三组件及原声明的事件、实例与关闭条件。
5. 摘要使用 UTF-8、排序键、紧凑分隔符、ASCII 转义、拒绝非有限值；保留数组顺序及整数／浮点序列化差异，等同 Python 标准 JSON 的 `sort_keys=True, separators=(',',':'), ensure_ascii=True, allow_nan=False`。固定工作时钟为 [0,0.5,1,2,3.25,3.75,4,4.5,5,5.5,5.75,6,6.5,6.75,7,7.25,7.5,8,9,10]，物理最大积分步长 0.01 秒。固定测点模型 seed 27、各槽手持模型 seed 23，使用各自冻结的零偏差、零随机幅度与零固定测点丢失率。仍按实际采样、现场适用范围和到达律发布记录。每臂单独生成自己的测量、工作回执和执行／复核身份。本轮仅进行上述 JSON 身份核对，D/K 文档能获得哈希不代表现有入口已支持新 token。

## 覆盖义务决定数量

每行承担下表的一项对照职责。除共同的网络恢复时刻外，被动因素以同组单因素改变为主。共同根具有 F/O/N 三种公开解释；下表“物理”列指评价者预先指定的设施输入，不能由私有参数替策略确诊。表中的条件标签在数据清单层。

| 行 | 条件及选择依据 | 主要分层／最近已见材料 |
|---|---|---|
| C01 | 基底滤阻倍率 4，清滤目标 1；可缓解的物理取水限制 | 私有物理 F、默认公开律；measure-low |
| C02 | 唯一物理差异是滤阻已为 1；工单仍可错误指向异常 | 私有正常 N；measure-normal |
| C03 | 滤阻为 1、取水阀开度为 0，硬联锁使流量为零。低值无法区分滤阻与阀限制，清滤不改变阀 | 私有其他原因 O；measure-normal、原生阀联锁组件 |
| C04 | C01 上，网络于 4 秒恢复时存储容量同时降为 0.5，保持到 H；查明独立组件是否限制整窗服务 | 私有服务瓶颈交接；persistent-bottleneck 的另一种物理来源 |

**N=17** 来自 3 项原因及可处置性、2 项额外耦合、3 项证据／时效、3 项公开模型敏感性、3 项独立资源维度、2 项窗口／授权和 1 项同源与共享工具竞争。相同物理条件上的政策声明变化是设计中刻意保留的对照。17 个共同任务只对应 **5 种**“完整设施配置＋外生事件”身份；摘要按此再分组，不能称为 17 个独立物理世界。C17 允许两个同类实例，副本不增加分母。仅 0.5 秒决定有机会考虑第二张独立工单；在声明工况的人工臂，第一段工作持有人员和仪器，下一公共时刻为 1 秒，第二张工单已失效。若真实日志出现第二槽在人员移动后重新派首段，保留原轨迹并登记适用域偏离，提交 review；本版没有取得从新位置重新规划首段的资格。

**公开分层**按各臂决定时能取得的公开模型、权限、班次、期限、预算、观测误差／有效期配置分层。动中记录按各自到达时点可用，仅作机制描述。**评价分层**另列滤阻、阀位、整流容量、外部网络／存储状态、真实流量及采取的动作后果。共同种子、场景、私有事件表和未来测量实现都留在设施侧。选择器既不能读取行号或输入摘要，也不能通过静态备注推断未来真假。公平性核对比较可见的帧、人的真实权限和本组记录，不要求不同动作后的两臂仍具有相同公开历史。
