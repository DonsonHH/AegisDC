# 39c下一行为的设计约束

设计记录，未冻结新测试、阈值、输入、预算或执行版本。当前已验证的是稳定问题ID下的关闭时序及三个有限边界；下文不构成诊断功能或整票接受。

|对象|下一实现必须区分的语义|
|---|---|
|外部报障/工单|到时线索和未确认声称；打开疑点本身不是系统误报|
|现场/固定测量|有目标、单位、观察/到达时刻、误差和来源的读数；一条读数不自动证明故障根因|
|系统条件判定|公开、事前声明的状态判据，保留正常/异常/未知及支持记录；如只判断容量不足，不能命名为根因诊断|
|故障真值|私有评价器依据独立声明的工程状态判据及适用区间判定；未建模的原因仍未知，不由报障或系统判断生成真值|
|可取证机会|按方法无关的通道、覆盖、初始资源包络、访问、线索和返回窗口事前固定；实际没派出/被本方法占用不能据此删掉机会|
|报警可用时间|记录判断何时可供决策，并与所依据的观察时刻分别保留；迟到的历史异常不能冒充当前异常|

公开条件判定程序应与私有业务评价程序分开声明。公开程序只能接收到时合法证据及静态知识，不能接收真实状态、私有事件标签、机会清单或未来节点。业务程序仍在评价侧使用，不能经参数抽取把私有标签回流给派工。后续需要对同公开信息、不同隐藏状态的运行验证公开判断相同，而评价可以不同。

首个候选可从具备真实手持测量接口的网络容量状态入手：用明确的合成容量需求定义状态失败，判定只覆盖这一状态，不推断网络故障根因或现场概率。数值阈值、误差区间跨阈值、陈旧/副本/冲突和无测量时的未知必须先写入正式行为契约，再运行。基础风险目录中尚未量化的六类不能因新增状态判定而升级为概率已知。

完整事件清单是报告主表，重复记录/采样不能增加事件数，同源/同工况事件也不是自动独立研究单位。原180次的未测诊断指标保持；新实现与效果比较分开。

误报、漏报的分母及未知/暂缓处理需在新契约明确：已知正常事件中的错误确定判断；已知故障且具备预定取证机会事件中的按时确认与未确认，另分错误正常、主动暂缓、迟到、未取证。不可取证和未知真值仍列完整清单并报告数量，分母为零时报不适用及原因。不能根据方法实际收到多少“好读数”重新挑分母。

提前量分别参照故障节点、服务损失节点和处置截止，保留窗口未观察到节点时的删失。防止服务损失的因果收益还需匹配反事实或明确未识别；新的读数/判断端点不能替代它。

另一个必要行为是39b动态实例关闭适配：绑定具体事件、实际行动及后续复检的身份和来源，保留至少两组设备/服务样本及有效性规则；不能复用另一个实例的关闭状态。无人工、授权失败、接受风险、升级与证据失效各有独立端点。最后补实际人员/工具/移动/等待/费用及计算成本，区分现有数学预测与LLM调用、准入包络与实际支出。
