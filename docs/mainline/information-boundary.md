# 决策与执行反馈的信息边界

此页细化现有规格的真实状态隔离要求，供14—17与21—23实施和验收使用；不启动尚未满足依赖的任务。当前M1工程运行器的后台访问检查仍是私有执行逻辑。

调度者使用声明的静态知识和决策时已经到达的记录。该约束同时适用于证据列表、候选任务、可选动作掩码、可行性查询及执行反馈。不能在证据接口隐藏实际故障，却在另一接口直接按实际故障筛掉任务或返回故障原因。

后台执行器继续使用实际状态阻止不安全操作。调度侧何时、通过什么方式得知阻止结果，需要单独声明：覆盖哪些对象、观察与到达时刻、可能的偏差或缺测、来源以及相关的时间和资源成本。已有远程门禁或保护状态通道可以提供相应记录；不能默认每个后台拒绝都等于全场可用的远程测点。

缺少远程记录时，一种可核验的执行方式是先到安全访问点，再在到达或检查完成后获得有限观察，保留已经发生的移动、等待及工具占用。具体观察和动作规则在相应执行票据中定义。重复提交无耗时任务并查询私有拒绝原因，不能成为未声明的检查通道。

验收使用成对场景：静态知识和当前已到达记录相同，隐藏故障或实际通行状态不同。合法新信息到达前，调度视图、候选与动作掩码、可行性查询结果及选择应一致；之后的差异必须能追溯到真实发生且按时到达的观察或执行反馈。后台执行记录可不同，不能据此提前修改调度输入。

同一报警复制成工单时保留根来源；固定测点未覆盖、停用或尚未到达的读数不补成实际状态。主场景包含稀疏固定传感器，历史、人工和现场手持结果按各自来源与时标进入同一证据边界。
