# A单步：UPS检修结束后是否仍未恢复投入

2026-11-11。父问题为`backup-support`，本次唯一子问题为`backup-ups-return-to-service-v1`。状态：**问题与条件模型待审；数值输入未齐，尚不可作收益评价**。本步无代码实现、试验或网站部署；自动主线保持暂停。

## 只回答这个问题

**检修工单已结束，但UPS是否恢复投入仍无可信的当前证据；在随后声明的上游失电情景中，它是否会使原有受保护辅助负载失去备用支持，专业核查是否会改变合法处置？**

只研究`ups_in_service`的状态不确定性。电池老化／容量识别、柴油故障、备用塔失效不是本次新增问题。UPS储能、转换效率、切换机制和其他路径继续使用明确声明的既有模型，不把它们假设为已现场验证。

|边界|本步定义及现有依据|
|---|---|
|隐状态|`X=0`表示UPS未投入，`X=1`表示投入；属于设施私有状态。[既有状态机](../../src/aegis_dc/reserve.py)、[实际功率门](../../src/aegis_dc/power.py)|

|已知投入|若当前证据已足够，也应允许不检查；投入状态不等于电池足够、转换必成功或关键服务必恢复|

## 条件计算契约：填齐输入后才计算

1. 决策时只读已到时证据`E`。设`p=P(X=0|E,情景)`；观测`y`包含未解决／拒绝，声明`ℓ(y|X)`，`p`及似然均在[0,1]，每个状态下各结果概率合计为1。同一工单及其BMS转发共享来源，不能当独立证据相乘。
2. `P(y)=pℓ(y|0)+(1−p)ℓ(y|1)`。当`P(y)>0`时，`p_y=pℓ(y|0)/P(y)`；零概率结果不作归一。检查完成、报告到达与可用于决策的时刻分开。
3. 给每条合法、含失败／拒绝的动作分支求完整设施的服务损失`L`：外生需求大于0时积分`(需求−实际交付)/需求`，单位秒；零需求时该项为0。辅助负载缺电能量另记焦耳，不直接换算或重复相加。
4. 不检查基线是在**所有合法的不检查选项**中选最低期望缺额：`V0=min_a[pL(a,0)+(1−p)L(a,1)]`。至少保留暂缓／升级；已有当前授权和证据若允许直接恢复，也必须进入对照，不能为使检查获胜而删除。
5. 检查分支按`y`选后续动作，算`VI=Σ_y P(y)·min_a E[L^I(a,X,y)|y]`。`L^I`包含检查、等待、回传、处置与核验的实际延迟；选择只依赖到时信息，实际执行仍过独立安全／人员／资源门。
6. 服务改善为`V0−VI`；人员、工具、路程及资源成本分别报告、受各自预算约束，不与秒数拼任意加权分数。这个公式定义待算对象，**本步没有代入未获依据的p、似然、时长或恢复成功率**。

## 对时间与关闭的最低要求

- 决策点、上游失电、UPS请求／接通、后备实际可供、到场、测量、回传、许可、恢复、复检及关闭各有时钟。失电真时刻若未预告，不提前泄露给调度者。
- 默认配置的30秒柴油启动、2秒接入、0.2秒UPS切换均为合成声明；检测、供能和共享容量仍须过实际动态，不能把`30+2`称为现场资格。[V6参数](../../configs/full-facility-mainline-reserve-v6.json)
- 0.2秒转换间隙造成的缺电不能删去，也不自动称为现场可容忍；它在投入／退出两状态中按各自真实轨迹计账。窗口、提前准备时间及容忍要求待风险问题通过后取得依据；[39t](39t-time-foundation.md)目前只是时间基础描述，未通过新的时间资格。
- UPS不直接供IT，停电期间两状态的关键服务都可能为0；UPS差异可能只在辅助连续性和后备恢复后的热／控制状态体现，也可能没有服务增益。报告包括零差异和更差分支。
- “投入门恢复”是操作结果；“三个负载得到所需供能”是功能证据；“服务恢复、问题关闭”另有条件。本实例的许可、行动、复检和服务证据必须对齐，不能拿工单关闭、旧复检或旁路有市电代替。
