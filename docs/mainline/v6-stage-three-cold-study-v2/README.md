## 边界、未解决与合法关闭

- **资料支持范围。** C03 的已付结果在 2.25 s 到达，配置 .25 与有效容量 11/170 的组合使 J、B 的公开假设均失去支持。两臂只支付了一次初检，没有修复或本人复检，实际服务缺额相同。C04 的网络初检本地正常，存储限制共同服务；J 能在 7.5 s 取得 N 的“无需处置”，全窗缺额仍为 9，两臂 C 均未通过服务复核。零支持是依法暂停自选动作的轨迹状态，并未使已经完整核对的配对成为数值未决。
- **窗口。** C05 中最早直接网络修订完成时恰逢写许可失效，.5 s 的 B 记录了 WRITE_WINDOW。C06 的完成时刻仍有效，B 的直接 N 分支可受理，但 B 选择 C。两行 J 均在 .5 s 发 N.I，结果到达时 N 的写窗已过，未发起真实 N.A。两行 J、B 实际缺额均为 9，J 少用资源，双方都没有具名关闭。
- **预算。** C07 的 .5 s 决策点不能容纳 31 人秒的完整初检、纠偏与复检。两法实际选择暂缓，到 .75 s 发初检、3.75 s 完成 N 修订，入场包络各 30.75 s、L=U=45/16。C08 允许包络 31 人秒，两法均从 .5 s 开始，3.5 s 完成修订、L=U=21/8。两行皆实际发行 3 项，不能把首刻被预算挡住记作整窗未能处置。[具名边界处的已保存候选与费用](public-decision-excerpts.json.gz)

主比较两法各有 48 个工单实例。J 的 23 个实例曾取得合法关闭，其中处置后复核 20、证据支持无需处置 3；B 的 21 个实例均为处置后复核。5 s 时双方有效关闭均为 0；7.5 s 时均为 21 个，但 J 的其中 3 个属于“无需处置”，两者的实例／类型并不一致。H12 的当前有效关闭为 J 12 个、B 11 个。对 B 的具名类型与时点，J 在 A03、B07、B08 有损失。每个实例的首次时刻及过期状态都保留在逐臂账内。[66 臂具名关闭与完整实际链](per-arm.md)
