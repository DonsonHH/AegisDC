# T2　分钟级一小时设施、参数化情景与三种现状基线

## 结论

**48 个条件全部入层，144 个独立基线位置及 48 个全知合法见证全部完成。** 只保留自动保护的 P 在 36 行出现服务损失，其中 24 行存在合法可减少的部分。按题定 T4 口径，**6 行**在 P、周期巡检与报警响应下都有损失，而全知排程可把损失降至零。这 6 行里两种人工基线甚至均未比 P 减少损失。**6 行的合格前兆都来晚了**。对另 9 行存在早于截止的合格前兆，报警响应均已完全避损。本批没有同时满足“已登记前兆来得及、两个现状基线仍失败、全知全救”的条件。

| 所属集合 | 该批实际条件数 |
|---|---:|
| P 有正损失 | 36/48 |
| P 有正损失且全知有余量 | 24/48 |
| 有余量、可完全避免且首个合格前兆早于最晚启动 | 9/48 |
| 三种现状均有损失、全知完全救回 | 6/48 |
| 上述 6 行中，已登记前兆有足够提前量 | 0/6 |
| 有报警且 P 有损失，但任何合法排程均不能降低服务损失 | 12/48，每族 3 行 |

固定巡检在 48 行中有 18 行仍高于合法最小 L，报警响应有 15 行。主备冷却族的巡检在部分晚警行能先覆盖到现场，网络族的相同有效容量读数又可以来自不同私有原因。因而，单看全板平均数不能说明未来核查方法在何种公共信息下会有额外价值。153 个具名工单实例在三种基线下都没有取得过有效 NA／PV 证书；这限制了本批用于比较关闭能力的价值。

研究单位是一个固定种子生成的完整合成条件。每条件 P、固定周期巡检、报警响应各自独立运行一次，另有一份只供评价端使用的全知合法见证。报告 L（归一化服务缺额秒）及 U（未交付服务单位·秒）。同一条件内需求为 1 时，两者数值相同；需求为 0 的区间两者都不计损失。差距一律为本臂实际 L 减已达到的最小 L。物理余量、公共信息来得及、以及某项具体方法能取得收益，是三个分开的结论。[48 份完整输入](all-study-inputs.jsonl.gz) · [逐位置数据与原件身份](study-results.json.gz) · [作业账与简要回执](receipt.json)

## 执行与完整性

A 用 3 个作业，预留 2,880 CPU 秒（0.8 CPU 小时，限额 4 小时），实际分配占用 286 CPU 秒。研究用 18 个作业，预留 37,800 CPU 秒（10.5 CPU 小时，限额 16 小时），实际分配占用 20,685 CPU 秒（约 5.75 CPU 小时）。预留按申请 CPU 数乘时限，实际占用按分配 CPU 数乘作业实历秒。单核位置在作业内并行，未把并行墙时当作 CPU 小时。

四个具名试点先于后续 188 个位置。首试作业 134753 的三个基线通过。4-01 全知原生返回前后事件采用不同显示顺序，旧身份检查退出，未留下该次完整原生轨迹或评分。作业 134754 在同一冻结输入上恢复这一位置并达到解析界。同一份原生事件以稳定时间顺序核对，原始输入列表和同刻相对顺序均有记录。四个合格位置的完整耗时约 91.6–93.9 s，计入首试失败的最慢墙时为 94 s。依冻结公式上取整为其余每位置预留 3 分钟，含失败与恢复的首次重估为 36,420 CPU 秒（约 10.12 小时），在预算内才继续。

作业 134757 的两个周期位置实际发布了同一目标的第二次初检，形成三个有值任务，被评分器拒绝。作业 134758 只按真实观测权益检查首 52 个位置，发现另有五个位置虽然只有两个有值任务，两者却是同一目标、同一阶段的重复初检。共 7 个旧周期位置原样保留并排除。作业 134759 只按原键重做这七个位置。落实输入中已冻结的“一目标一次”权益后，第二张同靶工单仍可到站、计费并获得回执，不能再次取得定量读数。共同输入、种子、基线规则、场景及判据均未更改。7 个恢复加读回审计把实际研究预留提高到 37,800 CPU 秒。后续仅使用相同权益的生产入口。[事件返回修正](production/execution-amendment.json) · [观测权益修正](production/observation-amendment.json) · [实际运行入口](production/bounded_execution.py)
