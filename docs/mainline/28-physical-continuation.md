# 第28项：修正公共输入后的物理续跑协议

首轮一次正常案例尝试在公共目录校验时失败；其 7.25 秒计入尝试时长上限，无完整轨迹、无验证通过。保留原失败输入、时序账、两轴审查及确切启动记录。不要从 completed=0 推断设施内部从未走到初次调度。

公共声明预检与设施尝试分开。第一次预检在迟到目录名义身份处失败；第二次预检的四个场景、三个初始框架和五次风险评估已通过，19 个文件可查。预检没有调用设施、选择器或闭合评估。续跑工具从 Git 校验两个预检及第一次失败的原件，并核对通过预检的输入与新物理输入完全一致。

物理、时钟、阈值、调度规则、成本和四例验收字面预期保持不变。四个实际案例各至多一次，共 21.5 秒；与首轮合计最多五次、28.75 秒计费上限。只有执行器实际返回并通过独立预期校验的案例才能称为通过。正常不派工、误报检查不增加服务且需证据审查、自动保护保留、太晚中止不擦掉损失。三个静态准备意图不会产生三个任务；太晚案例只提交一次网络任务。

新源双轴独立审查必须通过后才允许启动。首轮记录、公共预检失败、以后发现的问题均单独保留；失败即停，不自动重跑。此阶段仅限同一合成设施的工程核验；注册效果试验、现场标定和 M4 根验收仍待完成。
