# 当前方向：验证事件确认机制能否稳定改善任务

已完成[事件响应起步试验](../evidence/risk-response/README.md)与[事件优先级对照](../evidence/event-priority/README.md)。真实后果反馈试验此前已收束，不追加调用。

## 本轮结论

在同一事件空间、120秒有效期及安全检查下，比较FIFO、风险优先、保护下一步可执行机会三条规则。42次环境评价，0模型调用、0训练；新种子94003/94012的6条件中，Tour确认4/15段，FIFO与选定的机会优先均确认11/15段，全部安全违规为0。

机会优先仅因开发平均等待约0.0043秒的差异被选中；新确认与FIFO完整派单相同，没有额外收益。新确认只有2次多个合法事件竞争，机会损失数均不能区分候选。因此保留简单FIFO作为事件机制研究基线，Tour仍为项目默认。

## 下一项安排

2026-11-02按用户的新审阅建议推进一个有终点的验证包，问题固定为：简单FIFO事件响应能否在预定适用域中以可接受成本增加有效确认，且收益是否依赖正确风险位置？

前置工作已完成：修复事件过期边界并补回归测试；校验并[公开两轮旧实验原件](https://github.com/DonsonHH/Zhinengti-RSI/releases/tag/event-studies-20261102-v1)、配置、选择封存记录与源文件身份；从原件提取[成功与退化时间线](../evidence/risk-response/paired-timeline.md)。保留旧结果与旧源码，修复后的实验另存。

协议冻结前补齐位置与过程种子的独立配置，记录实际位置、遥测可见性、相位、持续时间。主比较为Tour、FIFO、同专业目标置乱的风险信息消融；三者使用相同人员与安全检查，事件组使用相同预定补查预算，另报实际访问及成本差，不能声称严格等成本。

预算草案为12个新过程种子×3个预定条件×3种方法，共108次评价；这是待落地的上限方案，不是已冻结协议或统计功效保证。运行前必须写定具体条件、种子、补查预算、实际意义阈值和停止条件，并封存源码与配置。近期适用域聚焦有提前公开线索的热—冷耦合确认，不据此主张四专业泛化。

统计按过程/种子配对，报告新增与丢失确认、净收益及不确定性、正/负/零过程数，另列移动、服务、完成量、安全约束、正常闭合、过期和晚完成。健康与未形成评价异常的条件单独报告成本。

结束后一次决策：若有实际意义的收益及可接受成本，冻结研究底座；若只优于Tour而接近风险消融，将收益归于访问权限和时序；若收益不稳或机会不足，保留边界并结束此包，不自动追加条件。后果反馈需在该决策后另行冻结协议，学习目标优先为“现在插入还是暂缓”，并处理共同预算、argmin语义、有效反馈保留及独立提案链。

优先为事件机制本身做更宽的独立条件验证，提前确定不同故障位置、周期相位、持续时间与专业异常的覆盖；健康与误触发条件也要独立报告。记录每个条件可供选择的竞争机会，不能在缺少竞争时宣称新优先级有效或无效。

不要为了制造差异放宽安全约束或改变人员。现有新确认条件现在均为已见材料，不再用它们挑规则。先形成可保持、可解释的有效确认收益，再恢复后果反馈，并补齐共同输入预算、argmin语义及失败后保留有效反馈。
