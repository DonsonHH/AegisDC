## 1. 只回答一个问题

在相同工具、合法修改空间、候选预算和巡检资源下，向固定开源改进器提供真实运行后果，是否比不提供这些后果，更容易获得有用修改，并把效果保持到新条件？

继续使用专业任务、受保护Tour和最多三项义务的局部修改。这个实验检验局部流程改进，不宣称已经实现全局接管或跨专业自主协作。当前岭回归不作为默认工具，不要求先修好它才研究经验作用。

## 2. 保留的比较

| 组 | 做什么 | 用途 |
|---|---|---|
| Tour | 固定受保护巡回 | 强任务基线 |
| 既有人工规则 | 固定已声明的局部规则 | 区分人工接口与模型增量 |
| 简单搜索 | 在同一修改空间内使用相同候选预算 | 区分模型提案与普通搜索 |
| 无具体后果反馈的模型 | 固定模型、任务说明和工具契约，不接收候选执行的具体后果 | 反馈作用对照 |
| 有真实后果反馈的模型 | 相同模型和起点，读取先前候选的实际执行后果 | 检验经验是否有帮助 |

各组共用任务、观测权限、工具、安全核和评价。候选非法、重复或执行失败都计入预算。策略相同而标签不同的结果只算一次实际运行。

## 3. 执行前一次性写清

- 开发与新确认条件、底层种子、候选次数、模型调用与环境评价预算。
- 使用哪个估计工具及其版本；是否运行学习策略，以实际调用记录为准。
- 修改字段和取值范围；保持物理、专业权限、测量语义及安全核不变。
- 保留/回退规则，以及漏检、等待、移动和完成量之间允许的取舍。
- 模型可以看到哪些开发反馈；新确认结果不得用于继续挑候选。

已看过的四个动作价值种子继续属于开发材料，不重新包装为新确认。没有必要先让PPO或CVAE分别赢过全部基线；若本轮主张其独立贡献，应另设对应对照。

## 4. 怎样算完成

**工程验收：** 候选经同一解析器检查；父版本与原始回复可追溯；反馈来自前一候选的实际执行；在线决策不读隐藏标签；每次执行、失败及回退均计数；输出一份完整且可读的比较表。

**科研验收：** 冻结候选后，在新条件评价一次；同时报告漏检、等待、移动、服务、完成量和成本；报告动作是否改变，以及经验组相对无反馈组的差异。资格和重访违规单列，不能用其他收益抵消。

结果可以是支持收益、无收益或证据不足。负结果也能完成本研究；格式失败导致候选未执行时，应写“未测试到收益”。不通过追加候选、重看确认集或事后改权重追求正分数。

交付只有三项：冻结的问题与预算、完整结果表和原件索引、更新后的 [EVIDENCE.md](EVIDENCE.md)。完成后结束本协议，再依据结果选择下一问题。

不重训大型模型，不扩大完整数字孪生，不引入开放代码进化，不同时扩展全部专业和全局协作，不将回归器调参变成主线。
