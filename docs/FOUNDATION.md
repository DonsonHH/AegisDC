# 设施结构与风险方法原型 v0.1

这是新阶段的第一份可运行交付：**结构模型与可复算决策算例**。它没有标定真实故障率，没有完成复杂设施瞬态仿真，没有部署设备控制，也没有训练智能体。

## 1. 结构比“更多机柜”增加了什么

[结构配置](../configs/facility-structure-v0.1.json)包含14个功能区、29个资产/服务对象、36条候选服务依赖及9条假设通行边。这些数字是模型对象数，不是某座超算的实际设备数。

|功能层|示例对象|建模作用|
|---|---|---|
|供配电|电网接入、变压/开关、整流/HVDC、PDU|共享上游、供电路径及下游服务暴露|
|后备能源|UPS、电池、发电机|候选保障路径；电池/保护范围等站点事实仍待核实|
|设施冷却|冷却塔、冷机、取水/过滤、泵和板换|区分环境排热、设施回路和设备回路|
|设备与服务|CDU/浸没系统、机柜、网络、存储及服务对象|从设备影响追踪到服务，而不是只计机柜数|
|控制/环境|BMS、本地控制器、房间空调、排水与候选安全屏障|区分控制能力、可见证据、环境及访问影响|

每个资产标注主来源或`candidate_not_site_verified`。所有连接均为`model_proposal`；通行分钟数是`synthetic_assumption`。配置是综合参照示意，不是三座设施拼出来的“真实竣工图”。源证据支持模块存在，不自动证明每条边、房间位置或冗余逻辑。

服务依赖的可达性只用于筛查**可能受影响的服务**；同一服务多条路径到达时只列一次。它不计算失效概率，也不声称上游异常必使所有下游停机。AND/OR冗余、容量、切换及共因需要后续明确。

行走边只连接功能区；它不改变服务依赖或风险后果。默认示例假设UPS/CDU两处可有固定测点，这不是实际站点统计；列表可缺失或为空。无固定测点输入的变体另有测试，风险方法仍可使用离线资料工作。

## 2. 风险与检查价值的边界

[合成风险算例](../configs/risk-method-demo.json)使用统一24小时窗口、CNY损失单位和一个二元缺陷/损失路径。每项参数保存basis和来源；这些数字是演示假设，不是Frontier、El Capitan或郑州测量值。

候选风险量：`R = q × r × C`，其中q是当前缺陷概率，r是有缺陷时窗口内发生损失的概率，C是发生后的条件损失。示例中无缺陷时该损失路径设为0，不能将这一假设推广至全部设施风险。

无检查时，允许比较“不处置”和“直接预防处置”。有检查时，分别按阳性/阴性后的后验选择行动，再求期望总成本。净检查价值＝最佳无检查行动成本−检查及条件行动总成本。维修/服务/赔付损失的重复项不能相加，安全目标也不能仅靠CNY均值覆盖。

### 已复算的两个例子

|示例|缺陷先验|无处置风险|最佳无检查成本|检查后总期望成本|净检查价值|模型含义|
|---|---:|---:|---:|---:|---:|---|
|未查清的供电支路|0.10|2000元|2000元|805元|1195元|检查结果会改变后续行动，因此有正价值|
|较明确的高风险问题|0.80|16000元|3000元|3200元|−200元|模型已倾向直接处置，再查一次没有改变行动|

共同假设：r＝0.20，C＝100000元，处置成本3000元且可完全消除该路径风险，检查成本200元、Se＝0.90、Sp＝0.95，忽略检查/处置延迟。它们均待真实数据替换。第二行仍列入“直接行动候选”，不会把“不推荐检查”误作“不处理风险”。程序不执行任何设备动作。

若不允许有效处置，第一例检查后总成本为2200元、净价值−200元：观察可以提供信息，却没有凭空消除物理损失。所有例子只描述声明的有限模型，不是已证实的经济收益。

## 3. 输入与选单契约

- 使用历史/人工/固定测点/现场便携测量证据；固定测点不是必要字段或全覆盖数组。
- 只接收决策时已获得的证据；未来可用的结果不参与后验。来源、观察/可用时间、性能和参数依据明确。
- v0.1每个问题最多接收一条可量化观测。没有联合似然时拒绝叠乘多条可能相关的证据；历史知识可预先体现在有来源的先验中。
- 带观测时还必须声明`observation_model`：`defect_state`为`fixed_binary_from_prior_through_prospective_inspection`，`inspection_channel`为`conditionally_independent_given_defect`。这表示从先验/旧观测到拟检查期间缺陷状态固定，且给定缺陷状态后，既有观测与拟检查结果条件独立。输出标明这只是声明的假设，未得到经验验证；填写声明不等于真实数据满足假设。陈旧证据、状态演化或相关测量需要另建时变联合似然，v0.1拒绝其他模型。
- 未知概率、非有限数字和无来源参数不自动当0；仿真器隐藏状态不属于闭合字段契约。
- JSON入口拒绝重复字段，Python接口对列表与一次性迭代器保持同一结果，避免参数覆盖或证据丢失。
- 下一次检查按正净价值、时间可行性选择，不生成固定巡回。CLI默认使用合成的120分钟预算，输出随结果记录；Python接口可显式传入预算。该选择不是多任务最优排程，也尚未把行走耗时并入动态优化。
- 不在不同货币或不同预测窗之间直接比较分数。每个问题单列，不把相互重叠的全设施损失简单求和。

## 4. 怎样运行

从仓库根目录安装后：

```bash
python -m aegis_dc status
python -m aegis_dc foundation
python -m aegis_dc risk-demo --output runs/foundation-demo-new
```

输出目录必须新建，已存在时停止。`status`读取当前研究契约；`foundation`检查结构并列出待标定参数；`risk-demo`只做合成算例的有限期望计算，不调用科研模型或生成真实设施收益。

已执行的[2026-11-04合成算例快照](../evidence/foundation-v0.1-20261104/README.md)保存输出、源提交和SHA，并附本地142项测试及会前340份冻结原件核对的摘要。

## 5. 下一轮研究先补什么

1. 为三个工程案例分别整理真实边界与候选依赖，不把共同模板视作各站实际拓扑。
2. 逐层定义供电/储能、泵阀水力、换热/相变、控制、IT服务状态方程，校对单位、容量、冗余与共同根因；再加入校准参数。
3. 从有在役分母的历史数据估计危险源/缺陷过程，标定检查性能、时延和处置效果；先冻结时间窗与损失账目。
4. 比较风险排序、信息价值与透明启发式的独立效果；验证概率校准、漏检、服务影响、成本和未确认暴露时间。
5. 最后才把智能体或RSI作为单独改变因素。会前的CVAE/PPO结果不替代新场景的验证。
