# 39r A2 · Frontier 与 V6 的功热量级参照

这份对照并列两份既有证据：Frontier 的一个实测日和 V6 的一个标称合成运行。先划定口径，再读数；数值落在一起或分开均如实报告，不设置跨站合格线。

## 先划出不可比项

| 指标 | 为什么这两份数据不能直接比 |
|---|---|
| 功率密度（W/m²、W/机架） | 缺少双方同口径的实际受载面积或机架分母；V6 的合成设备边界也不是已核实的现场机房。 |
| PUE | 需同一计量范围和时间窗内的全设施能耗与全 IT 能耗。[美国能源部计量指南](https://www.energy.gov/sites/default/files/2024-07/best-practice-guide-data-center-design.pdf)给出两者边界。Frontier 发布了 PUE；V6 的合成电力分项没有核成与它同口径的设施能耗。 |
| 绝对功率、单支路绝对流量 | 两设施规模和支路聚合方式不同；数值可作规模背景，不能以相近判定模型合格。单位换算不消除这个差异。 |
| 秒级响应 | 发布时点名义相隔 600 秒；V6 数值积分步长与现场观测粒度是不同概念。 |
| 服务缺额 | Frontier 表没有同窗的服务需求与交付。 |
| 功率波动系数 | `std(P)/mean(P)` 无量纲，但这里是一个实测日与一个短标称运行，缺少匹配的负载模式、稳定窗和观测频率。 |

## 参照边界与算式

| | Frontier | V6 |
|---|---|---|
| 取样 | [Figshare v4](https://doi.org/10.6084/m9.figshare.24391240.v4) 的 [2023-01-08 投影](../20261111-frontier-field-pilot/frontier-jan08.csv)，全部 144 个完整时点。 | [第 29 项已归档 nominal 轨迹](../../../evidence/mainline/engineering/29-uncertainty-domain/capture-01/nominal/run.json)，标称需量 1、4 秒、无外生扰动或作业。全部存档状态属于同一次合成运行。 |
| 水路 | [原论文](https://doi.org/10.1038/s41597-024-03913-w)二次环路的 1–3 号运行支路，50/50 水与乙二醇、1,060 kg/m³、3.50 kJ/(kg·K)。 | 内部水环路在板换的热侧；取内部泵实供流量、板换入口热池温度和出口温度。V6 用合成水近似 998 kg/m³、4.18 kJ/(kg·K)；取水侧和两相冷媒侧不混入。 |
| 功率 | 发布表 `compute_power_MW`；细分设备覆盖与计量点未配对。 | `actual_powers_W.compute` 为整流后实际计算负载；网络、存储和整流损耗在其它项。 |

三个 Frontier 支路先在**每个同一时点**求和：`ṁ = Σ(qᵢ × 0.003785411784 / 60 × ρ)`，其中 `qᵢ` 为美制 gal/min。再除以同一时点的计算功率（MW）。V6 用存档的内部水质量流量除以实供计算 MW。该比值的单位是 **kg/(s·MW)**；只有流量和功率按同一倍数变化时，比值才不变。各支路的 `ΔTᵢ = T回 − T供` 以 K 表示，数值等于摄氏温差；三路合计时用 `Σ(ṁᵢΔTᵢ)/Σṁᵢ`。温差仍随工况和换热策略变化。

排热比只作边界诊断：Frontier 用工作簿公布的三路计算余热，V6 用内部水经板换的热流，各除以本方计算功率。排热比是无量纲量，但等于 1 要求匹配能量边界并处理蓄热、其他热源与散热途径，不能从守恒直接得到。工作簿余热是同一组流量和温度派生的量，单独核对计算公式。

## 对照结果

Frontier 的区间为 2023-01-08 当天 144 条记录的最小–最大值。`OBSERVED` 说明所需字段和时标齐全，不能说明当天工况正常或具有年度代表性。V6 的 403 个存档状态在下列量上各为一个固定值，属于一次标称工况。

| 量 | Frontier 单日实测或派生 | V6 标称合成运行 | 比较口径 |
|---|---:|---:|---|
| 计算功率，MW | 9.639–23.599（中位 15.9285） | 2.000 | 规模背景；电表覆盖未配对。 |
| 单支路体积流量，m³/s | 1 号 0.03177–0.06057；2 号 0.03356–0.06450；3 号 0.06155–0.11977 | 无对应单支路 | V6 报的是一条聚合内部水路。 |
| 合计体积流量，m³/s | 0.12688–0.24484 | 0.12000 | 并列规模；左侧按同一时点求和。 |
| 单位计算功率的质量流量，kg/(s·MW) | **8.14–22.66**（中位 **12.50**） | **59.88** | 功能相近水路的量级参照；V6 是当天上限的 **2.64 倍**、中位数的 **4.79 倍**。 |
| 支路供回液温差，K | 1 号 1.33–28.00；2 号 1.72–28.11；3 号 16.61–30.94 | 板换热侧温差 **4.23** | 数值落入 1、2 号单路范围，低于 3 号范围；测点和控制工况未配对。 |
| 三路质量流量加权温差，K | **8.84–28.96**（中位 **17.84**） | 同一板换热侧温差 **4.23** | 与汇总水路的量级对照；V6 低于该日加权范围。 |
| 排热／计算功率 | 0.3960–1.0167（中位 0.8312） | 1.0596 | 各自能量边界诊断。两个分子的测点与其他热量来源不同。 |

**流量和温差描述的是同一个换热工作点。** 同一时点、同一流体边界的显热关系是 `Q̇/P = (ṁ/P)·cₚ·ΔT`；给定排热比与比热，流量和温差的变化方向相反。若用表中的 kg/(s·MW)、kJ/(kg·K) 和 K 计算，乘积单位为 kW/MW，数值除以 1,000 才得到无量纲比值。高流量、小温差不能当成两项独立偏差；也不能拿流量比和温差各自的中位数相乘当作逐时点排热比的中位数。Frontier 工作簿余热还有取整换算与负温差截断，表中 0.8312 直接来自逐时点的公布余热比。

**为什么 V6 的排热比超过 1。** 在[归档标称状态](../../../evidence/mainline/engineering/29-uncertainty-domain/capture-01/nominal/private-state.jsonl)下，内部水路的板换热流约为 2.1192 MW：两相冷凝向水路传热 2.0000 MW、存储散热 0.1000 MW、内泵向水路输入 0.0192 MW。此[归档配置](../../../evidence/mainline/engineering/29-uncertainty-domain/capture-01/nominal/scenario.json)把内泵的流体入热比例设为 1，而分母只取 2.0000 MW 的计算用电。这与[模型热账](../../mainline/healthy-run-model.md#hydraulic-and-thermal-closure)一致。Frontier 的二次环路测点、用电口径和暂态蓄热不同；两边的比值并列只作诊断，无法以谁更接近 1 判定正确性。

Frontier 的 432 个支路余热值按工作簿的换算与截断规则复算，最大绝对残差为 `3.55×10⁻¹⁵ MW`；这是派生列的算术核对。V6 的内部水质量流量与 `ρq` 一致，板换热侧的 `ṁcₚΔT` 与存档热流最大差约 `1.26×10⁻⁸ W`；全设施的归档能量余额残差为 `2.42×10⁻⁸ J`。它们分别核对计算关系和合成运行内的能量账，不是独立现场热量测量。

**这次对照支持的结论：**指定的 V6 标称工作点在这组参照中呈现较高的单位功率流量与较低的汇总温差。这是同一换热工作点的两个坐标；前两条支路的温差重叠只是局部数值交集。数据没有给出足以判断差异成因的匹配边界、负载或控制条件，不能据此作整体量级合格判断。比较未涉及现场动力学、参数标定、服务缺额或检查收益；600 秒发布间隔也不给出物理响应时长的上限。

## 全年分布背景

从云端留存的同一工作簿追加[全年描述统计](annual/result.json)。沿用[已审核的时间匹配](../20261111-frontier-field-pilot/README.md)：52,560 个名义格点中，49,869 个在一秒邻近范围内有唯一记录，2,691 个无邻近记录。对匹配记录另查所需字段、正计算功率、非负支路流量及正总流量；有 122 条总流量非正，无法定义加权温差，三个统计量统一使用其余 **49,747 条**。不插补，也不把这些排除项当成已识别的停机。保留带符号温差和工作簿公布的余热值；分位数用排序位置线性插值。

| 量 | 全年 p10／p50／p90 | 1 月 8 日中位数 | 当日中位数在全年中的百分位 |
|---|---:|---:|---:|
| 单位计算功率质量流量，kg/(s·MW) | 12.67／22.16／37.35 | 12.50 | 9.19% |
| 质量流量加权温差，K | 5.52／10.20／18.26 | 17.84 | 88.77% |
| 排热／计算功率 | 0.582／0.808／0.936 | 0.831 | 58.04% |

百分位按全年纳入记录中小于等于当日中位数的比例计，所选日也在全年样本内。当天的单位功率流量偏低、加权温差偏高，不能用完整性推断年度代表性。年度数据只提供观察分布背景，未对齐 V6 的工况。三个当日中位数均从工作簿复现了原 A2；原单日结果、协议及脚本保持原字节。

改用全年分位数作参照，V6 的单位功率质量流量 **59.88 kg/(s·MW)** 仍高于 p90 的 **37.35**（约 **1.60 倍**），板换热侧温差 **4.23 K** 仍低于三路加权温差 p10 的 **5.52 K**。高流量、小温差的方向在单日范围与全年分位参照中一致，无需把 1 月 8 日当成典型日。这里比较的是全年分位数，不能据此判断 V6 是否超出全部年度观测，水路与负载边界也仍未配对。

## 如何复核

[协议](protocol.json)固定两份数据的选择、输入 Git 提交与原文件 SHA-256；[完整结果](result.json)保留逐项区间和判定。[独立复核](verification.json)用十进制计算和按流量加权的回液温度重算 144 条记录，并从 V6 的初始原始状态独立复核归档范围的固定值。

从协议固定的输入提交 `d9a7d84f` 用 `git archive` 将所列文件按原始路径导出到 `input-root`，保持文件字节不变。在本目录执行以下命令（交付在云端 Python 3.12.7 完成，只用标准库）：

```sh
python -B analyze.py input-root fresh-result.json
python -B verify.py input-root fresh-result.json fresh-verification.json
```

年度部分另有[协议](annual/protocol.json)和[只读提取脚本](annual/analyze.py)。在 `annual` 目录用该协议记录的读表环境执行 `python -B analyze.py input-root frontier-v4.xlsx fresh-annual.json`，其中 `input-root` 为按年度协议导出的输入路径。
