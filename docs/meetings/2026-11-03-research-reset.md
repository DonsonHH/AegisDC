# 会后研究决策：从机柜巡回转向设施风险与按需巡检

整理/确认日期：2026-11-03。依据为用户本次口述、随后关于固定传感器的补充，以及用户提供的AI会议笔记。**研究要求以用户确认表述为准**；原始笔记含自动解释与时间顺序矛盾，不能当作逐字发言记录。原文保留在本地，仓库只记录去身份化的技术结论。

## 1. 本次确认的主线

1. **按问题触发检查。** 新策略不以固定路线、全场轮巡或统一300/600秒重访为默认任务结构。先判断哪里存在值得核查的风险问题，再选检查动作与动态任务序列；到目标的行走路径仍需满足实际可达性。
2. **稀疏观测，而非取消传感器。** 允许资产/历史巡检资料、人工报障和工单、已有固定测点及现场手持仪器结果。固定传感器现实存在，但成本限制覆盖；算法不能把全覆盖、连续实时遥测当作必要条件。可用测点是补充，盲区和缺测需要显式处理。
3. **扩大设施对象。** 从计算机柜扩到变配电室、开关/变压与整流、高压直流区、UPS/电池、备用电源、冷冻/冷却与泵/阀/换热、CDU/浸没或冷板回路、控制、网络/存储、房间与服务保障。模块有无、拓扑和参数必须与具体工程来源对应。
4. **先工程模型，再风险量化。** 先明确资产、空间、服务依赖、工况、失效路径及可观察证据；再借鉴FEMA风险评估过程，定义情景、概率对象、后果、检查价值和评价方法。
5. **智能体和RSI后置。** 模型和风险基线形成后，再研究语言理解、选单、人机反馈及版本改进的独立增量；不把复杂化本身当作改进证据。
6. **业务价值可检验。** 同时关注安全/可靠性、提前发现与确认、服务影响、检查和处置成本、时间与人员负担。温度误差、报警命中率或少走路不能单独代表全部收益。
7. **方法论可追溯。** 每项参数、分数及修订都有定义、时间窗、单位、来源和不确定性；检查阴性可以提供信息，是否减少损失还取决于后续可执行处置。

## 5. 接下来的交付顺序

**设施资产/服务依赖与证据台账 → 情景/时间窗/后果定义 → 风险与检查价值基线 → 按需检查及处置闭环 → 独立评价 → 智能体与RSI消融。**

第一批工作是建立可审查的设施结构、已知/未知参数表，以及可复算的风险—检查价值原型。原型中的假设数字明确标为合成演示，真实故障概率、检查性能、处置效果和经济收益另行标定与验证。
