# Domain documentation

This is one research context: `GLOSSARY.md` and `docs/adr/` at repository root.

Read the glossary before implementing a domain feature. Keep it to short domain definitions. Store accepted scope/architecture tradeoffs in an ADR; put executable requirements in the spec and experimental choices in the protocol.

Use `docs/MAINLINE.md` for the current proposed/approved objective and user-review gates. Old acceptance is historical evidence, not automatic acceptance for the reset mainline. Engineering and incident facts must retain their source/version; they are not silently promoted into calibrated simulation parameters or decision-time knowledge.
