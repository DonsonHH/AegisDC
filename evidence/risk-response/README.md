## 能讲清楚的成功与失败

- confirmation-2，机柜87：815秒公开风险转正，860秒实际测温确认，公开信号到有效测量45秒；固定路线漏掉了这段异常。
- 同一条件，机柜86：805秒公开风险转正，但事件响应直到955秒才例行检查，已错过800—895秒异常段；Tour原本在895秒确认。这是必须保留的退化案例。
- confirmation-5，机柜26：285秒风险转正，305秒有效测温确认；Tour漏检。该次完成的是例行头任务，说明前面的响应改变了巡回相位，不能把所有改善都解释为对这个对象额外补查。

区间起止来自事后评价，不提供给在线规则。公开优先分不是故障概率。等待指标对漏检截尾；健康条件无异常时不填0。

## 机制与保证范围

例行巡回游标和风险事件分别记账。非例行头的事件访问不推进游标；测量完成后再规划，途中与服务不可中断。风险持续为正不会无止境重开，未决期间的新升高合并；事件测量正常也闭合，但不算异常确认。由同刻专业测量揭示的事件立即闭合，不能计为额外响应成功。

新ResponseChecker检查所属、资格、预约、回合剩余时间，再从实际位置/时刻/最近测量逐项证明返回巡回和周期可行性；不是复用旧三项排列证书。实际执行后再检查首段、中间和回合尾的全部重访间隔。保证依赖固定通道、确定速度与服务时间，不含维修、随机服务或碰撞模型。
