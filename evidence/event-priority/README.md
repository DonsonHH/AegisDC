# 事件优先级对照：没有观察到新增排序收益

本轮方向：同一事件候选空间中，检验“先避免其他任务失去下一步检查机会”是否比先到先服务更有效。方案与规则见[冻结配置](../../configs/event-priority.json)。不增加人员、资格、候选权限或事件有效期，不打断在途任务；新排序只用当前公开信息和确定的移动/服务时间。

## 先解释旧问题

上一轮3段残余漏检的原件诊断见[prior-diagnosis.json](prior-diagnosis.json)。机柜86有2次能及时完成的合法机会，但未被选；随后3次被返回期限约束拒绝。机柜27、29在异常区间内记录到的合法候选已经来不及完成。这是沿旧策略实际轨迹的诊断，不是全局不可达性证明。

## 实际完成

开发6条件比较Tour、先到先服务FIFO、风险优先RISK、机会优先OPPORTUNITY。选择依据预先固定：先漏检，再异常条件的加权确认等待，最后移动距离。随后封存，使用两个新种子94003/94012的6条件确认。42次实际环境评价，0模型调用、0训练。

开发漏检三规则均为4段。机会优先平均等待56.41176秒，FIFO为56.41601秒，仅差约0.0043秒，按登记规则被选中；这不是有实际意义的强收益。

## 为什么新排序没有体现额外作用？

|范围|有事件可选的决策|多个合法事件|机会损失数能区分候选|相同状态下与FIFO选不同任务|
|---|---:|---:|---:|---:|
|开发|25|3|1|1|
|新确认|16|2|0|0|

新确认只有2次多个合法事件同时竞争，机会损失数都未区分候选，因此新规则没有改变动作。本轮无法据此否定机会优先在其他状态的作用，但没有增加其复杂度的收益依据。逐点比较不是另外运行一组策略消融。

## 后续取舍

保持简单FIFO作为事件机制研究基线，Tour继续作为项目默认。下一步优先检验事件机制在更多独立位置、相位和专业故障下是否保持收益，提前登记覆盖范围和预算；记录候选竞争机会，避免在没有竞争的状态中检验复杂优先级。不继续围绕已见确认条件调权重，不立即恢复LLM/RSI。
