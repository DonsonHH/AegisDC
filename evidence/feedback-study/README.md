# 真实后果反馈与巡检流程改进

状态：方案已写定，正式研究尚未运行。执行完成后在此页填写完整结果；不另建平行进度报告。

## 问什么

同样的固定开源模型、工具和两次修改机会，给它看真实开发后果，是否比不给后果更容易改好巡检排序？先在开发条件选版本，再封存到新条件确认一次。

固定路线T、人工公开风险评分R、简单搜索S、无后果反馈模型N、有后果反馈模型F共五组。各组人员、任务、观测、资格和重访约束相同；只允许改当前最多三项义务的纯数值排序评分。

冻结方案见 [feedback-study.json](../../configs/feedback-study.json)。开发6条件；独立确认6条件、2个新种子。S/N/F各2次候选机会，Qwen共4次调用。主比较最多78次环境运行；前置工程8次与正式研究合计最多90次。重复、非法和失败都占用候选机会，重复策略引用同一环境记录。

## 开始前核对了什么

- 公开流量确实进入名义温度估计，专业风险再由估计温度等公开量形成；不是完全断开的信号链。
- 已解释案例的风险等待项约为0.0005—0.0011，重访项约为0.125。虽然均无量纲，候选间差值与尺度仍可能使风险项不改变排序；当前窗口确实存在6个合法排列。保持执行核和特征不动，让同一评分语言中的修改来检验，而不事后扩大窗口。
- “遥测提示”与“专业人员现场确认”分别解释；环境不模拟维修，不声称诊断已覆盖辅助馈线故障根因。
- 一个入口保护的失败测试提前执行过62011/62017的6个条件。已在方案的`pre_freeze_audit`中披露，排除这些种子，正式确认改为预先登记的80521/80539。后续测试只用0/1占位种子。正式研究尚未读取新确认结果。

## 与导师指定论文的关系

原论文核对来源：[大学机构库PDF](https://idus.us.es/server/api/core/bitstreams/79e88506-ca7f-48f1-86b8-5504d9cb3e39/content)，DOI：[10.1016/j.eswa.2025.126483](https://doi.org/10.1016/j.eswa.2025.126483)。已阅读方法与实验相关页。

| 核对项 | 原论文 | 本轮 |
|---|---|---|
| 观测与估计 | 部分采样重建重要度场；VAE-UNet（§4.3） | 公开遥测与专业测量；固定名义估计，不运行VAE |
| 动作与协作 | 栅格移动、采样；Double DQN与安全共识（§4.1–4.2） | 固定所属任务的合法局部排列，不复现原协作算法 |
| 估计评价 | RMSE、加权RMSE、耗时（§5.1，表4–7） | 不主张估计模型增益 |
| 巡检评价 | 重要度加权未访问时间、R²及消融（§5.2–5.3，表8–9） | 漏检、现场确认等待、移动、服务、完成量和约束 |
| 本轮新增问题 | 无本轮的有/无后果反馈比较 | 固定开源模型改评分；不等同于递归能力已经提高 |

Qwen固定为[官方Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B)的登记修订，关闭thinking，FP16推理；所有权重在GPU作业里逐文件核对SHA。仿真端NumPy2.3.5与独立模型环境分别记录；无网络模型下载，无神经训练。

## 怎样复现

1. 从本仓库安装最小仿真依赖。按方案准备固定模型与独立推理环境。
2. 在Slurm GPU分配内运行：

```bash
python src/patrol_rsi/model_proposals.py --model /absolute/model/path --mailbox /absolute/shared/mailbox --protocol configs/feedback-study.json
```

3. 本机使用已验证主机密钥和已解锁SSH认证，显式启动：

```bash
python -m patrol_rsi study --protocol configs/feedback-study.json --output runs/feedback-study --ssh-host USER@HOST --mailbox /absolute/shared/mailbox
```

同一个输出目录用于恢复已完成步骤；已有候选与完成评价不重做。未完成调用应先检查原Slurm作业与响应，不得盲目重提。封存后禁止新提案，确认只读取选定版本。
