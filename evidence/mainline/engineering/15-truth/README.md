# Ticket15: evidence-only current decision inputs

This package concerns information flow in the same complete, Zhengzhou-inspired
synthetic V6 facility. Its 45 canonical identities, eight operational domains and
four relation graphs remain intact. Source facts and synthetic assumptions keep
their existing classifications. It is an engineering fixture, with zero
registered research trials, model calls and training calls.

The independent public nominal, three hand-authored evidence streams and fixed
public schedule are in `configs/full-facility-decision-v1`. Their authoring tool
reads the canonical public V6 profile; it never receives a private scenario or
run. These streams are engineering input records, not observations generated by
ticket16/17, the paired runs, or the private engineering work requests.

`docs/mainline/15-decision-contract.md` and
`docs/mainline/information-boundary.md` define the consumer boundary. The
evaluator alone owns `DecisionGateway`; the consumer sees only the current
detached plain-JSON frame. Pure feasibility, masks and demo choice use nominal
capabilities and arrived declared reports. Their result is planning eligibility;
dynamic safety stays unverified and `execution_permission` is always false.
Unknown dynamics leave planning intentions available while execution still
requires the private safety checks and a declared feedback channel. The demo
selects the first eligible public intention and does not execute it.

The frozen `docs/mainline/15-truth-runbook.json` specifies two actual 7-second
V6 plant runs at maximum step 0.01 s. The normal world should deliver 7 service
unit seconds. The second world has no grid capacity, 20 kg initial floor water,
a 50 K local-temperature bias and private filter events at 1.375/1.875 s. It
should deliver zero service, refuse the private IT work for unreachable access,
and disable compute locally. These private events must create no dispatch tick.
The private job is predeclared evaluator work, independent of the planning demo;
it produces no dispatch observation.

Each actual world is crossed with all three public streams. The same public
stream must yield identical full frames, public feasibility, masks and choices
across worlds. Open and closed report streams remain equal for four ticks before
the report arrives at 6 s; two later ticks can differ only through that record.
The one-ULP predecessor of 6 s remains a distinct public tick.

`development/` preserves every original red/green behavior log. They predate the
final frozen execution and are development evidence only. Formal capture uses a
new directory after committing source, tools, runbook and inputs. The durable
leaf list is declared before output hashing; Python runtime caches are excluded
by type. A terminal receipt keeps its original pending-delivery state. A later
fresh-checkout proof compares original SHA-256 identities, committed delivery
blobs, execution-source blobs, actual plant source identities and saved-data
checks, without another physics or full regression run.

Reproduction commands use the pinned interpreter and `PYTHONPATH=src`:

```powershell
python -B -X utf8 scripts/capture_decision_engineering.py --output evidence/mainline/engineering/15-truth/capture-01
python -B -X utf8 scripts/verify_decision_delivery.py --root FRESH_CHECKOUT --directory FRESH_CHECKOUT/evidence/mainline/engineering/15-truth/capture-01 --delivery-commit DELIVERY --output OUTSIDE_FRESH_CHECKOUT
```

Capture performs one full author regression. The two optional Torch checks may
be reported separately when the isolated author interpreter lacks Torch; root
integration owns the all-executed regression and independent review. Generated
SVGs read the saved actual audit plus the public input copies; visual rendering
is a separate root check. Ticket15 can be implemented pending acceptance while
M3, observation/execution mechanisms and the complete research objective remain
active. No scientific or AI/RSI gain is established here.
